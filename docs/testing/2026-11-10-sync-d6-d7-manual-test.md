## D6：清理旧的本机副本

准备：先备份待测试数据，退出旧版实例，使用本次新构建完整重启（热重载不会替换 Rust 库）。需要至少一个已经完成加入、当前不使用、下次启动也未选中的旧副本。加入暂存项仍用原来的“放弃加入”入口。

1. 设置 → 同步 → 管理，找到“清理旧数据集副本”，点刷新。当前使用的副本、下次启动已选中的副本、默认库和 staging 不应出现在可清理列表。
2. 对旧副本点“查看并清理”。核对副本名称、目录条目 ID、文件字节数，以及永久删除、仅作用于本机、其他设备与远端不受影响的说明。点取消，副本及密钥必须保留，重进列表仍可见。
3. 先锁定本机同步密钥；若还有进行中的加入，先结束该会话。再次审阅并确认“永久删除本机副本”。成功后副本从清理列表及“进入数据集”列表消失，当前应用中的原文、知识页和 Provider 配置保持可读。重启后检查同样结果。
4. 在其他设备检查原文和名册：本次仅清理本机副本，不应触发远端删除或撤销设备。
5. 若仍未锁定同步或另一应用进程仍使用旧副本，确认清理应失败并提示锁定/关闭占用后重试，不能破坏该副本。确认弹窗打开后，另一进程改变目录选择或副本文件，再确认应拒绝过期预览；刷新后重新审阅。
6. 若 OS 密钥存储不可用，文件删除后应保留“清理未完成”条目。恢复系统密钥存储后点“继续清理”，确认完成。重启也应保留待办；清理不会删除当前或其他副本的安装密钥。
7. 将 UI 切换为英文，在手机窄屏重复查看、取消与确认，核对警告和按钮可读、无溢出。

结果记录：设备/系统、旧副本 ID、清理前后字节数、取消结果、占用保护、失败重试、重启后状态。系统密钥不得复制进截图或日志。

## D7：加入过程中业务消息等待

准备：桌面作为 owner、手机作为新 joiner，两端使用包含本次修复的构建。用测试数据，避免拿唯一副本做故障试验。

1. 手机开始加入，桌面批准。在手机尚未应用成员名册/初始快照时，桌面连续录入几条带唯一标记的文本；条件允许时让接收延迟覆盖多次同步轮询。
2. 加入过程中业务消息可以显示等待，不能因暂未激活反复形成 `sync_local_membership_inactive` 拒收或到三次后 drop；也不能提前显示为已消费。名册与初始快照应继续推进。
3. 等待加入完成，按提示进入数据集并完整退出、重开。检查每条唯一标记文本及对应知识数据最终可见，文本不丢失、不重复。之后继续录入，验证双端正常收敛。
4. 若包含 Provider 配置同步，在桌面变更测试配置，确认等待后最终收到正确配置。不要在截图或验收记录里暴露 API Key。
5. 记录两端状态、录入时点、加入完成时点、唯一标记数量与最终数量。若检查诊断数据，按两端分别核对拒收/drop/收敛，不能仅凭一端宣称全部通过。
