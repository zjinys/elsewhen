# AI 对话契约与验收基线

## 归属与状态

本文件对应 [AI 对话体验 Roadmap](../roadmap/2026-09-30-ai-chat-experience-roadmap.md) 的 C00，定义主对话和知识页对话共用的运行契约、回归场景和测量口径。契约是 C01–C09 的实现约束，不代表流式、取消或队列已经交付。

基线版本：`chat-local-v1`。2026-09-30 在当前工作区、C00a 时间上下文实现后建立；只使用临时 SQLite 和本机脚本化 HTTP Provider，不使用个人记录、真实密钥或外部模型。

## 输入与运行身份

- `conversation_id`：业务会话。主对话与知识页对话适用同一契约。
- `input_message_id`：触发本次生成的已提交用户消息，不以“执行时最新一条”代替。
- `input_basis`：上下文截止消息、必要消息/材料版本及策略版本的引用或指纹；旧 run 不无意消费后来提交的输入。
- `run_id`：一次生成运行的稳定身份；用户重试创建新 run，并保留与原输入及前次 run 的关系，不再次保存用户输入。
- `provider_basis`：本轮采用的配置 ID/版本、模型、窗口和输出预留，不包含密钥。failover 的请求分别记录，不能重置本轮已完成动作。
- `request_id`：同一 run 内的一次实际模型请求；usage 先在请求内合并，再跨请求累加。
- `action_id`、`proposal_version`、`target_basis`：用户审阅的动作、内容版本与目标依据。一个 run 可产生多个提议，每次批准都显式绑定选中项。

输入保存继续使用既有 submission idempotency key。run ID 不能替代输入幂等键，tool call ID 也不能替代业务动作确认身份。

## 状态与事件契约

### 状态

建议实现语义为 `preparing → running → completed/failed`，取消路径为 `preparing/running → cancelling → cancelled`；异常启动恢复为 `interrupted`。终态不可被晚到事件复活。

待审提议独立持久化：本轮可以完成并留下待审草稿，不要求 Provider 请求一直挂起等待人工。后续显式审阅与业务执行各有结果。

### 事件信封

每个事件包含 `run_id`、该 run 内单调递增的 `sequence` 和事件内容。Provider 请求 ID、工具调用 ID 或提议 ID 在相应事件中携带。

| 事件语义 | 来源 | 展示与持久化规则 |
|---|---|---|
| 阶段变化 | Rust 编排层实际开始相应工作 | 展示准备、请求、检索、阅读、工具、收尾，不伪造百分比 |
| 正文增量 | Provider 解码并通过展示边界的内容 | 属于未完成回复，不自动认定为最终答案 |
| 工具开始/结果 | 实际 dispatch 与返回值 | 结果绑定调用 ID；成功写入须有业务回执 |
| 提议就绪 | 草稿持久化成功 | 展示具体动作和版本；未接受不执行 |
| usage 更新 | Provider 或显式标注的估算 | 标明 request、来源与完整性；缺失不冒充精确零值 |
| 最终快照 | 核验与终态提交后的运行快照 | 最终正文、有效引用、动作结果和状态相互一致 |
| 失败/取消/中断 | 运行裁决 | 保留已落盘成果；不能暗示已提交业务操作被撤销 |

### 消费规则

- 重复序号不重复应用；错 run 的事件不改当前会话。
- 发现序号空洞时取权威快照，不盲目追加文本。
- 重订阅拿到带最后序号的快照，再衔接后续事件；快照与订阅交接不能留下丢事件窗口。
- 终态快照优先于晚到增量；Dart 不通过本地 Set 决定 Rust 是否已完成或执行过工具。
- 流式协议残片与私有推理不展示。正文里的保存声明和引用仍经过已有核验，不因“已经流出来”而跳过。

## 取消、确认与恢复边界

1. 取消接收后不启动下一次请求或动作；当前事务已提交的结果仍有回执。服务商是否停算/停计费不由 UI 承诺。
2. 确认携带动作 ID、提议版本和必要目标基底；普通短回复、否定句、别的会话以及过期授权不能执行。
3. 编辑提议后旧确认失效；多项确认明确列出动作及逐项结果，原子性必须说明。
4. 写入与执行回执尽可能共享现有业务事务/幂等边界。无法确认提交结果时标待核实，不自动重放。
5. 正常退出有界 flush；异常退出只能恢复已持久化检查点，不能保证恢复最后一个 token 或模型内部状态。
6. 队列消费与 steering 注入有持久身份，不能同时注入当前任务又再次派发下一轮；用户停止会冻结派发。

## 固定回归场景

| 场景 | 现有基线或新增用例入口 | 后续验证重点 |
|---|---|---|
| 普通短问答与 32K 请求 | `short_new_conversation_fits_conservative_32k_budget` | 时间块、完整原问题、工具开销与最终预算 |
| 读工具后回答 | `chat_local_fixture_baseline` 的 `read_tool` | 真实阶段、原生 call/result、请求内/跨请求 usage |
| 空回复、协议 fallback | `conversation/protocol_tests.rs`、`continuity_tests.rs` | 不丢原任务、不重复写入、不展示内部协议 |
| 草稿与短追问 | 现有草稿状态/FollowUp 测试 | 审阅内容、进度追问不当成确认 |
| 否定、旧授权、重复确认 | C01 添加明确 ID/版本回归 | “好的，别保存”、A/B 多提议、编辑与并发 |
| 时间与长对话 | `time_context/tests.rs`、memory/budget 测试 | 当前/发送/事件时间分离，摘要与精确信息回读 |
| 长知识页、源版本变化 | 既有 knowledge authoring/review/reading 测试，C07 场景 | 全文覆盖、选区保护、过期基底不覆盖 |
| 取消、切页、丢增量、重启 | C02–C04 新增故障注入 | 终态一致、快照衔接、副作用回执与不确定状态 |
| 排队和补充要求 | C08–C09 新增持久队列测试 | 输入先保存、消费一次、停止不自动点火 |

新增契约的场景尚未实现时标“待实现”，不得删除相应验收项或以文档存在代替测试通过。

## 本机基线与复测命令

```bash
NO_PROXY=127.0.0.1,localhost no_proxy=127.0.0.1,localhost \
  cargo test --lib chat_local_fixture_baseline -- --ignored --nocapture
```

基准测试位于 `src/ai/conversation/baseline_tests.rs`，常规 CI 标记 ignored，更新基线时显式执行。每个场景 8 次，数据通过 `CHAT_BASELINE` JSON 行输出，不包含 prompt、工具参数或密钥。

2026-09-30 实测（包括 C00a；不是改造前历史测量）：

| 指标 | 普通直答 | 一次读工具后回答 |
|---|---|---|
| 请求数/样本 | 1 | 2 |
| 本地保存中位数 | 0.327 ms | 0.339 ms |
| 本地保存范围 | 0.316–0.422 ms | 0.311–0.392 ms |
| 完整回复中位数 | 30.492 ms | 36.104 ms |
| 完整回复范围 | 29.772–254.088 ms | 35.031–39.197 ms |
| 每请求保守输入估算 | 23503 | 23503、23740 |
| 模型窗口 / 输出预留 | 32768 / 4096 | 32768 / 4096 |
| Provider usage / cache | 未报告 | 未报告 |
| 首次进度 / 首段正文 / 取消延迟 | 当前接口不提供独立观测 | 当前接口不提供独立观测 |

普通直答首个样本包含冷启动开销，不剔除后伪装成完整分布；8 个样本不用于宣称 p95/SLA。这些是本机脚本化 Provider 的应用开销，不代表外部模型耗时或真实回答质量。未知模型的计量在当前实现中采用 UTF-8 bytes 保守估算，并非服务商真实计费 token。

C03 后增加真实阶段、首段正文与取消的独立时间点；C06 增加摘要自身成本；C08 增加排队等待与本地提交分离指标。同版本固定材料对比前后结果，不能混用本机与公网端点或拿工具进度冒充首字速度。

## 2026-10-01 — C03 真实 Bridge 到共享 Widget 的本机测量

新增 `ui/test/chat_run_performance_bridge_test.dart`：临时 SQLite、loopback SSE 服务、真实 Rust 动态库、FRB、共享 `ChatRunStatus` widget。服务保持连接不发 EOF，测试等待实际正文组件出现后点击停止，再等待实际终态标签出现。不是仅测 Future 返回，也不是把工具进度当正文。

```bash
cd ui
NO_PROXY=localhost,127.0.0.1,::1 no_proxy=localhost,127.0.0.1,::1 \
  fvm flutter test test/chat_run_performance_bridge_test.dart
```

一次通过样本的 `CHAT_LOOPBACK_UI` 输出：

- SSE 合成正文释放 → 首段可见：**399 ms**。
- 点击停止 → “已停止生成”可见：**466 ms**。
- 检查点策略：100ms 或 2KiB；UI 事件轮询：300ms，每次最多 64 个事件。
- 两项回归门槛均为 **2 秒**：宽于检查点/轮询/测试帧调度的本机周期，用于发现等待 EOF 或仅隐藏进度而未取消的回归，不承诺公网模型 SLA。
- 这是单样本 smoke 测量，不声称中位数或 p95；与 C00 同步返回基线不是同一指标，不能把 30ms 总耗时与 399ms 首段可见直接作速度收益比。
- 此样本 Provider 未提供 usage/cache，标记为未知。真实端点延迟、模型回答质量和缓存收益仍待独立验收。

`chat_run_bridge_test.dart` 另外验证主对话/知识页工具分片、分页/重开、取消与保存声明隔离；`chat_run_review_bridge_test.dart` 验证两个入口的“检索 → 草拟知识页 → 拒绝/接受 → 执行回执”，拒绝不落页、重复接受不重复保存。controller/widget 测试覆盖慢消费有界轮询、重复/错 run/缺口及终态补快照。

## 2026-10-03 — 收尾场景与有界真实验收

工程门禁：Rust 457 passed / 10 ignored，Flutter 283 passed，Python额度测试2 passed，FRB/release通过。analyze仍有4条既有warning、73条info、退出码1。后续模型场景按需显式执行，普通测试不读取个人库或连接真实端点。

真实配置：`deepseek-flash`，窗口65536，单请求输出上限4096。使用合成材料、临时SQLite与内存relay；只读已授权Provider配置，不读取或上传个人事件/知识页。累计39次请求在分次授权44次内，不把未用额度滚成隐含新授权。

| 场景 | 请求数 / 总耗时 | 核验结果 |
|---|---|---|
| 主对话拒绝 / 新稿接受 | 3 / 5185ms；3 / 11184ms | 实际读取与草拟、三项约束、重复回执、原页不变 |

| 摘要首次 / 重试 | 3 / 7960ms；2 / 2313ms | 首次1摘要请求，重试0摘要请求、1缓存命中；原文回读及约束正确 |
| 主对话 / 知识页补充 | 2 / 3989ms；2 / 2551ms | 实际读工具后只保留项目范围、一次注入、不写数据 |
| 修复后的4752字符全文 | 3 / 20902ms | 首/中/尾完整、否定语义保留，分块归纳不冒充原文 |
| 真实流取消 / 原输入重试 | 1 / 13656ms；1 / 13630ms | 终态、重开冻结、用户输入不重复，未盲重放动作 |

### 复验入口与额度

必须先获得当前有效的显式授权，再运行脚本；示例中的上限不是自动授权：

```bash
python3 scripts/real-chat-acceptance.py \
  --provider-db /path/to/elsewhen.db --allow-live-model --max-requests 8 \
  --test-filter real_model_chat_full_page_acceptance
# 多个 --test-filter 共用同一 relay 额度，不为每个场景重置。
python3 -m unittest discover -s scripts -p test_real_chat_acceptance.py -v
```

独立真实场景还包括 `real_model_chat_workflow_acceptance`（主入口）、`real_model_chat_wiki_review_acceptance`、`real_model_chat_summary_acceptance`、`real_model_chat_supplement_acceptance` 和 `real_model_chat_cancel_recovery_acceptance`。`CHAT_REAL_QUOTA` 区分实际发送与本地额度拒绝，`CHAT_REAL_INCOMPLETE` 列出尚未启动的场景；失败不会自动获得新的请求额度。

### 失败样例及修正

- 固定3000字符切块将“不表示试验已经完成”拆成否定前缀和肯定尾句，标记检查通过但模型误称材料矛盾。已改为优先句末/段末边界，加前后各最多120字符只读邻文，不改变覆盖范围；新增两项确定回归。最终真实输出保留否定语义。
- 旧摘要夹具只证明原文回读，未证明摘要注入；现在按工具预留后设定选材预算，断言`summary_ready`，缓存重试必须零新增摘要请求。
- 拒绝后原样重复草拟请求被模型视为无意重发；真实夹具明确要求生成新的待审稿，不改变生产“拒绝不执行”语义。
- 中途额度耗尽的本地429不得记为模型质量失败或成功；原失败记录保留，单独复验缺失场景。

这些是真实端点脚本场景和逐条结果核对，不是真人在GUI连接端点的手工点按验收；后者尚未执行。UI链路由隔离Bridge/widget覆盖，不合并两种证据冒称人工验收。

## 验证分层

- **Rust：** 纯逻辑、协议、临时 SQLite、loopback HTTP 与故障注入。
- **Flutter widget：** 渲染/交互状态，mock 不证明原生链路。
- **真实 Bridge：** 经 `ui/test/support/isolated_bridge.dart`，两个对话入口共用 API 与状态契约。
- **真实模型：** 仅使用允许发送的测试材料和端点，记录模型/配置/材料版本以及指令遵从、日期理解、来源准确性、全文覆盖和失败样例。没有执行则明确标待验收。

常规诊断只保留 run、请求、计数、时长、状态、错误类别与版本引用。精确原始请求重放不是默认日志功能，需要用户显式开启本地诊断，并定义脱敏、保留和清除方式。
