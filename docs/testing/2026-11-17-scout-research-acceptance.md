## 版本与升级

- Scout：新增 D1 `0004_research_observations.sql`、`0005_product_insights.sql`，公共契约 `version: 1`。旧 `/findings` 保留，新 `/v1/findings` 用服务实例 ID、固定上界与整数游标续传。
- Elsewhen：SQLite 迁移 87 保存可重建缓存与游标，88 保存本地 AI 分析任务，89 保存未同步研究草稿。个人研究与偏好复用既有 human-held memo、wiki 修订、导出与同步，不能因清空 Scout 镜像而删除。
- 新 FRB API 包含产品查询/详情、研究保存/列表、分析及偏好读取/保存；`scripts/regen.sh` 已生成桥接并构建 release 库，Rust/Dart hash 一致。
- GitHub 身份从名称转为数值 repo ID；保留旧名称身份的 alias，迁移既有观察与源成员关系。客户端按 alias 找到已有研究，保留旧研究身份。跨平台产品没有按名称自动合并。
- 旧服务返回缺少 v1 接口时，客户端继续读取旧动态，不推进假的完整增量水位；发现页提示升级。历史回填每拍最多 20 个快照，旧快照口径标 `legacy-unknown`，不能当完整趋势；线索索引每批最多 40 产品，待处理数量在界面提示。

发布顺序（本轮只完成演练，没有执行远程迁移或发布）：

```bash
cd scout-cf
npm ci
npx wrangler d1 migrations apply elsewhen-scout --remote
npx wrangler deploy
```

先在目标库备份与维护窗口内应用新增迁移，再发布 Worker，最后运行新客户端。新表对旧接口是增量扩展；回退应用代码时保留观察表和个人研究，不用删除迁移来回退。部署后检查 `/v1/findings` 身份/游标、采集失败记录、回填/索引积压，再开始连续观察。现有历史无法自动补出从未采到的 7/30 天证据。

## 数据与查询契约

- 产品身份为 JSON 编码 `[platform, platform_key]`；同平台同 ID 多源只生成一张产品卡。来源成员关系保留，跨平台保持独立。
- 仅成功、完整、非空且 ID 无重复的结果发布观察。每个成功 run 即使无字段变化也记录观察；空响应、解析错误、部分条目错误和 GitHub incomplete_results 均失败，不能发布“全部消失”。目前不能区分真实空榜，宁可保持上次成功基线。
- 提交以源 lease token 和事务检查栅栏保护，快照、观察、产品、finding、run 同批提交；过期提交回滚。D1 批次中的失败行为由本地迁移/并发测试验证。
- `GET /v1/findings?after=&upper=&limit=`：升序 ID，最大 500 条；首次响应捕获 upper，后续页沿用。客户端成功提交一页后更新 after，单轮 5000 条/20 秒后续拍恢复。服务身份改变不混用旧水位。
- `GET /v1/products?q=&source=&view=&before=&as_of=`：40 产品一页，view 为 signals/growth/price/all，固定 as-of 与 `[实质变化时间, product_id]` keyset。搜索范围和来源筛选在服务端执行。线索索引是可重建派生表，存在异步积压时明确提示；固定 as-of 下尚未建索引的产品可能暂时不在该查询结果中，刷新获取新 as-of 后再查。
- `GET /v1/products/detail?id=&before=`：每页最多 100 个观察，不读取/解析整个源的全部历史。计算每产品最多 800 观察，界面绑定打开时的产品证据。缓存最多 32 个查询/详情键，离线只回退同一查询的最后成功值并标 stale，未缓存查询不会伪装离线命中。
- 趋势为同来源、同 spec_hash 的 7/30 天窗口，提供真实起止时间、样本数、端点 snapshot ID、算法 `window-v1`、可比较的前一窗口与至多约 30 个绘图点。缺采、缺指标、口径变更和过旧采样不能成为完整窗口；旧口径未知的回填不能成为可靠增长。
- stars/forks/评价数为各自计数，评分为评分，榜位为 positions，price_cents 为币种最小单位。评价数不等于评论正文数量或独立需求人数。零基数不计算增长百分比；计数下降标修正，榜位 20→5 为上升 15 位。价格没有币种时不输出可比价格信号，不推断订阅周期。
- 当前规则：至少 4 观察、3 次正向变化且无回落形成持续增长；榜位上升至少 5；价格变化/新进入监控范围保留 7 天。价格为 `price-change-v1`、入选为 `scope-entry-v1`。首次/口径重置基线保持安静。阈值目前在代码中，未提供用户配置。

## 研究与分析

“发现线索”默认展示有解释的信号，全部产品入口保留。被放弃、无实质指标变化的产品在信号视图降低重复出现，标题/时间刷新不触发重现；有新数值证据时可重现并在详情提示复核。该反馈尚未覆盖重复/弱证据等独立类型。

研究保存当时公共产品证据、个人判断、目标人群、报价假设、替代方案、关键未知、实验/期限/条件与实际反馈，阶段可回退。卡片可直接进入待研究、继续观察或不相关；未保存编辑自动落本机草稿，保存正式研究后删除草稿。关闭编辑器或 Esc 在当前进程保留草稿；草稿会写入本机迁移 89 的未同步草稿表，进程重启后可恢复；它不进入同步、导出或后台 AI。研究列表最多读 1000 条，没有更大规模支持承诺。

主题由用户逐行确认，一个产品可跨多个主题；同主题可横向比较最多 5 个产品，展示当前产品/监控源数量、买方、报价、未知和不适配原因。不凭同名自动归组，没有机器聚类/拆并建议；共同需求、矛盾仍需用户阅读证据判断。来源数量指监控源数量，不能冒充独立证据主体。

个人偏好仅含用户填写的人群、方向/任务、能力/资源、时间/成本、可接触买方。默认空白保持中性；用户可记录适配/不适配原因，显式将偏好固定为本次判断依据，之后清空偏好不重写旧研究。偏好与研究走相同同步/冲突规则。

人工证据上限 20 条，每条 8–8000 字符，可 URL 抓取后确认或直接粘贴；保存 URL+正文内容哈希、确认时间、原文类型，可选作者、语言和来源声明发表时间。正文不可自动当译文；修改原文生成新证据，用户可从本次研究移除，旧 wiki 修订仍保留。尚无平台级评论作者去重或自动评价编辑/删除检测。

AI 每项研究独立 opt-in，仅材料与问题参与候选分析，不自动浏览或调用工具；单次最多 12000 字符、单条最多 4000，截断有覆盖信息。任务绑定证据/问题/提示/provider 配置版本，lease 保护且最多 3 次尝试；失败等待 30 分钟，变更/撤回会使旧结果过期或取消。候选最多 6 观察、3 假设，逐字引文和证据 ID 校验，阿拉伯数字不能凭空引入；不具备完整语义真实性证明能力。支持/反对证据 ID、未知和实验可读，采纳需用户保存。确认后的候选及其有界证据摘录写入研究，后续自动分析不覆盖人工判断。任务记录模型/token 用量，尚无费用估计和完整耗时/失败分类面板。

## 可复现规模基准

命令：`cd scout-cf && SCOUT_SCALE=1 npx vitest run test/scale.test.ts`；`cargo test --lib research_scale_thousand_records -- --ignored --nocapture`。

设备：Intel Core i7-12650H、Linux x64、Node v26.7.0。测试由本地 Miniflare D1 生成 10000 产品/1000000 次观察，每个请求等待 JSON 解码完成；预热一次、计 20 次，升序第 19 个样本为 p95。服务端每页 40 产品/详情 100 观察；产品窗口最多 800 观察/产品。没有远程 D1、Flutter 渲染或网络耗时。

| 测量项 | p50 | p95 |
|---|---:|---:|
| 全部产品第一页 | 298ms | 333ms |
| 线索第一页 | 278ms | 309ms |
| 产品详情 | 14ms | 19ms |
| 本地 1000 研究记录列表（20 次） | 31.02ms | 32.48ms |

查询计划使用 `idx_observations_product_time`，新增 `idx_observations_product_snapshot` 支持最新观察索引。Node 进程峰值 RSS 为 340353024 字节（约 325MiB），不包含独立 workerd 进程。该结果只证明此固定本地数据集的查询基线通过目标；O7.2 端到端首屏与缓存详情目标仍待真机验证。更多数据、不同源密度和长期索引增长尚未测。

## 后续验收入口

1. 在部署演练确认后发布本轮 Scout，检查升级基线安静、游标持续推进、失败不推进可信采样、索引积压能清空。
2. 对三类来源至少 30 个真实产品走查用途/理由/缺口；补浅色、英文和真机，记录首屏/缓存详情性能。
3. 观察至少 7 天，继续到有真实 30 天窗口；缺采与误报分别登记。
4. 为 AI 建立含反证、营销自述、语言差异和注入文本的评审集，做至少 20 份真实模型人工审阅；目前不宣称可以自动判定市场事实。
5. 用户从 10 个真实候选选择 3 个研究，并完成至少一个实际验证与反馈；连续观察与用户实验不会由合成数据代替。

## 后续交互调整（2026-11-19）

主对话中的 Scout 提示由“未读总量 + 按源计数”改为最多三个精选产品信号。精选只接受服务端完整窗口、价格变化或排名/持续增长理由，并绑定产品与端点证据；没有可靠信号时不显示卡片。普通新发现、消失、首次监控、源计数和过期/缺采样不会打断主对话。旧数量卡保留在消息历史中但不再渲染，复制和保存主题也不会暴露内部系统标注。Rust 4 项卡片测试、Flutter 精选卡/聊天复制回归和桥接 release 构建通过。
