# 参考项目笔记：AIcove

> 位置：`ref/AIcove`（Flutter 本地优先 AI 陪伴应用，与 Elsewhen 技术栈同源：Flutter 桌面/移动、SQLite 本地存储、用户自配 API Key、设备配对同步）。
> 本文档解释"哪些值得参考、参考的具体是什么"，供后续决策。关联：[`video-plan.md`](marketing/video-plan.md)（宣传elines）、`docs/roadmap/`。

## 一、它是什么，和我们差在哪

**AIcove = 会主动找你的 AI 陪伴聊天应用**（角色人设、语音、画画、表情包、长期记忆）。卖点是"情感陪伴"。

**相同**（所以工程实践有参考价值）：

- Flutter 跨端 + 本地 SQLite，隐私立场一样："聊天数据只存你自己设备上，模型用你自己的 API Key 直连，不经过中转服务器"
- 设备间同步走"扫码/配对码 + 设备互信"，与我们同构
- 同样重视 AI 的"记忆"问题（他们叫记忆库，我们叫知识库/LLM Wiki）

**不同**（所以产品功能不能照搬）：

| | AIcove | Elsewhen |
|---|---|---|
| 定位 | AI 陪伴（拟人化、有情绪价值） | 个人认知主循环（记录→沉淀→复利） |
| 记忆的用途 | 让角色"记得你们聊过的事" | 把事件消化成结构化知识页，产生行动 |
| 多模态 | 语音/绘图/表情包是核心卖点 | 不做，文本为主 |
| 同步 | 局域网直连 + 可选自部署云 | 盲中继端到端同步 |

结论：**工程纪律和文档体系抄，产品路线不抄**。

## 二、参考点详解

### 2.1 「项目记忆」文档体系 ⭐ 最值得抄

**它是什么**：AIcove 用一套纯 markdown 的目录当作"人和所有 AI agent 共用的长期记忆"，让任何一次新会话（Claude Code / Codex / Pi）都能快速接上上下文。目录结构：

| 文件 | 放什么 | 什么时候写 |
|---|---|---|
| `README.md` | 项目总览、架构边界、**当前重点**、写入规则 | 架构变化时 |
| `需求日志.md` | 用户每次提需求的**原话** + 一句话结果 | 每次实际改动任务 |
| `决策记录/NNNN-标题.md` | 架构级决策，一字一文件：背景 / 备选 / 决定 / **代价** | 选型、数据流、边界变化时 |
| `经验教训.md` | **硬约束**清单（见下） | 修完"表面原因≠真实原因"的 bug 后 |
| `术语表.md` | 领域术语统一口径，带"避免使用"别名 | 出现新术语时 |
| `历史任务/` | 没做完的任务的原始方案，只读归档 | 任务取消/搁置时 |

**它牛在哪——「经验教训」的写法**。不是流水账，每条是违反会直接出 bug 的约束，带正例路径和回归测试路径。真实摘录：

> ### 可空模型配置的清除语义（2026-09-16）
> - 界面传入 `null` 不等于配置实际被清除；`copyWith` 若使用 `value ?? this.value`，显式清除会被当成保留。……失效配置使用 sentinel 区分"未传参"与"显式 null"。
> - 正例：`.../memory_config.dart`；回归：`.../memory_plugin_detail_page_test.dart`

**对 Elsewhen 的意义**：我们有 roadmap（计划层）和 CLAUDE.md（agent 指令），缺三层：

1. **教训沉淀**——这轮 CI 调试的 9 个坑，全是"会再犯"的硬约束，现在只存在于对话记录里：
   - `git push | tail -1` 管道吃掉退出码 → 推送后必须 `ls-remote` 验证
   - dash（CI 的 sh）不认 `{A,B,C}` 大括号展开 → shebang 是 sh 的脚本禁用 bash 语法
   - runner 镜像会静默升级预装软件 → CI 不硬编码版本号路径，按 glob 定位并 fail-loud
2. **决策记录**——"清空同步表而非 UI 撤销""本地留全文仅信封截断 reason"这类取舍，过两个月就没人记得为什么
3. **术语表**——"事件/记录/对话/消息"在代码和文档里已经偶尔混用

**落地形态建议**：`docs/decisions/`（决策）+ `docs/lessons.md`（教训）+ `docs/glossary.md`（术语），CLAUDE.md 指路。不需要他们的 hook 自动化，手动写就够起步。

### 2.2 Release 附 SHA256SUMS

**它是什么**：每个 GitHub Release 附一个校验和文件，用户可核对下载完整性：

```
AIcove-1.2.0-android.apk  3f9a...  ← SHA256SUMS 内容
```

**对 Elsewhen 的意义**：我们 release.yml 已产出 6 种安装包，加一步生成 `SHA256SUMS` 到产物目录即可（约 5 行 yaml）。顺手在 README 下载说明里教用户校验。

### 2.3 「带着家当搬过来」的生态兼容思想

**它是什么**：AIcove 完整兼容 SillyTavern 的角色卡/预设/世界书，一键导入。这是它们的获客利器——用户不是从零开始，是**搬家**。

**对 Elsewhen 的意义**：抄思想不抄对象。我们的"搬家入口"候选：

- **导入**：Obsidian/Markdown 笔记 → 批量建事件或知识页（谁不想把积累的旧笔记喂给知识库？）
- **导出**：知识页本来就是 markdown，导出成 Obsidian vault 应该是零成本的——这同时是"数据主权"承诺的兑现证明

### 2.4 局域网直连同步（roadmap 候选）

**它是什么**：同一 Wi-Fi 下扫码即同步，不走任何服务器；附件断点续传。

**对 Elsewhen 的意义**：我们的盲中继方案在**跨网络**场景是必须的，但同一局域网（家里手机↔桌面）走中继是绕路。可作为同步引擎的**第二传输层**：发现对端在局域网就直连，否则回落中继。配对/加密/信封逻辑全部复用。收益：延迟降低、断中继也能同步。**适合进 roadmap 排期，不急**。

### 2.5 对话短期记忆：自动压缩 + 手动"翻篇"

**它是什么**：聊天太长时自动把旧内容压缩成摘要腾出上下文空间；用户也可以手动点"翻篇"开始新话题（旧内容归档但可被长期记忆召回）。

**对 Elsewhen 的意义**：我们的主对话流是长生命周期会话，上下文压力相同。现在靠消息截断策略；"翻篇"是一个用户可控的轻量替代（翻篇文章落进事件库，知识消化照常接管——和主循环天然兼容）。**中优先级 UX 改进**。

### 2.6 回顾主动出现（roadmap 候选，需改造成我们的语义）

**它是什么**：AIcove 的角色会主动发消息（早安、"会开完了吗？"），机制是"基于时间/内容/规则触发 + 工具调用安排下一次联系"。

**对 Elsewhen 的意义**：**不要拟人化**，但机制可改造为"回顾到点主动出现"：当日事件分析完成、知识页有更新待审阅时，托盘通知/打开页横幅 brings 你回来，而不是等人想起来开 App。符合"主循环"定位——循环的最后一环（回顾）目前是被动的。

### 2.7 宣传与运营（对接 video-plan）

- **README 对比句式**："不是又一个『你问一句、它答一句』的聊天框"——用"不是 X"先立立场再讲功能。我们 README 刚写的"而不是一堆一次性聊天记录"同路，方向被验证
- **落地页叙事**：website 有 story 页（插画+滚动讲故事），比功能列表高级；我们若有官网可学
- **冷启动路径**：内测群（QQ）+ LINUX DO 社区首发——中文 self-host 圈子的即时反馈渠道，链到我们 video-plan 第 8 周之后
- **下载区规范**：平台×文件×备注的表格、SHA256SUMS、"测试版请备份"提示，都是一行成本大提升观感

## 三、明确不抄的

- 语音/绘图/表情包/人设——产品灵魂不同，做了会稀释定位
- 云端自部署后端（他们 cloud_backend）——我们盲中继架构已决（信封端到端，Service 无明文），路线不同
- 多 harness 的 hook 自动化系统——我们单协作者+可控 agent 数量，手动纪律够用

## 四、如果要落地，建议顺序

1. **本周**：`docs/decisions/` + `docs/lessons.md` + `glossary` 骨架；教训先用本周 CI 9 连坑 + 401 结案 + splash 居中定位填第一批
2. **顺手**：release.yml 加 SHA256SUMS
3. **下次 roadmap 排期**：Markdown 导入导出（生态兼容）→ 翻篇 → 回顾主动出现 → LAN 直连
