# Hierarchical knowledge-page synthesis

目标：将“总结多个知识页”从把全文片段全部塞进一次对话，改成可追溯、可分层、受预算约束的摘要树流程，避免多页任务因上下文超限而失败。

## 当前问题

- 多个 `get_wiki_page` 结果直接进入同一轮上下文，输入 token 随正文长度线性增长。
- 读取预算耗尽后，已完成的页面内容不能稳定进入最终总结。
- 会话历史压缩解决的是聊天上下文，不等于知识页综合任务的 Map-Reduce。
- 页面版本变化、单页读取失败和汇总超限没有统一的任务级恢复策略。

## 设计原则

- 原文只用于生成叶子摘要；中间层和最终层只传摘要、来源和版本 hash。
- 每个摘要都必须保留来源 slug、标题、content_hash、覆盖范围和不确定性。
- 每一层都先估算 token，超限时分组或继续压缩，不把超限留给最终 provider。
- 单页失败不阻塞其他页面；版本变化只重做受影响的叶子摘要。
- 摘要任务和普通聊天分离预算、重试和运行记录。

## 阶段

- [x] **P0：任务识别与观测**
  - 识别“总结多个知识页/资料/来源”的综合任务。
  - 记录候选页数量、叶子摘要数量、各层 token、失败页、版本 hash 和最终压缩次数。
  - 为真实会话建立基线：全文直塞的输入量、耗时和失败率。

- [x] **P1：单页叶子摘要**
  - 新增单页摘要流程：按页读取、必要时分页、独立生成短摘要。
  - 摘要结构固定为：核心结论、关键步骤、适用条件、限制/冲突、来源定位。
  - 叶子摘要绑定 `content_hash`；页面变更时标记过期并重新生成。
  - 单页读取失败只记录失败节点，不让整棵摘要树失败。

- [x] **P2：分组汇总**
  - 将叶子摘要按 token 预算分组，组内生成中间摘要。
  - 中间摘要继续保留来源集合和冲突信息。
  - 组数超过预算时递归合并，形成摘要树而不是一次性汇总。

- [ ] **P3：最终回答生成**
  - 最终模型只接收摘要树根节点、必要来源索引和用户问题。
  - 明确区分“已覆盖页面”“读取失败页面”“版本变化页面”。
  - 没有可用摘要时返回可操作的重试/重新导入提示，而不是泛化为上下文超限。

- [ ] **P4：预算与恢复治理**
  - 为叶子、组间、最终回答设置独立输入/输出预算。
  - 每层重试次数和总 token 预算独立受限。
  - 支持从中断节点恢复，不重复生成已完成摘要。
  - 页面版本变化只使对应叶子及其祖先路径失效。

- [ ] **P5：质量与性能验证**
  - 增加 1、5、20、100 页的固定 fixtures。
  - 验证总 token、延迟、失败率、来源覆盖率、冲突保留和回答质量。
  - 与旧流程做回归对比，确认普通聊天、单页读取和写入工具不受影响。

## 初始预算建议

- 叶子摘要：每页 300–600 output tokens。
- 单个中间摘要：最多 1,500 input tokens，1,000 output tokens。
- 最终汇总：最多 6,000 input tokens，2,000 output tokens。
- 单次任务默认最多处理 32 个候选页，超出后按相关性分批。
- 每页最多自动重读一次，版本持续变化则保留失败节点。

## 完成证据

每个阶段补充真实任务样本和数据库事件证据。最终至少证明：20 个长知识页可以完成分层总结；最终请求不携带全部原文；单页失败不会丢失其他页面结果；页面版本变化不会混合不同版本内容。

### P0-P2 实现记录（2026-11-24）

现有 `synthesize_knowledge` 的证据提取结果现在额外生成 `knowledge_summary_tree`：按页形成带 `content_hash` 的叶子摘要，按每组三页形成中间摘要，并生成受长度上限约束的根摘要；原始逐字证据和 coverage 仍保留用于追溯。预算计算包含摘要树，低预算时保留部分结果而不是整轮失败。P3-P5 的任务持久化、递归模型汇总和恢复审计仍需真实长任务样本继续验证。
