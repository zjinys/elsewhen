## 1. P0：主对话流的上下文管理（吸收「短期记忆」层）

> 已展开为独立路线图：[`2026-10-17-context-management-roadmap.md`](2026-10-17-context-management-roadmap.md)（源码级机制解剖 + P1–P4 分期 + 红线）。

**它解决什么**：主对话流是长生命周期会话，上下文超长后要么粗暴截断（丢事实）要么请求失败。AIcove 用 ADR0038 把"短期记忆"做成独立的上下文管理器，与长期记忆解耦。

**它怎么做**（`docs/04_功能模块规范/记忆系统/README.md`）：

- 话题「边界」+ 边界前内容压缩成摘要（存 `context_summaries`），原文不动
- **三种压缩**：手动翻篇（预览可编辑）/ 自动（到 80% 触发线） / 运行时（只剩一轮，不落库）
- 摘要口径严格："只继承事实、经历、约定，不带旧格式"——**压缩的是表述，不是事实**
- 压缩成功后触发记忆 Agent 把摘要覆盖段整理进长期记忆（书签推进与写入同事务，失败书签不动）

**移植到 Elsewhen**：

1. `context_summaries` 等价物进 SQLite（引 schema），主对话流引入话题边界
2. **翻篇的落点是主循环**：被翻篇的对话段本来就该登记为事件 → 知识消化接管 → 沉淀进 wiki。这是 AIcove 没有的联动（他们摘要只喂回上下文，我们摘要能变成知识），吸收后比原版更强
3. 自动压缩阈值沿用 80% 思路；摘要口径直接抄他们的措辞进提示词

**验证**：长会话（>200 条）请求不失败；翻篇后旧事实仍能被 AI 引用（经摘要或 wiki）。

## 2. P0：知识检索装配进主对话

**它解决什么**：wiki 页面越攒越多，但主对话的 AI 看不到"相关旧知识"，知识库和对话脱节。

**它怎么做**：`memory_items_fts`（FTS5，中文二元分词，Dart 端写入），发消息时按"本轮输入+最近两轮"检索 ≤6 条约 1500 tokens 注入；检索器是 `MemoryRetriever` 接口，本期只做关键词，`embedding` 列预留，将来换向量只换 Provider。

**移植到 Elsewhen**：

1. `wiki_pages` 建 FTS5 索引（标题+正文，中文 tokenizer 用 trigram 或二元）
2. 每次装配主对话请求时：最近消息 → 检索相关 wiki 页 → 注入页面摘要（含 kind/slug/evidence_count）
3. 同样**先 FTS 后向量**——他们 2026-09-23 把四层向量库整个废弃归档（旧方案见 `05_历史归档/`），先关键词是踩过坑的正确顺序，我们直接走对的路
4. AI 对话浮层复用同一检索器

**验证**：提到"健身"能召回 habit 页；无关话题不注入（省 token）。

## 3. P0/P1：LAN 直连同步（第二传输层）

**它做什么**：同一局域网内扫码直连，附件断点续传，全程不出网。

**移植到 Elsewhen**：同步引擎抽传输层接口——LAN 发现（mDNS/手动 IP）直传 **密文信封**（加密逻辑、信封格式、配对信任完全复用，LAN 只是换传输，不做"局域网明文"降级）；不在局域网回落盲中继。附件/图片批量同步加断点续传。
收益：家里双端秒级同步、断中继可用、中继流量成本降为零。排期在传输层抽象就绪后。

## 4. P1：对话体验四件套（低成本高感知）

来源：他们 README 聊天体验节 + `聊天界面功能增强.md`。

1. **自然分段**：长回复按语义拆成多条消息逐条出现，代码块/图片不切断——长解释不再糊成一堵墙
2. **消息编辑与重新生成**：改写发过的话、不满意重生成（枚举现有 provider 语义一致）
3. **时间感知注入**：当前时间、距上次交互间隔、设备时区进 system prompt——"下周提醒我"类表述才有根基
4. **思考档位**：会话级思考深度开关，三家接口参数自动映射

## 5. P1：知识页/对话分享长图

**它是什么**：选几条消息渲染成高颜值长图分享出去。

**为什么对 Elsewhen 特别值**：知识页本来就是 markdown + 证据计数，渲染成"你的年度认知卡片"既是分享传播素材，也是**视频规划的现成素材**（evidence_count 涨到 7 的那天，B2 那支直接用）。选段→模板渲染→存图，纯前端工作。

## 6. P2：回顾主动出现（改造吸收，去拟人化）

**它怎么做**：触发器（时间/内容/规则）+ AI 管家分析会话决定是否主动 + **预生成机制**（通知发出前内容已备好）+ 作废与优先级（`04_功能模块规范/主动关怀系统/03、04、05`）。

**改成我们的语义**：不做"TA 来找你"，做**回顾的推进器**：

- 触发：当日囤积 N 条未分析事件 / 知识页有待采纳修订 / 距上次回顾超 X 天
- 预生成：后台提前把回顾摘要算好，通知点开即达（不现场等 AI）
- 落点：托盘通知 + 打开页横幅 → 一键进入回顾视图

这让主循环的最后一环（回顾）从被动变主动，循环才真正闭合。
