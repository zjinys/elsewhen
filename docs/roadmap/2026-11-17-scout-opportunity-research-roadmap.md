## 目标与交付边界

用户通过情报判断值得研究的生意，形成可验证的假设，再用实际反馈决定继续或放弃：

```text
可靠采集 → 产品归并 → 有窗口的趋势 → 值得研究的线索
                                      ↓
            加入研究 → 机会假设 → 小实验 → 外部反馈 → 更新判断
                                      ↑
                           需求原文、定价与同类产品证据
```

首版交付 O0–O3：产品去重、可靠趋势、关注理由、证据缺口、发现与研究两条路径，以及手动记录假设/验证结果。O4 补需求与付费证据，O5 做可选 AI 候选分析，O6 做需求主题与适配，O7 完整验收。首版不等待 AI 或自动需求聚类才能使用。

用户能回答的五个问题：

| 问题 | 主要信息 | 缺失时的行为 |
|---|---|---|
| 这是什么生意？ | 产品用途、目标用户/场景、收费方式 | 使用来源描述；目标用户未证实则标待核实 |
| 为什么现在看？ | 7/30 天变化、历史基线、持续性、入选理由 | 历史不足或采样不连续时不输出完整窗口增长结论 |
| 有人愿意付钱吗？ | 价格/周期、可核实付费陈述或交易证据 | 售价只证明报价，评价只证明评价；销量/收入未知 |
| 有什么切入空间？ | 具体抱怨、替代方案、同类比较、反证 | 没有原文时不生成痛点结论 |
| 值不值得我投入？ | 用户关注方向、已知能力/约束、关键未知、下一步验证 | 未设置偏好时保持中性，不推断用户适配度 |

## 实施前基线与原始缺口

已具备：独立 Scout CF Workers/D1 采集、快照/finding/run、Rust 本地镜像、后台轮询、已读、卡片网格、来源图标、side sheet 历史、存为素材和记为事件。此前记录的 25 项 Flutter 与 8 项存储测试仅作为基线，不替代本路线验收。

实施前复核的原始问题（当前修复证据见上方交付表）：

- `src/api/scout.rs::poll_scout_now` 单次只取 1000 条，随后推进本地时间水位；`/findings` 无续传游标。积压超限和拉取期间新增可能遗漏。
- `scout-cf/src/index.ts` 的 finding 详情按源读全部快照后解析；不能沿用为大数据产品趋势接口。
- `scout-cf/src/store.ts::recordRun` 先单独插快照，再 batch finding/run；失败快照不能成为下一轮可信基线。
- 目前镜像仅含变化记录；无变化的成功采集不产生 finding。仅靠 finding 无法证明趋势采样完整。
- 快照 90 天后抽样保留、配置和解析器会变化；趋势需要知道有效观察、监控范围、采样与版本。
- 当前 GitHub 是累计 stars 搜索榜，不是近期增长榜；CWS 只跟踪预设扩展；Gumroad 评价数不是销量；App Store 免费榜不是收入榜。

## 决策与数据归属

| 层 | 责任 | 边界 |
|---|---|---|
| Scout 服务 | 原始快照、成功观察、源覆盖、产品公共资料、确定性趋势与证据 | 不保存用户私人的研究假设；失败/部分采集不伪装成功基线 |
| Elsewhen 派生镜像 | 产品卡片、趋势、来源版本与离线证据缓存 | 可重建；联网失败保留最后成功版本并标新鲜度 |
| Elsewhen 个人研究 | 加入研究、用户假设、实验、反馈、搁置/放弃理由 | 持久、可导出；清空镜像或更换连接不删除；O3 接入既有同步规则 |
| 可选 AI 分析 | 基于固定证据版本提取描述、归纳需求、提出候选假设 | 有引用与覆盖说明；不能替用户确认或覆盖人工结论 |

O0 固定接口与样例，O1 落地时确定表名和迁移号。预计涉及产品/源映射、观察/指标、证据、个人研究记录、分析版本；不在规划阶段锁死迁移序号。

产品原始身份使用 `(平台, 平台稳定产品 ID)`，来源是“在哪个监控集合中观察到它”；同一平台的不同榜单/关键词允许指向同一产品。跨平台同名产品不自动合并。个人研究引用稳定产品身份和证据版本，不绑定可清空的镜像行 ID；服务连接使用稳定实例身份，不能仅靠可修改的 base URL 或远端自增 ID 区分。

- [x] **O1.3 每次成功采集落观察**：包含无变化观察，建立按产品/来源范围/时间查询的有界索引。指标缺失不写 0；榜单未见不写销量/用户归零；删除/改名/重新出现不丢旧轨迹。

## O2 确定性趋势与可解释的线索

- [ ] **O2.1 同口径窗口计算**：7/30 天绝对增量、适用时的相对变化、前一可比窗口、采样点数/覆盖率/端点实际时间。当前值缺失、零基数、负向修正、源口径变化、榜单短暂进出和历史不足分别处理。排名用上升/下降名次，不用百分比增长；指标不跨币种或地区直接合并。
- [ ] **O2.2 持续性与基线**：区分一次突变、连续变化和回落；使用真实观察时间，不用每天 finding 数代替市场需求。跨范围“同类对比”只在类别、地区、指标和窗口可比时显示，并给样本数；样本不足保留自身比较。
- [ ] **O2.3 线索选择与降噪**：首版三类入选理由为“持续关注增长”“出现可核实的定价变化”“新进入监控范围”；每条展示触发规则、基数和覆盖。阈值按指标定义、可配置并版本化，O0 样例校准。配置变更/图片 URL/描述编辑进入普通动态，不冒充商机。
- [ ] **O2.4 查询、排序与新变化**：默认按可解释的线索分组后按最近实质更新排序，可切增长/最近/价格条件。用稳定 keyset 游标及固定查询 as-of，避免边翻页边重算排序造成漏项。已研究产品的新实质证据标更新，和已读状态分离；规则未命中的产品仍可通过全部产品/搜索找到。

验收：每个数字可从引用观察重算，12 小时 +34 star 不显示成“7 天增长”；少一次采集不产生骤降；榜位 20→5 显示上升 15 位。7 天不足时显示具体可用区间。初始基线不批量冒充新品，缺少可靠信号时允许线索页为空。

本阶段不输出统一商机分数，不把 stars、排名、评价相加；证据完整度说明缺什么，不表示商业成功概率。

## 实施顺序与首批范围

1. 首批只做 O0.1–O0.4：数据样例、续传游标、成功采集基线和证据契约。交付接口/fixture与完整性测试后再推进。
