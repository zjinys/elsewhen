# 单流对话与主题沉淀 Roadmap

## 执行状态

- **状态：** 已完成（2026-09-21）
- **开始日期：** 2026-09-21
- **来源：** 从 [个人认知主循环 Roadmap](2026-09-17-personal-cognition-main-loop-roadmap.md) 暂时切入
- **完成后回切：** 回到原路线的 Phase 4C — 决策辅助第一版

原路线仍然有效，已完成的 Phase 0、1、2、3 数据层、2.5、4A、4B 不重复执行。这里的改造优先处理主对话入口、主题边界和上下文承载方式，为后续决策辅助提供稳定输入。

## 目标

把对话从“需要管理的会话对象”改成持续记录流：普通交流进入唯一主对话，明确的主题讨论进入 topic 页面；长期内容通过事件、实体、待办和知识页沉淀。

## 范围

- 对话 Tab 不再展示对话列表、新建、改名、归档或已归档视图。
- 左侧提供“最近使用”工作区，最多显示 10 个最近创建或编辑的主题/知识页面，不承担完整知识库浏览职责。
- 主对话按日期分章，支持日期定位、关键词定位和回到现在。
- 支持明确的 topic 标记语法；自动识别只作为辅助建议。
- topic 聊天不直接写入主事件流，确认后的结论、事实和待办才沉淀。
- 底层 conversations 表和旧消息继续保留，作为存储实现和历史回读来源。

## 执行步骤

### Step 1：主对话壳层

状态：已完成。Flutter 已移除主路径上的会话列表和会话管理入口；主对话使用数据库持久化的保留标题 `主对话流` 与 `diary` 标签自动绑定，旧普通会话会被一次性收敛到该标识。

- 增加主对话的稳定标识和获取/创建 API。
- Flutter 启动时自动绑定主对话；没有数据时自动初始化。
- 移除主路径上的对话列表、标题、归档和新建入口。
- 保留消息发送、AI 回复、失败重试和消息复制能力。

### Step 2：时间线定位

状态：已完成。主流消息按自然日显示日期分隔条并保留“显示更早的消息”分页窗口；支持日期选择定位、只搜索用户原话、清除定位和回到现在。

- 按天分组渲染主对话消息。
- 增加日期跳转、用户原话关键词搜索和命中后的上下文展开。
- 增加“回到现在”入口。

### Step 3：topic 明确进入机制

状态：已完成。主流输入识别 `#主题名`、`/topic 主题名` 和“进入主题：XXX”；已有 topic 会复用，不存在时创建 topic 页面并切换到知识库。topic 页复用现有知识页聊天，不直接写入主事件流，并提供“返回主对话”入口。

- 支持 `#主题名`、`/topic 主题名` 和自然语言“进入主题：XXX”。
- 查找已有 topic；不存在时创建 topic 页面。
- 主流提供进入 topic、返回主对话和暂不归类操作。
- topic 页内聊天沿用知识页聊天边界，不进入主事件流。

### Step 4：沉淀与状态区

状态：已完成。topic 工作台提供“沉淀讨论”入口，明确要求 AI 整理结论、决定和下一步，并通过 `save_wiki_revision` 确认门写回；主流“现在”状态区展示当天交流、未归档 topic、未完成待办和待分析任务数量。

## 完成验证

- Rust `cargo test --lib`：129 项通过。
- Flutter `flutter analyze`：无 error；仅保留既有 warning/info（未使用的旧会话管理辅助方法、弃用 API 和风格提示）。
- `git diff --check`：通过。
- topic 标记单元测试覆盖 `#主题`、`/topic`、自然语言入口和普通文本误触发排除。
- 既有 `save_wiki_revision` 工具测试覆盖确认门、缺失页面拒绝和不产生 ghost page。

- topic 讨论结束时提供确认式沉淀入口。
- 主流顶部增加轻量“现在”状态区：进行中的主题、今日到期待办、分析异常。
- 关联事实和优先级必须能够回溯到来源。

## 验收条件

- 用户打开对话 Tab 后只看到唯一主对话，不需要选择会话。
- 普通输入始终进入主流；topic 输入有明确、可见、可纠正的边界。
- 用户可以按日期或原话关键词找回过去内容。
- 主题讨论不会未经确认写入主事件流。
- 旧 conversations 和 messages 不被删除，已有知识页聊天继续可读。

## 风险

- 主对话无限增长，需要分页和按天加载。
- topic 标记语法必须足够低摩擦，并处理同名 topic。
- 自动建议不能越过用户确认门。
