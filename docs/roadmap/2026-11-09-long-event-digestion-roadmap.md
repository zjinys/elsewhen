## 目标与完成条件

单条事件原文超过实际 Provider 可用输入预算时，自动进入持久化分块阅读，跨有界后台 tick 完成全文覆盖、合并和知识消化。不得为了通过预算而丢弃尾部、改写事件、伪造来源或提前确认整个事件。

交付分成两个证据层：E1–E5 是工程交付；E6 包含真实模型质量验证。若实际模型/设备资源不可用，保留明确的验收缺口，不能用脚本化模型通过代替。Goal 只有完整范围已达成才能关闭。

## 范围与不变式

1. 事件内容和 ID 不变，中间节点不创建新事件，不进入个人业务同步。最终页面来源仍指向原事件。
2. 已实现的普通消化、完整请求预检、动态缩批次和 Provider failover 保留；只对完整单事件仍超窗的情况进入分块路径。固定指令自身超窗须单独识别，不无限切分空材料。
3. 原文块使用 Unicode 字符范围 `[start,end)` 与内容指纹。叶节点有序、无缺口、无重叠，覆盖范围从0到原文末尾；引用必须能在所记原文范围校验。最终显示必须区分生成摘要与原文引文。
4. 任务创建时固定消化及阅读指令、语言策略、依赖指纹。设置变化影响新任务，不能换掉进行中任务的 bundle。缓存不能跨事件/内容/策略/语言混用。
5. 分块、合并与最终请求都通过具体候选 Provider 的完整序列化预检，包括模板、包装、输出预留和安全余量；换渠道重新预检。已确认节点不得因为窗口变化被冒充为不同范围。
6. 每个后台 tick 最多推进一个模型节点；每节点至多尝试当前有限 Provider 链一次，不添加无限重试。既有单渠道超时继续有效；tick 不串行读完全文。材料、合并扇入、层级、单节点输出及持久缓存均有上限；超上限明确等待配置/失败原因。
7. 节点完成不是消化完成。只有全范围覆盖、根节点完整、最终提议验证通过，才能将页面写入、证据去重与任务确认一起提交。人工正文保护和显式审批纪律不变。
8. 租约/任务代数和 owner/processor 权限在领取与提交均校验，网络调用期间不持数据库写锁。超时、重启、撤销/重新分类和移交后的迟到结果不能覆盖有效节点或确认旧任务。
9. 中间阅读使用独立进度/重试语义，不能把一次正常分块推进计成一次整事件失败。普通事件应继续有机会被处理，长事件不能长期堵住队列。
10. 不新增手动后台触发按钮；只读进度沿用现有知识消化队列。应用显示中英文，原文/slug/协议保留。长事件分析 worker 是另一调用路径，本项不声称同时解决它。

## 实施结构

| 层 | 责任与边界 |
|---|---|
| 存储迁移与 task/node 数据 | 事件+固定bundle+策略身份，范围/节点树，租约代数，进度、结果、退避；不在通用 Store::open 重复扫描事件或执行模型调用 |
| 预算与选材 | 复用 `AiProvider::fits_request` / `generate_prepared`；动态确定叶范围与合并组，模型无法提供预算时保守拒绝而非无界发送 |
| 阅读执行 | 一次节点调用，严格结构化输出，范围与引文校验、完整结束校验、输出大小限制；持久结果可重用 |
| 合并与最终消化 | 合并依赖必须已完成且范围连续；根摘要携带明确生成标识和完整覆盖证据；最终来源映射为原事件 |
| 调度与展示 | 接入现有 worker，推进/等待/失败/完成分开，处理公平性与后台故障隔离，必要时更新 FRB 并重新生成 |

已有 `src/knowledge/reading.rs` 与 `src/ai/summary.rs` 可复用节点/覆盖设计；不直接借用来源快照 ID 或对话消息 ID 来伪装事件身份。表结构、状态枚举、资源 key 和限额在对应阶段实现记录中固定，迁移只追加。
