# Elsewhen AI 对话体验优化 Roadmap

## 目标与归属

借鉴 RikkaHub 等成熟聊天产品，把 Elsewhen 的 AI 对话从“发送后等待最终字符串”完善为**过程可见、可以停止、操作明确、长任务连贯、失败可恢复**的体验，同时保留事件与知识的来源、版本和审阅边界。

优化方向与取舍见 [AI 对话体验方案](../notes/proposed/architecture/2026-09-30-ai-chat-experience.md)。本文件是[个人认知主循环总路线图](2026-09-17-personal-cognition-main-loop-roadmap.md)下的对话能力子路线，服务 Phase 4C / Phase 5，不替换总路线，也不把既有 Wiki 实现重新计为本路线完成。

本路线依据用户体验收益、依赖关系和当前源码安排，不沿用早期比较文档里的 P0/P1 编号。具体接口、表结构及阈值在相应切片设计时确定；下面列出的状态和字段是实现必须表达的语义，不要求逐字采用命名。

## 不变式与范围

1. **本地输入先提交。** 沿用现有统一输入和事件事务入口；原始事件不可变。Provider 故障、取消和 UI 重连不重复创建用户消息、事件及分析任务。
2. **Rust 裁决业务状态。** Dart 不直接写数据库，不靠本地布尔值认定工具已执行；主对话和知识页对话使用同一生成与确认契约。
3. **取消不等于撤销。** 取消被接受后不开始新的模型请求或业务动作；已提交的操作有回执。不能保证服务商立即停止计算或计费。
4. **草稿不等于完成。** 流式正文、待确认提议、已执行动作和最终回复各有身份；不能把工具协议、私有推理或未核验的保存声明当成最终答案展示。
5. **保留最终预算闸门。** 完整序列化 payload、tool schemas 和输出预留必须计入；当前问题和必要证据不静默裁剪。整轮工具配对有显式验证。
6. **原文与摘要分离。** 摘要、运行检查点、检索缓存都是派生物，不覆盖原始消息，不升格为原始来源或永久规则。
7. **后台知识管线不变。** 不新增 digest/source maintenance 的手动触发或重试 UI；聊天 run 的停止/重试不能操作后台知识队列。
8. **诊断默认最小化。** 默认只记录 run/请求身份、模型配置版本、计数、时长、状态和错误类别。密钥、完整 prompt、工具参数和用户原文不进入常规日志；用户显式诊断另设脱敏、保留和清除策略。

## 第一阶段：看得见、停得下、操作明确

### C00a — 对话时间上下文（优先小切片）

**用户收益：** AI 理解“今天、昨天、刚才、明天”和重新打开会话后的时间变化，而不是猜日期。此项可先做，不要求先改 run、流式或摘要。

- [ ] 从应用时钟取得完整日期、星期、本地时间、UTC offset；可靠的时区标识可附带，不能把中文界面等同于东八区。使用可注入时钟/时区，使测试不依赖机器当天时间。
- [ ] 每轮用户请求构建一个当前时间合成块，置于稳定前缀之后的本轮动态上下文区；不修改用户输入正文，不存为聊天消息或事件，不挤掉当前问题。
- [ ] 保留消息发送时间作为历史语义锚点，区分当前时间、消息时间与事件发生时间；排队跨午夜才处理的“昨天”不能静默按处理时间重解。
- [ ] 历史首条用户消息、相邻用户输入间隔超过 10 分钟、跨本地日期或时区时添加简短时间提醒。短间隔不重复堆积历史提醒；10 分钟是初始内部节奏，暂不新增设置项。
- [ ] 同一轮请求重试复用已构建时间块；长工具任务跨日或超过提醒间隔时，在下一次模型请求前刷新/替换当前块而非追加。时钟回拨不生成负数间隔结论。
- [ ] 合成块计入现有预算，明确仅供时间定位，不作为来源证据、永久记忆或独立摘要事实；知道日期仍需查真实记录才能回答“昨天做了什么”。
- [ ] 主对话和知识页对话共享这一构建逻辑。时间提醒不授予模型定时任务、主动推送或后台执行权限。

**验收：** 固定时钟覆盖同日短间隔、超过 10 分钟、跨午夜但不足 10 分钟、隔天重开、时区/DST 变化、延迟处理旧消息、重试幂等、时钟回拨以及预算紧张。原始 messages/events 内容不变，历史相对日期不漂移；时间块不会随刷新页面重复叠加。真实端点用非个人测试材料验证“今天是哪天”“昨天的记录”“明天截止”的理解，不能只靠模型回答中的日期字符串认定来源检索正确。

**主要位置：** `src/ai/memory.rs` 的消息装配与合成上下文、`src/ai/conversation.rs` 的请求轮次、对应 Rust 测试。当前 `turn_start` 用于写入核验，不直接改变其语义；时间上下文另有明确采样点。原则上无需改公共 API 或 schema；如实施时需要变更，则遵守公共交付门禁。

### C00 — 基线、验收场景与共享契约

**用户收益：** 后续优化能回答“体验改善在哪里”，而不是只证明多了接口。

- [ ] 建立固定场景：普通问答、检索后回答、草拟待办/知识页/规则、长对话追问、长知识页、拒绝确认、流中失败、取消、重启。
- [ ] 记录基线：本地保存耗时、首次可见进展、首段正文、总耗时、请求次数与 token、错误类型；区分工具进度与正文首字时间。
- [ ] 明确 run 的输入消息身份、上下文截止点、Provider 配置版本和并发范围；避免生成期间新消息被旧 run 无意读取。
- [ ] 定义最小事件语义：run 身份与序号、阶段变化、正文增量、工具开始/结果、提议就绪、用量、最终快照、失败与取消。终态不可被晚到增量复活。
- [ ] 列出当前主对话、知识页、工具和确认路径的回归清单；复用既有 FollowUp、引用校验和输入幂等机制。

**验收：** 有可重复运行的离线场景和脱敏基线记录；接口契约覆盖两个对话入口。纯进度事件不伪装成模型正文，系统兜底也不伪装成模型原话。

**主要位置：** `src/ai/conversation.rs`、`src/ai/provider.rs`、`src/api/conversations.rs`、`ui/lib/providers/conversation_provider.dart`、`ui/lib/widgets/message_area.dart`、`ui/lib/widgets/wiki_ai_chat_panel.dart`。新增生成模块按职责拆分，避免继续把所有逻辑堆入大文件。

### C01 — 具体动作与版本确认

**用户收益：** 清楚知道自己批准了什么，不再由一句短回复执行积压动作。

- [ ] 确认请求绑定 conversation、action/proposal ID、提议内容版本和必要的目标修订；规则转正同样覆盖，不能只改 pending actions。
- [ ] 主对话和知识页显示具体草稿/动作卡，提供接受、编辑和拒绝；已有受保护页面审阅界面优先复用。
- [ ] 取消模糊短句自动批量放行。无法确定对应动作的“好”只引导用户选取，不直接写入；否定句不能命中肯定分支。
- [ ] 允许用户显式选择多个具体动作；逐项绑定版本、展示执行结果，说明是否支持原子整批，不能把部分成功说成全部成功。
- [ ] 编辑提议或目标变更后旧确认失效；历史草稿保留但须重新审阅，迁移不能把旧内容自动当成已经批准。
- [ ] 确认与执行具备幂等键和执行回执；连点、失败重试、页面重载均不重复写入。仍以业务规则校验依据和保护状态。

**验收：** 覆盖“好的，别保存”“可以不保存”、同会话多个 pending、旧轮提议、跨会话 ID、改稿后旧授权、重复点击和目标版本冲突。接受 A 不执行 B；接受草稿和执行副作用有明确区别。所有确认入口通过真实隔离 Bridge 验证。

**主要位置：** `src/ai/conversation.rs` 的两类 confirmation、`src/ai/tool/mod.rs`、`src/storage/records.rs`（含规则存取与转正）、`src/knowledge/authoring.rs`、`src/knowledge/review.rs`、相关 API 和 Flutter 审阅组件。

### C02 — 统一生成 run、事件和恢复底座

**用户收益：** 切页后状态不丢，失败后能知道做到了哪里。

- [ ] 为每次生成建立稳定 run ID，绑定输入消息和上下文版本；同会话串行，其他会话不共享取消信号。
- [ ] Rust 提供统一事件应用逻辑与 run 查询快照；兼容旧 `generate_reply` 期间也调用同一核心，不维护两套生成实现。
- [ ] 将运行状态、部分回复检查点、工具调用身份/结果及已执行回执持久化。增量合并写入，关键业务结果和终态及时提交。
- [ ] 定义 preparing/running/cancelling 与 completed/failed/cancelled/interrupted 等状态；待审提议独立持久化，第一版不要求网络请求一直等待用户。
- [ ] 以 run/generation 身份和序号拒绝晚到、重复或错会话事件；重订阅先取快照再衔接增量，终态有权威快照。
- [ ] 正常关闭有界 flush；异常启动把未完成 run 标记为 interrupted 并保留已落盘内容，不假定退出钩子一定执行。
- [ ] 本地业务提交与执行回执采用事务或稳定业务幂等机制闭合窗口；无法核实的执行结果标为待核实，不自动重做写工具。

**验收：** 在工具执行前后、回执提交前后和最终回复前注入故障。原始输入不重复，已提交业务结果可恢复；不确定状态不声称成功。检查点之外的尾部可能丢失，必须明确损失窗口，不承诺恢复模型隐藏状态或精确续接任意 token。

**主要位置：** `src/ai/conversation.rs`、`src/storage/conversations.rs`、`src/storage/records.rs`、迁移目录、`src/api/conversations.rs`。新增运行表/模块在实施时按当前最新 schema 追加，不预定或覆盖已有版本号。

### C03 — 端到端流式与取消

**用户收益：** 及时看到正文，用户主动结束时不再只能等超时。

- [ ] 在现有 OpenAI-compatible provider 路径实现增量解码；工具调用参数组装完成并校验前不执行，保留文本协议兼容和最终引用校验。
- [ ] FRB 暴露带 run ID 的事件订阅与停止接口；Rust 负责取消传播，不能仅在 Dart 隐藏进度条。
- [ ] 取消贯穿请求、工具轮边界、重试/退避和提交前检查；取消与成功竞争时由持久状态裁决，晚到结果不得创建新的业务动作或覆盖新 run。
- [ ] Flutter 主对话/知识页共用状态消费机制；按帧合并增量，避免每个 chunk 全文序列化、全列表刷新或写 SQLite。
- [ ] 慢消费者、重新订阅、重复事件和序号空洞可以回到权威快照；终态不可依赖恰好收到最后一个 delta。
- [ ] 同一次请求中的累计 usage 事件合并去重，不同请求的 usage 累加；中断后无 usage 标未知或估算，不冒充准确计费。
- [ ] 明确不支持流式的端点如何回退；不把超时、鉴权或预算错误都当协议不支持。Capture 保存继续独立于生成状态。

**验收：** 覆盖 UTF-8/协议边界跨 chunk、工具 JSON 分片、空回复、流中断、取消前后提交、切页重开、慢消费者和非流式端点。停止不影响其他会话或后台分析。可控假服务下记录取消本地响应与增量到屏幕的延迟，并按 C00 基线确定门槛；不以外部模型时延作为 UI 性能保证。

**主要位置：** `src/ai/provider.rs`、生成核心、`src/api/conversations.rs`、`ui/lib/bridge/rust_bridge_repository.dart`、conversation provider 和两个聊天视图。公开 Rust API 改动后从仓库根运行 `scripts/regen.sh`，同步 bindings 与动态库。

### C04 — 工具进度、审阅与诚实收尾

**用户收益：** 知道 AI 在查什么、准备做什么、实际完成什么。

- [ ] 工具阶段由真实开始/完成事件驱动；可展开用户可理解的结果和证据，不展示私有推理或原始内部协议。
- [ ] 将“草稿已生成”“等待用户审阅”“操作已执行”“执行失败”分别显示；写入成功只来自业务回执。
- [ ] 对跨 chunk 的工具协议标记做边界缓冲/过滤；流式草稿与最终校验结果区分，未经核验的引用不挂成有效来源。
- [ ] 适配现有保存声明核验、空回复兜底和 FollowUp，不能因开启流式而绕过它们；需要缓冲的内容明确缓冲，不为首字速度牺牲诚实性。
- [ ] 失败展示已完成步骤和未完成步骤，重试仅重跑所选生成，不重写用户输入或盲目重复已成功工具。

**验收：** 一条“检索 → 草拟知识页 → 审阅 → 执行 → 结果确认”的流程在两个聊天入口均可完成。用户拒绝不会落业务数据；工具失败不会显示“已保存”；中止后部分正文与实际业务结果不矛盾。

**第一阶段出口：** C00a 与 C01–C04 全部完成；通过下方公共门禁，并用测试材料执行真实端点人工验收。不仅演示无工具的打字机效果。

## 第二阶段：聊得久、读得全、接得上

### C05 — 上下文选材与完整预算协调

- [ ] 为上下文段定义用途、来源、版本、是否可省略和预算归属：稳定设定、个人规则、历史、摘要、跨会话背景、当前页、选材证据和工具结果。
- [ ] 前置选材尽量使用 provider-aware 计量，并为工具定义、当前交换和输出留预算；最终 serialized payload gate 始终保留。
- [ ] 明确降级顺序：可选背景 → 可重建历史/摘要选材 → 缩小附带材料任务范围；不得悄悄截断当前问题或验证所必需的证据。
- [ ] 原生工具历史按 call ID 验证配对；整轮裁剪、恢复和摘要边界都保留合法交换，不机械移植其他消息模型的数组规则。
- [ ] 记录各段计数与降级原因等元信息，区分本地预算拒绝和上游超窗口；显式上下文窗口拒绝的有限重试沿用现有约束。

**验收：** 长问题、工具 schema 膨胀、多轮工具结果、可选背景过大、未知 tokenizer、仅剩必要证据仍超限均有确定结果。当前输入与必要证据不被静默损坏，最终预算没有被摘要路径绕过。

**主要位置：** `src/ai/memory.rs`、`src/ai/budget.rs`、`src/ai/provider.rs`、`src/ai/conversation.rs`、`src/knowledge.rs`。

### C06 — 非破坏性摘要与连续性

- [ ] 摘要独立存储，绑定明确消息范围/路径、输入版本、模型和策略版本；旧消息不删除，UI 分割线不充当技术切点。
- [ ] 摘要包含目标、约束、已确认事实、关键决定和未完成事项；明确标注生成性质，不自动建立永久记忆或规则。
- [ ] 以 token 预算触发并保留必要余量，避免每轮重复压缩；覆盖少量超长消息、长工具结果和没有可压缩历史等情况。
- [ ] 复用 FollowUp 处理短追问，避免把独立新问题误续接旧任务；依赖精确信息时按范围回读原文。
- [ ] 摘要生成可取消；提交前校验基底是否变化。失败沿用仍有效的旧摘要或明确省略，过期基底不静默生效。
- [ ] 只缓存明确允许陈旧的稳定段；规则、源版本和本轮执行结果有失效契约。前缀缓存不承担完整逐轮审计。

**验收：** 固定长对话中晚轮仍能回忆关键约束、解释任务进度；摘要取消/失败/编辑冲突不改原历史；原始引用可回到原文。记录摘要请求自身成本、额外延迟和实际缓存效果，不预设节省比例。

**主要位置：** `src/ai/memory.rs`、`src/ai/conversation/continuity.rs`、生成与存储模块。新增摘要基底需要迁移和旧会话兼容测试；当前已有分支数据不能被默默拼成同一条摘要路径。

### C07 — 知识页对话的任务相关选材

- [ ] 区分局部问答、全文总结、跨来源对照、局部编辑和全页修订，优先从明确用户操作及当前任务确定范围；不确定时说明范围或澄清。
- [ ] 局部问题注入相关原文与版本；全文任务复用现有完整阅读/分块缓存，缺失覆盖不能冒充已读全文。
- [ ] 页面编辑绑定显示时的修订与选区；全页任务分块处理后验证完整性，不使用简单正文截断规避超限。
- [ ] 沿用 `knowledge/authoring`、`review` 和依赖有效性规则，生成期间来源或人工内容变化后重新核验，不静默迁移到新版本。
- [ ] 同一任务的后续问题保留材料身份和工作进度；切到其他任务时不把旧页默认当有效证据。

**验收：** 短局部问题不携带不必要全文；长文摘要覆盖尾部；局部编辑不改其他段；源内容中途更新阻止旧稿覆盖；最终引用仍可验证。真实模型评分包括全文覆盖和指令遵从，不以预算通过代替质量合格。

**主要位置：** `src/ai/conversation.rs`、`src/knowledge.rs`、`src/knowledge/reading.rs`、`src/knowledge/authoring.rs`、`src/knowledge/review.rs`、`ui/lib/widgets/wiki_ai_chat_panel.dart`。实施前复核现有阅读模块的公开复用边界，避免建立第二套来源缓存。

**第二阶段出口：** C05–C07 完成且与第一阶段集成。长对话、长材料、短追问、取消摘要与版本冲突都能解释结果，原始输入和来源不受损。

## 第三阶段：自然追加与可靠恢复

### C08 — 生成期间输入与持久待生成队列

- [ ] 解耦“本地保存用户输入”和“触发模型回复”；生成中提交仍经现有幂等入口保存，旧 run 使用自己的输入截止点。
- [ ] 明确展示仅记录、排队下一问和停止的行为。队列绑定已保存消息，不复制第二套消息正文；队列状态持久化而不只存在 UI 内存中。
- [ ] 同会话 FIFO，支持撤回待生成资格；撤回不删除不可变事件，不把尚未送达模型的消息说成已被模型采纳。
- [ ] 用户停止后冻结自动派发，明确继续才恢复；会话删除清理队列并阻止晚到结果复活会话。
- [ ] 重启后显示待生成和中断项，不自动重新执行不确定的业务动作；恢复使用稳定 run/输入/动作身份。

**验收：** 当前生成中连续提交多条消息，保存不等待网络；每条待生成项最多启动一次；停止不会立即点火下一条；撤回和重启不重复事件、消息、分析任务或写工具。

### C09 — 在安全轮边界补充当前任务

- [ ] 在 C08 稳定后新增明确的“补充当前任务”操作，不把所有新消息自动当 steering。
- [ ] 只在本轮工具结束、下一次模型请求之前消费可注入内容；校验队列项仍有效、run 未终止、预算可容纳。
- [ ] 注入记录与队列消费共同持久化，重启后可判断已消费/未消费；未注入时保留普通排队资格。
- [ ] 有未支持的附件或上下文无法安全合并时保留队列，不只取文本丢掉附件；用户取消时不得自动转成另一次未授权执行。
- [ ] 补充要求仍不授予业务写权限，已审阅提议发生改变后必须重新确认。

**验收：** “正在整理材料 → 补充只保留项目相关部分”能在下一轮模型请求生效；注入前撤回、注入时崩溃、停止竞争、预算不足和附件输入都有确定回退，要求不会既注入当前轮又重复生成下一轮。

**第三阶段出口：** C08–C09 完成。用户可自然追加、撤回和继续；系统能解释每条输入是否已保存、排队、注入或处理完毕。

## 公共交付门禁

### 自动化与构建

每个步骤按改动范围执行并记录结果；阶段出口至少执行：

```bash
# 仓库根目录
cargo test --all-targets
cargo build --release
# 公开 Rust API 变更时必做，先于真实 Bridge 验证
./scripts/regen.sh

# ui/ 目录，始终使用 FVM
fvm flutter analyze
fvm flutter test
```

- 真实 Flutter Bridge 测试只经 `ui/test/support/isolated_bridge.dart` 初始化，Rust 使用临时数据库；自动测试不得访问个人数据库。
- 迁移验证旧数据量、消息、原始事件、来源和修订完整性；不能通过删库重建让测试过关。
- 新增 schema、模型请求或公共 API 后同步相关 Note、API 文档和完成证据；生成绑定不手工修改。
- 保留既有空回复、文本/原生工具兼容、保存声明、引用和预算回归。失败或未跑项原样记录，不以局部通过代替完整门禁。

### 固定验收场景

| 场景 | 最低通过条件 | 首次要求 |
|---|---|---|
| 时间感知与跨日 | 当前时钟可信、历史时间不漂移、提醒幂等，时间不是来源证据 | C00a |
| 普通回复与长正文 | 增量可见，最终正文一致，长输出不造成无界 UI/桥接积压 | C03 |
| 工具调用与审阅 | 进度来自真实事件，用户只批准展示的动作版本 | C01、C04 |
| 否定与重复确认 | 否定不写入，重复确认不重复执行，旧授权不生效 | C01 |
| 停止与切页 | 停止不只是隐藏 UI；切页后恢复正确 run，其他任务不受误取消 | C02–C04 |
| 进程异常 | 检查点、终态和副作用可解释，不盲重放已完成写入 | C02 |
| 长对话与短追问 | 保留目标/约束/未完成事项，必要时回读原始历史 | C06 |
| 长材料与来源变化 | 不伪装全文覆盖，过期草稿不覆盖新版本 | C07 |
| 排队与补充 | 保存不等 AI，停止冻结派发，一条输入最多消费一次 | C08–C09 |

真实模型验收使用用户允许发送的测试材料及已配置端点，记录模型/配置、场景输入版本、预期、实际表现、耗时和用量；不自动上传个人记录。固定任务评价指令遵从、事实连续性、来源准确性和全文覆盖，记录失败样例。mock、Rust、Bridge 通过仅证明工程行为，不等于真实模型质量验收。

### 性能与可观测性

C00 建基线，之后各阶段记录前后对比：本地提交延迟、首次真实进展、首段正文、总耗时、取消本地响应、UI 更新/桥接量、检查点写入量、上下文分项 token、摘要成本和 provider 实际缓存用量。先在可控服务上验证本地开销，再看真实端点表现；没有返回的 usage/cache 指标标未知，不补造为零或收益。

## 暂不进入本路线的内容

- 整体迁移 Bun/React/SSE 或 Web SharedWorker 多标签连接管理。
- 为追求通用聊天客户端功能而扩展多助手、完整分支编辑 UI、多个原生模型协议或超大工具循环上限。
- 重建已有实体事实、个人规则、知识依赖和来源阅读管线。
- 为了缓存命中冻结全部检索结果，或删除最终预算校验。
- 仅凭代码观察宣称模型质量、缓存节省或大规模性能已经验收。
