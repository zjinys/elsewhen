## 已知边界（预期行为，不是缺陷）

测试中遇到以下现象**直接记通过**，不要当 bug 报；表现不同才是问题：

1. **配图增量间隙**：A 刚导入的推文配图要等**下一份快照**才到 B（增量 op 不携带字节）。期间 B 打开该页看到占位符原文（可见死文本）。
2. **无 DB 自愈**：B 删掉本地图片文件后显示占位符原文；重拍快照后恢复。不会伪装成加载失败的白图。
3. **Provider Key 需手动吊销**：撤销成员后，对方本地留存的 API Key 无法远程抹除，须到 Provider 控制台吊销/轮换（M5 有专项）。
4. **旧端显式拒绝**：v2 时代旧版 App 收 v3 快照报 `sync_snapshot_version_unsupported` 类可读拒绝，不是崩溃或静默错乱。

## M0 环境与构建准备

- [ ] 两台真实设备（A=owner，B=加入者），均为 **release** 构建：`cd ui && flutter build apk --release`。
- [ ] 测试用 Provider Key 为一次性低额度密钥（记下到期时间，测完吊销）。
- [ ] 记录：两台设备型号/平台、App 版本、release commit hash（当前 `52e54f7`）。
- [ ] A 设备先安装并正常使用一天以上（攒出事件/对话/wiki 页，含至少一条**带图推文导入页**）。
- [ ] 找回 wiki 日志入口（设置→知识库日志）：M4 要看「图片引用回填」条目。

## M1 配对与增量同步

- [ ] **扫码通道**：A 出邀请码（二维码显示正常、刷新过期正常）→ B 扫码加入 → 走完 preview/指纹核对/批准。
- [ ] **粘贴通道**（先撤销 B 再重来）：A 复制邀请码文本 → B 粘贴 → 同上完成配对。
- [ ] 配对后 A 审批，B 名册与 A 一致（成员数、owner、加工端指针）。
- [ ] 增量双向：A 记一条笔记 → B ≤1 分钟内可见；B 记 → A 可见。
- [ ] 双端断网重连后自动追平（B 飞行模式 2 分钟，A 期间记 3 条）。

## M2 Provider 开箱与加工移交

- [ ] B 配对完成后无需填 Key 即可发起对话（Provider 配置随快照带过来）。
- [ ] A 让出加工权给 B：A 后台任务立即停止、B「待接管」→ 追平 → B 开始加工。
- [ ] B 让出回 A：反向同验。
- [ ] A 有进行中后台任务时让出被拦，文案可读非报错堆栈。

## M3 可变对象与冲突

- [ ] wiki/待办/规则/目标四类：两端分别增改，最终状态一致，无静默覆盖。
- [ ] 同一页双端同时改动 → 冲突审阅界面出现，采纳任一方后双端一致。
- [ ] 删除留 tombstone：一端删除的清单项在另一端消失且复活后不重复。

## M4 快照断档恢复、配图与回填（本轮新功能专项）

- [ ] **回填**：A 升级新版本后首启，wiki 日志出现「图片引用回填/N 页归一化」；旧带图页的正文不再含本机绝对路径（检查页详情正常显示图）。
- [ ] **配图跨机**：A 导入一条新带图推文 → 等一次快照 → B 打开该页图片正常显示；B 设备上通过文件管理器确认 `…/elsewhen/tweet_images/<tweet_id>/img_1.*` 已落盘。
- [ ] **恢复带图**：B 卸载重装（或第三台新设备）走快照恢复 → 配图直接出现，无需 A 重做任何操作。
- [ ] **幂等**：B 收到后 A 无改动重拍快照，B 端无重复文件/重复台账。
- [ ] **退化形态**：B 手动删掉某张图文件 → 页面显示占位符原文（预期行为 2）→ 重拍快照后图恢复。

## M5 撤销、长离线与重快照

- [ ] A 撤销 B → B 推送/拉取均失败且文案可读；A 名册标记已撤销；重新配对需新邀请码。
- [ ] 撤销后到 Provider 控制台吊销测试 Key，确认 B 的旧 Key 已失效（预期行为 3）。
- [ ] B 离线 30 分钟+，期间 A 推进 GC/重快照 → B 回连后收敛（对比 wiki 页数、待办条数全等）。
- [ ] B 离线期间 A 导入带图推文 → B 回连收到的快照里含图（覆盖增量间隙由快照补齐，预期行为 1）。
