# 对话自动沉淀记忆路线图（2026-11-23）

## 目标

把对话中的稳定用户信息自动整理成可读、可修改、可召回的独立记忆。设置 / 记忆页面展示的正文就是实际召回正文。`profile/me` 继续作为个人档案知识页，不再作为所有记忆的唯一容器。

## 当前真实状态

- `personal_memory_claims` 已有独立 `content` 字段。
- `94-personal-memory-content` 增加该字段；`95-backfill-memory-content` 将能匹配知识页的旧正文回填进去。
- 管理列表和详情优先读取 `content`，旧记录仍可回退到 `page_slug` 对应知识页。
- 普通搜索/召回、有效性、自审及维护统计优先使用独立正文；缺少正文的旧记录才走知识页兼容路径。
- `propose_memory` 在提供正文和用户消息依据时写入独立记忆；旧知识页入口保持兼容。
- 新增用户消息经规则及模型后台提取，候选默认 pending；确认后才进入默认召回。
- 语义关系分析支持有界去重、补充及冲突判断，保护人工决定和确认正文。专项验收完成；全量回归的剩余基线失败见验收报告。

## 目标模型

```text
messages/events（原始对话）
        ↓
候选记忆（保守提取、待处理）
        ↓
personal_memory_claims.content（规范化实际记忆）
        ↓
设置页展示 / 对话召回
        ↓
profile/me（可选的个人档案汇总）
```

知识页只承担 `profile/me` 和旧数据兼容，不是新记忆的必经存储。

## P0：修正独立正文闭环

- [x] `search_memories` 优先从 `claim.content` 生成 excerpt、匹配文本和召回正文。
- [x] `memory_validity` 对独立正文使用 `content` 的 hash；旧记录才检查知识页 hash。
- [x] `memory_claim`、详情、来源校验区分 direct-content claim 与 legacy page claim。
- [x] 为 `content`、旧知识页回退和正文修改增加 Rust 定向测试。
- [x] 检查同步、导出和恢复策略：personal_memory 系列表显式归类为本机数据，业务同步快照不携带正文、人工决定、权限或游标；不宣称跨设备记忆同步。

**验收：** 修改独立记忆正文后，搜索和上下文召回立即使用新正文；知识页变化不会改变已有独立记忆。

## P1：从对话自动提取候选

- [x] 新增后台任务 `run_automatic_memory_extraction`，接入现有 background tick 和 `knowledge_background_runs` 账本。
- [x] 按消息游标或输入 hash 增量读取用户消息，避免重复处理历史。
- [x] 先做保守规则闸：只处理用户明确陈述，过滤问句、寒暄、临时状态、助手推断、过长文本；每轮限制数量和长度。
- [x] 模型提取仅输出候选正文、类型、主题和来源消息 ID，不直接赋予全局事实权限。
- [x] 候选没有合法用户消息依据时不落库。

**验收：** 一轮对话结束后，后台最多生成少量稳定候选；重复运行不会重复写入。

## P2：去重、合并与冲突

- [x] 完全相同正文幂等跳过。
- [x] 同主题近似正文更新已有候选或生成新版本。
- [x] 相互矛盾的内容进入 `conflicted`/`pending`，不静默覆盖。
- [x] 用户 `dismissed`、`deleted`、`excluded` 的内容进入自动提取抑制检查。
- [x] 旧版本标记 `superseded`，新正文成为唯一默认召回版本（新候选仍需确认才可默认召回）。

**验收：** 自动沉淀不会原样复活用户明确删除或否定的记忆。

## P3：设置 / 记忆用户控制

- [x] 列表展示独立 `content`，不向用户暴露 claim、hash 和知识页内部细节。
- [x] 详情提供正文编辑、停用和删除。
- [x] 编辑保存新版本并更新正文 hash/version，后续召回只使用新版本。
- [x] `profile/me` 继续显示为“关于我”，与普通记忆分开。
- [x] 旧知识页型记忆在用户查看或后台迁移时完成 content 回填。

**验收：** 用户修改设置页中的文字后，该文字就是下一次对话可召回的记忆。

## 暂不引入

- 不把所有记忆拼进 `profile/me`。
- 不先引入图扩散、赫布边或复杂遗忘曲线。
- 不把助手自己的陈述当作用户事实。
- 不让自动提取绕过现有用户控制和抑制状态。

## 参考实现可借鉴点

`ref/agent-memory` 的保守抽取、事件/片段/画像分层、正文即记忆、去重巩固和显式忘记机制可作为实现参考；其 JSONL 存储和图动力学不直接移植，Elsewhen 继续使用 SQLite、claim 状态和版本控制。

## 最终验收（2026-11-24）

本路线图实现与专项验收完成。详见 [验收报告](../testing/2026-11-24-conversation-memory-acceptance.md)。

- Rust 记忆模块：73 项通过，包含模型提取→关系分析→事务提交、双方依据保留与旧候选替代的完整流程。
- 提取规则与语义关系模块：10 项通过。
- 迁移套件：37 项通过；本机记忆快照策略专项通过。
- Flutter 页面、真实桥接、设置入口：14 项通过；定向 analyze 无问题。
- 全量 Rust 回归执行完毕：1389 passed / 9 failed / 28 ignored。两项迁移失败已修复并复测；四项 HTTP 失败分别独立复跑通过。另有固定契约、wiki_tags 分类和旧知识画像预期三项基线失败，详见报告，不宣称仓库全绿。

边界：新候选默认 pending，确认/编辑后才默认召回；模型合并只替代有效未确认候选，保护人工决定与已确认正文，依据最多 8 条；记忆目前属于本机数据，没有新增跨设备同步。设置页覆盖各类会话的记忆，但管理可见不授予跨会话召回权限。
