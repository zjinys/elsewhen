# S06 真人双设备门禁清单（发版前人工执行）

> 本清单无法由 AI 代做：需要两台真实设备、真实网络环境与真人操作判断。
> 每项通过后勾选并记录日期/设备型号；任何一项失败即阻塞发布。

## 准备

- [ ] 两台干净设备（A=owner，B=加入者），均为发版构建（非 debug）。
- [ ] 测试用 Provider Key 为一次性低额度密钥，用后吊销。
- [ ] 记录两台设备 ID、平台、App 版本。

## 1. 配对与名册

- [ ] A 创建数据集并出邀请码，B 扫码/输入加入；B 显示 `pending_takeover`/等待状态符合预期。
- [ ] A 审批后 B 名册视图与 A 一致（成员数、owner、加工端指针）。
- [ ] 双向同步：A 修改一条笔记 → B 可见；B 修改 → A 可见。

## 2. 加工移交全链路（两方向）

- [ ] A 让出加工权给 B：A 立即停止后台任务（观察通知/任务日志），
      B 显示"待接管"直到追平 frontier，确认后 B 开始加工。
- [ ] B 让出回 A：同上反向验证。
- [ ] 在 A 尚有进行中后台任务时尝试让出，确认被拦并有可读文案。

## 3. 撤销与丢失设备

- [ ] A 撤销 B：B 随即无法再同步（推送拉取均失败且文案可读）。
- [ ] 撤销后 A 名册中 B 标记为已撤销；A 重新配对 B 需新的邀请码。
- [ ] **Provider Key 边界**：确认撤销后 B 本地仍留有的 API Key——
      到 Provider 控制台吊销/轮换，B 上旧 Key 失效。
- [ ] 模拟 B 丢失（直接离线）>7 天后回连，确认被名册态正确处理、
      无沉默数据分叉。

## 4. 长离线与升级

- [ ] 旧版本 App（当前发布版）与新版混跑：未知名册/快照版本字段不崩溃，
      旧端行为可预期（容差/拒绝均有可读文案）。
- [ ] B 离线期间 A 推进多轮 GC/重快照，B 回连后收敛一致（对比笔记集全等）。

## 5. 验证签名与风险确认

- [ ] 恢复 vault（改密码/换机导入）后设备仍可签名，私钥未要求重复输入明文。
- [ ] 名册/移交签字验证：手动篡改一笔名册 JSON 后导入被拒。
- [ ] 勾选本清单者签名确认，记录发版 commit hash。
