# Elsewhen AI 对话体验 —— 真人 GUI 人工验收 Roadmap

## 目标与归属

AI 对话体验路线（C00–C09）的**工程实现、隔离 Bridge、真实端点合成场景**已全部完成（2026-10-03），但「真人 GUI 连接真实端点的手工点按签收」无法由脚本、mock 或自动化 UI 测试替代。本文把这项人工验收单独列出，作为 [AI 对话体验优化 Roadmap](2026-09-30-ai-chat-experience-roadmap.md) 第一阶段出口的**人工签收载体**。

本文只做人工验收，不新增工程任务；不把「工程完成」与「人工签收」混为一谈。

## 为什么单独成文

- 工程侧（Rust/Flutter/Bridge/合成模型）已无未完成项，继续挂在主路线会持续阻塞第一阶段出口的勾选。
- 人工验收需要**真人实际操作**，步骤、预期、记录项应当可照做、可复核，而不是一句「补真人签收」。
- 后续跨平台人工体验（macOS/Windows/移动端）与长期模型质量另行安排，不在本文范围。

## 验收前提

1. 应用以桌面端运行（本次基线 Linux），设置页已配置真实 OpenAI-compatible Provider。
2. 只使用**允许发送的测试材料**（合成/非个人隐私），不上传个人事件、知识页或个人配置。
3. 每个场景记录：模型/配置、场景输入、预期、实际表现、耗时、请求数、通过/失败。
4. 不把脚本调用生产核心、mock/Bridge/合成模型测试当作人工验收证据。

## 必做范围：第一阶段出口（C00a + C01–C04）

6 个场景覆盖主对话与知识页两个入口；标注「双入口」的场景需在两个入口各做一次。

### S1 时间感知与跨日（C00a）

- **目的**：AI 理解「今天 / 昨天 / 明天」，重开会话后时间不漂移；知道日期不等于知道事实。
- **前置**：库里已有昨天的 events，且有一条 `dueAt` 为明天的待办。
- **步骤**：
  1. 主对话问「今天是几号、星期几？」
  2. 问「我昨天记录了什么？」
  3. 问「我明天有什么截止的事？」
- **预期**：日期/星期回答正确；「昨天记录」真实调用了按日期检索工具（工具步骤可见 `按日期查询事件`）而非编造；截止日期理解正确。
- **记录**：日期正确性、检索是否真实发生、是否有编造。

### S2 普通回复与流式正文（C03）

- **目的**：正文增量可见、最终一致，长输出不造成 UI/桥接积压。
- **步骤**：
  1. 主对话发一个会触发较长回复的问题（例如要求列出多步骤清单或长说明）。
  2. 观察正文是否逐步出现。
  3. 等待完成后核对正文完整性。
- **预期**：正文不是一次性蹦出，而是增量可见；最终正文完整、无截断、无重复；期间 UI 不卡顿、输入框仍可操作。
- **记录**：首字可见时间、是否流式、最终完整性。

### S3 工具调用与草稿审阅（C01、C04，双入口）

- **目的**：工具进度真实可见；草稿必须审阅后才执行；写入成功来自业务回执。
- **步骤**：
  1. 主对话输入「帮我记一个待办：周五前给张三打电话」（触发草拟待办）。
  2. 观察工具步骤出现「草拟待办」；出现草稿/审阅卡。
  3. 核对草稿卡内容（待办标题/内容正确）。
  4. 点「接受」。
  5. 知识页对话重复一次（如「基于本页草拟一个待办」）。
- **预期**：能看到工具步骤真实发生；草稿卡展示具体内容而非空承诺；接受后出现「已执行」回执，待办真实入库（去待办列表确认）。
- **记录**：工具步骤、草稿内容、接受后是否真实入库。

### S4 否定与重复确认（C01）

- **目的**：否定不写入；重复确认不重复执行；旧版本授权不生效。
- **步骤**：
  1. 触发一个草稿（如「记个待办：周末洗车」）。
  2. 草稿卡出现后，回复「好的，别保存」（否定句）。
  3. 确认待办未入库。
  4. 再触发一个草稿，连点「接受」两次。
- **预期**：否定后不写入（待办列表无此项）；连点接受不重复创建（只有一条）；否定句不命中肯定分支。
- **记录**：否定结果、重复点击后的待办条数。

### S5 停止与切页恢复（C02–C04）

- **目的**：停止真实生效（不是只藏 UI）；切页后 run 状态恢复正确；其他会话不受误取消。
- **步骤**：
  1. 触发一个较长的生成（或含工具循环）。
  2. 生成中点「停止生成」。
  3. 观察正文/工具是否停止，状态是否变为「已停止生成」。
  4. 切到另一个会话，再切回。
  5. 观察 run 状态恢复是否正确。
- **预期**：停止后不再出正文/工具；切回后状态正确（已停止），不重新生成；其他会话不受影响。
- **记录**：停止是否及时、切页恢复、其他会话状态。

### S6 进程异常恢复（C02，建议但不阻塞出口）

- **目的**：异常退出后已落盘内容保留，未完成 run 标记中断，不盲重放。
- **步骤**：
  1. 生成中直接杀进程（kill / 关窗口）。
  2. 重启应用。
  3. 观察未完成 run 与已保存输入/消息。
- **预期**：已落盘的用户输入、消息不丢；未完成 run 显示中断状态，不自动重做已完成写入。
- **记录**：数据保留情况、中断状态、是否自动重放。
