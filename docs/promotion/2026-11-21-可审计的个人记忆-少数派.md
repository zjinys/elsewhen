# 你的 AI 笔记正在悄悄篡改你的记忆

> 目标渠道：少数派 / V2EX / 即刻（长文深度向）
> 切入点：A+B 合并主轴——「可审计的个人记忆」（事实不可变 + 证据链 + 人审契约）

## 正文

去年我把三年的笔记喂给了一个 AI 助手，让它帮我整理"我这半年在折腾什么"。

它答得头头是道。直到我发现其中两条"事实"是错的——一条是它自己编的，另一条是我半年前随手写的一句话，后来被我修改过三次，AI 用的是最后一个版本，而那个版本已经和当初的事实完全不一样了。

那一刻我意识到一个问题：**我们一直在讨论"AI 能不能记住你"，却很少有人讨论"AI 记住的东西可不可以被信任"。**

### 所有 AI 笔记应用都有一个共同的架构缺陷

不是说产品做得不好，而是几乎所有的个人知识库产品——云端的、本地的、开源的——底层都是同一套模型：

**一份可以随便改的笔记，加上一个直接读这份笔记的 AI。**

这个架构下，无论你把数据存在本地还是云端、加密还是不加密，都改变不了三件事：

1. **你的历史是可篡改的。** 笔记可以编辑、可以覆盖、可以删除，昨天的"事实"今天就能变成另一个样子。你的 AI 记忆的根基是一份随时在变的文档。
2. **AI 的产出和你的输入混在一个池子里。** AI 总结的、AI 猜的、你自己写的，最后都是同一篇笔记。半年后你自己都分不清哪句是你想的、哪句是 AI 替你想的。
3. **AI 犯的错没有账可查。** 它上次基于什么得出了那个结论？引用了你哪条记录的哪个版本？没有答案，因为系统根本没打算回答这个问题。

### 我想要的是一套不同的东西

所以我自己做了一个个人事件系统，叫 Elsewhen。它的核心不是"AI 帮你记笔记"，而是三条结构性的规矩。这三条规矩不是功能，是架构——改不掉的那种。

**第一条：原始记录不可变。**

你随手记下的每一条——一句话、一个想法、一件发生的事——是一个**事件**。事件一旦落库，数据库层面的触发器会直接拒绝任何对原文、时间戳、来源的修改。不是 UI 上不给你改，是 SQLite 里写了个 trigger，任何 UPDATE 尝试直接 abort。

事实只能追加，不能改写。你后来改变了想法？很好，那是**新的一条**，它和旧的那条放在一起，本身就是信息。

**第二条：AI 的一切产出都带证据链，并且和你的输入分开存放。**

AI 分析你的事件后产出的知识页，每一段都绑定它引用的证据——精确到"引自哪条记录的哪个版本"。原始事件在一个区，AI 的整理在另一个区，永远不混。

AI 基于三个月前的版本得出的结论，在你修改源记录后会**失效并要求重新审阅**，而不是悄悄地继续用旧理解糊弄你。部分采纳 AI 的修改建议时，系统不会偷偷把你的源版本迁移走。

**第三条：AI 提案，人确认。确认不等于执行。**

AI 在聊天里说"好的，我已经帮你把这条规则记下了"——在 Elsewhen 里这句话没有任何效力。真正生效要经过一条完整的契约：AI 的提议被持久化成一个 claim，等你审阅；你确认后才有执行租约，做完要有回执；做晚了会被"围栏"拦下来标记为不确定，而不是默默当成成功。

这是刻意做成这样的。LLM 会犯错、会幻觉、会过度自信，这不是缺陷是属性。所以系统设计的前提就是：**AI 可以提议一切，但决定权留在你手里，且每一步都有据可查。**

### "记忆"这个词，配得上它的系统不多

市面上大量产品在讲"AI second brain"、"给 LLM 持久记忆"。但记忆的本质除了存储，还有**可信**：你知道哪句是事实、哪句是推断，知道结论从哪来，知道历史没有被改过。

Elsewhen 现在做到了这些：随手记录（移动端和桌面端）、异步 AI 分析（自带 API key，模型随便换，失败不丢数据）、自动整理成带证据链的知识库、多端同步（同步我们下篇单独讲——那个更有意思）。

数据在本地 SQLite 里，AI 配置你自己定，没有账号体系。

如果你也被"AI 一本正经地引用一段不存在的历史"刺过，欢迎来聊聊。我后续会把这套"可审计的个人记忆"的设计细节拆开来写：不可变事件流的存储设计、AI 知识页的证据绑定机制、以及那个人审契约是怎么一步步长出来的。

---

*Elsewhen 是一个本地优先的个人事件系统：原始记录不可变，AI 分析带证据链，产出需人审。Rust 核心 + Flutter 界面，支持 Windows / macOS / Linux / Android。*
