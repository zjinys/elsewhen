# FR-PES-002: 个人记忆系统

**版本**: v0.1  
**最后更新**: 2026-09-12  
**变更类型**: FEATURE  
**状态**: Draft  
**关联**: [FR-PES-001](./FR-PES-001-个人事件记录与状态管理.md)

## 1. 产品目标

记忆系统在 Raw Event 和 AI Analysis 之上维护可检索、可修正、可追溯的长期信息，帮助 Elsewhen 理解用户的稳定事实、偏好和习惯。记忆不是原始事件的替代品，也不能反向修改 Raw Event。

核心原则：

- 原始事件永久保留，记忆属于可重建的 derived data。
- 每条记忆必须能追溯到一个或多个来源事件。
- AI 只能提出记忆候选，Core 负责校验、去重、冲突和状态变更。
- 不确定的信息宁可不记，也不能把猜测写成事实。
- 用户可以查看、纠正、删除和禁止某条记忆。

## 2. MVP 范围

- 单用户、本地 SQLite 存储。
- 支持 `semantic`（稳定事实）和 `procedural`（偏好/习惯）两类长期记忆。
- 使用 SQLite FTS5 做关键词检索；MVP 不依赖向量数据库或云端 memory 服务。
- 记忆候选由现有 Analysis Worker 异步生成。
- 支持新增、合并、更新、冲突标记、失效和人工删除。
- 提供按关键词和实体过滤的记忆查询接口。

## 3. 非目标

本版本不包含自动执行外部操作、跨设备同步、多用户记忆、永久保存未经确认的推断、独立向量数据库，以及让 Agent 直接写数据库。

## 4. 记忆模型

每条记忆至少包含：`id`、`kind`、`subject`、`predicate`、`object`、`confidence`、`importance`、`status`、`valid_from`、`valid_until`、`created_at`、`updated_at`。

记忆类型：

- `semantic`：相对稳定的事实，例如“Elsewhen 使用 Rust”。
- `procedural`：用户偏好或习惯，例如“希望晚上提醒”。

状态：

- `active`：当前有效。
- `superseded`：被新记忆取代，保留历史和来源。
- `conflicted`：与其它记忆冲突，等待确认。
- `dismissed`：用户明确否定，不得自动再次启用。
- `deleted`：用户删除；默认不在检索结果中出现。

每条记忆通过 `memory_sources(memory_id, event_id)` 关联来源事件；禁止创建没有来源事件或用户明确输入的记忆。

## 5. 功能需求

### FR-PES-002-01 记忆抽取

1. 只有 Analysis Result 中明确表达的事实或偏好才可生成候选记忆。
2. 候选必须包含规范化的 subject、predicate、object、confidence 和来源 event_id。
3. 低于配置置信度阈值的候选进入待确认状态，不得自动成为 `active`。
4. 闲聊、猜测、一次性事件和无法指明主体的内容默认不生成长期记忆。

### FR-PES-002-02 去重与更新

1. 相同 subject/predicate/object 的候选应合并来源和置信度，不重复创建永久记录。
2. 同一 subject/predicate 出现新 object 时，不得静默覆盖旧记忆。
3. 新旧事实有明确时间关系时，旧记忆标记 `superseded` 并设置 `valid_until`。
4. 无法判断哪个事实正确时，保留冲突并标记 `conflicted`，生成 Clarification。

### FR-PES-002-03 检索

1. 支持关键词、subject、kind、status 和时间范围过滤。
2. 默认只返回 `active` 记忆；调用方可显式请求历史和冲突记忆。
3. 检索结果必须返回记忆内容、置信度、更新时间和来源事件摘要。
4. 记忆检索失败不得阻塞 Raw Event 记录。

### FR-PES-002-04 用户控制

用户可以查看记忆来源、确认/否定候选、编辑 object、标记失效、删除记忆，以及禁止同类候选自动写入。人工修改必须记录时间和修改前后的值。

### FR-PES-002-05 重建与隐私

1. 支持按事件和全量重建记忆；重建不得修改 Raw Event。
2. 删除来源事件后，相关记忆必须重新评估；没有剩余来源的记忆不得继续作为高置信度事实召回。
3. 原始文本、记忆和来源默认只存本机；发送给外部 AI 前必须沿用现有 Provider 配置边界。

## 6. 验收场景

| 场景 | 输入/条件 | 预期 |
|---|---|---|
| 新事实 | “我现在主要用 Rust 写 Elsewhen” | 生成 semantic 候选并关联来源事件 |
| 重复事实 | 同一事实记录两次 | 一条记忆，关联两个来源 |
| 偏好变化 | “我更喜欢浅色主题”后又说“改回深色主题” | 旧偏好 superseded，保留历史 |
| 冲突事实 | 两条记录无法判断哪个项目状态正确 | 标记 conflicted，生成 Clarification |
| 不应记忆 | “今天午饭吃了面” | 不生成长期 semantic/procedural 记忆 |
| 用户否定 | 用户拒绝一条候选 | 状态 dismissed，后续不自动恢复 |
| AI 不可用 | 记录时 Provider 断开 | Raw Event 成功保存，记忆任务可重试 |

## 7. 非功能需求

- 记忆写入必须幂等，可安全重试。
- 任何记忆都能追溯到来源事件和生成版本。
- 记忆层故障不得影响 Capture 和 Raw Event 提交。
- 初始实现只增加 SQLite/FTS5 依赖，不引入常驻外部服务。
- 所有自动写入、更新和冲突处理应有可测试的确定性规则。
