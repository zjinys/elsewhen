## 1. 产品目标

记录回答「我做过什么」，目标回答「我要去哪」。Elsewhen 若只做前者，就退化成一个记录工具；作为认知系统，它必须知道用户想去哪里，才能判断用户实际做的事是否指向那里。

本需求把目标提升为一级对象，并让系统用「用户在做的事」去对照目标，暴露偏差。三个判断构成设计前提：

- **人生需要目标**，认知系统应围绕目标组织，而非围绕存储模型组织。
- **人倾向做自己认为容易的事**，而目标往往难以达成。对话与事件流反映用户当下在做什么，因此具备判断「行为与目标的偏差」的条件——偏差检测的价值恰恰在于对抗这种向下的漂移。
- **目标随阶段更新**，用户在不同时期定义不同阶段的目标，系统不得把目标当作一次性设定。

偏差检测是本需求的核心，不是附属提醒。判断「多久没聊到目标」属于次要问题，且容易误伤：用户正在做的事若正是该目标，天天不会主动提起它。

## 2. 范围与原则

- 目标由用户显式设定。AI 不得自行创建、改写或删除目标，也不得把目标自动推导成别的目标。
- **同一时刻最多 3 条活跃目标**，这是硬约束而非建议。约束活跃集而非表总行数，历史目标另行保留。
- 目标阶段（近期/中期/长远）必填，但**不要求三个阶段都有**，且允许同一阶段存在多条。总量 3 条封顶，阶段是标签而非槽位。
- 目标历史不可原地覆盖。与 ARCH-002 对来源快照的原则一致：改目标内容可编辑同一目标，重定义目标（换阶段、换方向）走归档加新增，旧目标保留。
- 偏差判断是**待审建议**，不是事实判定。系统不得因为评估出偏差就改写目标、改写事件或降级证据。
- 偏差评估失败不得影响事件记录与对话。
- 所有表结构的新增与变更一律通过迁移实现，不得直接改写当前 schema 基线文件。

## 3. 非目标

- 不做目标向任务/待办的自动拆解。待办是独立对象（见 FR-PES-002 与既有 `todos`），自动拆解会把意图陈述和行为承诺混为一谈。
- 不做目标完成度打分、进度百分比或 KPI 面板。百分比是伪精度，会诱导用户为数字做事。
- 不做目标数量无上限的管理。「更多目标」不等于「更清楚的方向」。
- 不承诺模型对偏差的判断准确。偏差评估是可错建议，界面必须允许用户认为它判断错了。
- 不做系统推送或跨进程通知。进程未运行时不具备提醒能力，不以常驻服务换取提醒。
- 不复用 `rules` 表。`rules` 语义是行为约束（回复时对照检查），目标是意图陈述，混在一张表会使 `list_active_rules()` 把目标当作行为准则，且 `rules` 无时间维度。

## 4. 功能需求

### FR-PES-005-01 目标设定与管理

用户可设定近期、中期、长远目标，每条包含目标内容与所属阶段。同一时刻最多 3 条活跃目标，阶段必填、不要求齐备、允许同阶段多条。

**管理入口挂在对话区顶部的「今天」状态栏**（`ui/lib/widgets/message_area.dart` 的 `_NowStatus`），与「草稿」「待办」并列，不新增一级导航。这条决定了目标功能没有独立 tab，因此该入口在目标为空时**必须仍然可见**，否则功能将无法被发现。

达上限时拒绝新增并明确提示需先归档一条，**不得自动顶掉或静默替换既有目标**——用户写好的目标无声消失，与本系统「防止静默覆盖」的整体原则冲突。界面应在达到上限时预先禁用新增并给出提示，但拒绝的最终权威在数据库层，界面提示不得被当作唯一防线。

用户可编辑活跃目标正文、归档目标、查看历史归档目标。归档不等于删除，历史目标可复活（同样受上限约束）。

### FR-PES-005-02 目标进对话记忆

构造对话系统提示时注入全部活跃目标，使用户在任何对话中都以目标为背景被理解。目标为空时明确告知当前无目标，不静默省略该段。

目标与个人规则库必须语义分离：目标进入「当前追求什么」的上下文，规则进入「回复时对照检查」的行为约束段，二者不得混入同一段落。

目标段须带反向护栏，以免对话变成实时审计：仅在话题与目标直接相关时使用；**不评判用户是否偏离目标**；**不把对话引向目标**。偏差判断是 FR-PES-005-04 后台周期任务的职责；若对话里也做，同一件事会被做两遍，且更频繁的那遍会主导用户感受。

### FR-PES-005-03 目标历史

归档目标保留原内容、阶段、创建与归档时间。评估记录必须能说明「当时是对着哪个目标判的」，因此评估需内联保存当时活跃目标的文本快照，不依赖后续可能变化的表状态回溯。

### FR-PES-005-04 偏差检测

系统周期性评估「用户近期实际在做的事」与活跃目标之间的偏差，输出可溯源的判断：每条偏差结论必须指向具体事件或知识页，不得输出无证据的偏差断言。

评估须遵守两条纪律，二者决定这个功能是否会被用户关闭：

- **不重复已给过的判断**：同一偏差已在历史评估中提过且情况未变时，不重复输出。
- **宁缺毋滥**：没有真正值得说的偏差时返回空结果，不为凑数产出判断。

评估输入以事件流为主要证据（事件带结构化分类与原文），对话内容为辅助证据。不得把「用户没聊到目标」直接判定为偏离。

### FR-PES-005-05 评估的可观察性

偏差评估复用现有后台任务模式：周期性自动执行，无手动触发入口，失败原因可见、连续失败冷却后自动重试、进程重启后不永久遗漏。评估结果与运行日志可查看。

## 5. 待决问题

以下四项尚未裁决，不在本版需求内承诺；相关实现须等裁决后再定。

| 编号 | 问题 | 现状与候选 |
|---|---|---|
| Q1 | 偏差结论往哪里呈现 | 候选：独立列表页 / 混入对话上下文 / 写入待办。倾向独立列表加对话注入，不写入待办（AI 判断的偏差与用户自己的承诺语义不同，混入易被忽略）。目标管理入口已定在「今天」状态栏，偏差呈现是否复用同一处仍未定 |
| Q2 | 检查节奏是否由阶段决定 | 候选：近期每周、中期每月、长远每季。不由阶段决定则需要另一套节奏来源 |
| Q3 | ~~目标是否成为一级导航~~ | **已定（2026-09-28）**：不做一级 tab，管理入口挂在对话区「今天」状态栏，与草稿、待办并列 |
| Q4 | 「用户在干什么」以何为主 | 现有无结构化「对话主题」信号。事件流有结构化分类与原文，对话仅有自由文本。是否额外抽取对话主题层成本显著更高 |

## 6. 验收场景

| 场景 | 输入/条件 | 预期 |
|---|---|---|
| 首次设定 | 目标为空，用户新增「三个月内上线 v1」，阶段近期 | 成功，活跃目标 1 条 |
| 空态可发现 | 尚未设定任何目标 | 「今天」状态栏仍显示目标入口，用户可从该处开始设定 |
| 阶段不齐备 | 只设近期目标，不设中期与长远 | 正常，不要求补齐，不报错 |
| 同阶段多条 | 已有 2 条近期目标，再加第 3 条近期 | 允许，活跃共 3 条 |
| 达上限 | 已有 3 条活跃目标，再新增 | 拒绝并提示先归档；既有 3 条内容不变 |
| 归档后新增 | 归档 1 条后新增 1 条 | 成功，活跃集换血 |
| 编辑不误触上限 | 已有 3 条活跃目标，编辑其中一条正文 | 编辑成功，不被上限拒绝 |
| 历史保留 | 归档目标后查看历史 | 目标仍在，阶段与内容完整 |
| 复活受约束 | 已有 3 条活跃目标，尝试复活一条历史目标 | 拒绝；先归档一条后复活成功 |
| 目标进对话 | 存在活跃目标时发起任意对话 | 系统提示含全部活跃目标；目标为空时明确说明无目标 |
| 语义分离 | 对话系统提示 | 目标与个人规则库在不同段落，不混入行为约束段 |
| 对话不审计 | 用户说一段与目标无关的话 | 对话中不出现「这与你的目标无关」这类判断，也不主动转向目标 |
| 评估可溯源 | 输出一条偏差结论 | 必须指向具体事件或知识页，否则判为非法 |
| 评估不重复 | 同一偏差情况未变，第二次评估 | 不重复输出该判断 |
| 评估宁缺 | 近期行为与目标无实质偏差 | 返回空结果，不产出凑数判断 |
| 评估失败 | 评估时 Provider 断开 | 事件记录与对话正常；评估失败可见并可重试 |
| 不因沉默判偏离 | 用户近期未提及目标但事件显示正在推进该目标 | 不判为偏离 |

## 7. 非功能需求

- 活跃目标上限必须在数据库层保证，不得仅靠应用层计数（仓库已有两处 check-then-insert 竞态的修复记录）。
- 任何偏差结论都必须能追溯到当时的活跃目标快照与具体来源。
- 目标写入幂等，可安全重试。
- 目标与偏差评估故障不得影响 Capture、事件提交与对话。
- 偏差评估的上下文成本必须有界（目标最多 3 条、事件与证据条数有上限），不得随使用时长无界增长。
- 不引入常驻外部服务。
- 所有周期性行为应有可测试的确定性规则，不依赖随机或不可复现的采样。
