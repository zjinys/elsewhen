# FR-PES-004: LLM Wiki 知识库闭环

**版本**: v0.2

**最后更新**: 2026-09-29

**状态**: Implemented（验证范围见 §7）
**关联设计**: [技术设计](../architecture/FR-PES-ARCH-002-LLM-Wiki知识库闭环技术设计.md)、[现有 v1](../../llm-wiki.md)、[来源层构想](../../sources-and-deep-chat.md)

## 1. 目标与现状

用户记录事件或确认导入材料后，系统持续将原料编译为可追溯的知识，在相关对话、洞察及分析中使用；用户纠正可长期保留。知识库是积累和使用的循环，不以“导入完成”作为终点。

当前已有 SQLite wiki 页面、URL/文本/文件与项目导入、页面编辑及知识搜索工具。事件消化与认知洞察由应用后台执行，不设手动触发入口。本轮补齐统一来源版本、共享选材、可核验引用与人工审阅（见 §7）；项目目录仍沿用有界评估。旧来源层文档保留为设计历史，当前实现以本需求和技术设计的实施记录为准。

## 2. 范围与原则

- SQLite 是唯一真源；`wiki export` 是只读快照。原始事件不可变；已确认的导入内容保留原始快照和出处。
- AI 提议知识及修订，核心校验和记录审计；用户编辑和明确否定不能被后台任务静默覆盖。
- 记录事件成功不依赖 AI 或知识编译成功；失败可见、可重试、不重复写入。
- 检索结果与回答区分用户事实、外部观点、AI 推断；引用可返回具体来源，不把外部文章误写为用户画像。
- 继续采用有界项目盘点；项目目录默认不逐文件建页，也不生成无界目录镜像。

## 3. 功能需求

### FR-PES-004-01 自动积累

记录新事件后，系统安排可恢复的知识消化任务并在后台自动执行，不提供手动触发入口；用户可查看队列明细、每批日志、待处理数量、最近成功/失败时间和失败原因，连续失败的任务冷却后自动重试，不需要用户操作。迟到事件、跨时间窗积压、同时间戳事件及进程重启后不得永久遗漏。重复投递与重试不得重复累加同一事件的证据。暂无可靠 AI Provider 时记录仍成功，任务等待重试。

### FR-PES-004-02 原料与编译

网页、文本、显式文件导入保留原文快照、来源类型、出处和导入时间；同一来源再次导入可预览差异，用户决定是否更新。现有 `source` 页和 URL 去重需兼容迁移，不复制成两份原料。项目模式继续保存有界项目评估，文件模式才按用户明确意图逐文件采集。

系统可从材料建议方法、案例和规律页，列出支持它的原料及适用条件。强度分为 `reference`、`method`、`rule`；AI 不得自行把材料提升到会触发硬性提醒的 `rule`，必须用户确认。对现有素材页的 `reject` 评价应影响后续选材，不删除原文。

### FR-PES-004-03 使用知识

对话、话题分析、认知洞察和回顾共用有界选材契约，按当前问题、适用条件、状态、评价和证据选取；没有合适材料时允许不引用。回答可展示实际使用的页面、原始出处及适用理由；不得仅凭模型声称“已检索”而视为引用成功。固定四透镜在动态方法库未覆盖时保留兜底。

### FR-PES-004-04 纠错和维护

人工编辑页不得被后台 digest 覆盖；AI 修订走可审阅的确认流程。来源变更后标记依赖页待复核，不能静默改写用户定稿。系统提示无有效来源、失效来源、矛盾或过期候选和断开的引用；启发式提示是待审建议，不直接宣称事实错误。用户可以追踪修订及拒绝建议的历史。

## 4. 交付顺序

1. 自动消化与可靠任务状态：先使现有 v1 在日常使用中持续积累。
2. 统一来源和方法页：兼容迁移现有导入，不扩大项目扫描范围。
3. 共享选材与可见引用：逐一接入对话、话题、洞察和回顾。
4. 来源更新、矛盾/过期审视与人工确认：形成维护闭环。

各阶段可独立验收；前一阶段完成不代表整个需求完成。GUI 的后台任务状态应使用简短操作信息，不要求用户理解内部游标或模型提示词。

## 5. 验收场景

| 场景 | 预期 |
| --- | --- |
| 连续记录同类事实及重复重试 | 页面复用；每个不同事件恰计一次证据 |
| Provider 离线、进程退出后恢复 | 事件已保存；任务可恢复、状态可见，恢复后继续处理 |
| 迟到事件、同时间戳、超过默认 7 天的积压 | 均能处理，不依赖时间戳大于上次 digest 时间 |
| 人工修改档案页后出现新证据 | 保留正文，累加证据并给出待审建议 |
| 再次导入同一网页 | 不生成重复来源；用户可预览并决定是否更新快照 |
| 导入与用户无关的案例 | 可作为外部观点引用，不自动变成用户经历 |
| 用户拒绝材料或案例不适用 | 不作为正面依据引用，回答可不引用材料 |
| AI 建议把方法升级为硬规则 | 未经用户确认不生效 |
| 回答引用某条知识 | 可展开至页面及事件/原料出处，说明适用理由 |
| 项目目录很大 | 仅有界盘点，页面大小及耗时有上限 |

## 6. 非目标

本轮不引入第二真源、强制向量数据库、全量目录文件地图、自动执行外部操作，亦不承诺 AI 可以无人工确认判断所有矛盾或自动修复全部知识。真实使用几周后的质量评估应单列验证，不能用单次演示代替。

## 7. 实施与验证记录（2026-09-29）

- [x] **原料版本**：旧素材页原地绑定来源，保留全部已有正文；新导入保存不可变快照。网页、推文、显式文件支持预览后确认；确认期间来源变化则拒绝过期保存。推文 AI 整理稿单独保存为有出处的产物。
- [x] **知识提炼**：素材页“提炼知识”生成方法/案例/规律建议；“来源与修订”查看依据、接受或拒绝。默认 reference，规则强度由用户另行确认；模型修订改变规则内容后需要重新确认。
- [x] **知识使用**：主对话、页内对话、搜索工具、事件分析、话题分析、自动洞察与每日回顾接入共享选材；对话中有知识链接的回答可展开“引用依据”，查看当时片段、理由与具体来源版本/事件。
- [x] **维护审阅**：人工持有页保留正文和元数据，digest 留下待审建议；全局“知识审阅”列出来源变化、失效事件、无来源和断链提示，页内“审阅本页”生成附依据的修订建议。拒绝记录和历史版本持续保留。

验证使用临时数据库、离线 Provider、真实 Flutter Bridge 与本机 HTTP 测试 Provider，未使用个人库或外部账户。新增覆盖来源升级、去重、不可变性、确认竞态、工具引用、各消费通路、后台退避/中断恢复，以及界面的取消/拒绝/窄屏操作。

最终结果：Rust 全量 246 通过、0 失败；此前 Flutter 全量 199 通过，合入主分支后本次定向复验真实 Bridge、知识审阅、草稿确认与标题复制共 12 项通过；Linux release 构建成功；Flutter analyze 无 error，保留 77 条既有 info/warning。新增 Agent Note 单篇校验通过，全仓 Note 校验另有历史格式问题，未扩大到无关文档整理。

迁移协调已完成：另一 agent 结束后，用户明确授权接手 `new_migrations.rs`，两条既有断言已对齐 `04-knowledge` 与版本 4，相关注释同步更新。迁移 SQL 自检及 v3→v4 数据保留测试通过。

使用边界：检索采用关键词与适用条件匹配；没有适用材料时不引用。系统核验出处与版本，不替代事实判断。文件模式每批最多 100 文件、240,000 字，每文件最多 12,000 字，超过预算会说明并跳过；对话展示前 6 个文件的限长差异预览。超长日结输入超过总预算时返回错误。长期真实使用中的召回质量与积累空间仍需单独评估。

真实模型的测试材料、操作步骤、对照问题和评分方法见 [LLM Wiki 实际效果测试指南](../../testing/llm-wiki-real-world-testing.md)。指南尚未执行为真实模型验收结果。
