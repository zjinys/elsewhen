# FR-PES-006: 外部工具与技能执行

**版本**: v0.1
**最后更新**: 2026-10-18
**变更类型**: FEATURE
**状态**: Implemented（验收记录见 §6）
**关联设计**: [技术设计](../architecture/FR-PES-ARCH-003-外部工具执行与信任模型技术设计.md)

## 1. 产品目标

Elsewhen 的对话不适合只做「读写自己的库」。用户要求 AI 能做两件越出本地数据边界的事：

- **调用外部服务**：查仓库 issue、调内部 API、抓网页——业界成熟通道是 MCP（Model Context Protocol），用户自己配 server，不绑定某个厂商的工具市场。
- **执行本地自动化**：用户已有技能包（SKILL.md + 脚本，见 FR-PES-002 的技能体系），对话中应能真正运行脚本，而不是把命令打印出来让用户复制粘贴。

两者的共同点，也是本需求的核心命题：**AI 发起的执行，最终落在一个不在本系统控制下的任意逻辑上**——MCP server 是第三方代码，技能脚本虽是用户自己装的，但脚本内容同样可以是任意逻辑，且模型可能被诱导发出破坏性参数。因此本需求的主体不是「怎么执行」，而是**执行前的信任边界怎么设**：默认逐次审批、信任必须显式声明、豁免必须留痕（审计）、放行之外的一切拒绝。

## 2. 范围与原则

- **第三方执行默认不信任**。所有 MCP 工具调用与脚本执行，未标「信任」前必须弹出审批卡，由用户逐次确认。系统不得以任何理由（节省点击、会话流畅度、模型 自 行判断低风险）替用户跳过。
- **确认执行的必须是确认时看到的内容**（参数封存）。审批卡展示的命令/参数与实际执行的内容必须逐字节一致；确认与执行之间不允许任何重写、重排或环境侧改写。这是防止「确认前是好的、执行时被换成坏的」的铁律。
- **信任是显式、命名、可撤销的**。免审批只能作用于用户逐个命名的 MCP server 或技能（trusted 开关），必须有 UI 风险明示（第三方代码，模型可能被诱导发起破坏性调用），且撤销立即生效。
- ** trustworthy 是本机事实**。trusted 状态、MCP server 配置都不进同步域——换设备重新声明。一台设备的信任不搭车到另一台。
- **豁免不免除校验**。trusted 只豁免「按审批卡确认」这一步；执行函数、参数解析、server 活动性检查、超时控制与确认路径完全同一条代码。免审批绝不能演化成一条更弱的执行通道。
- **停用即拒绝**。server 或技能在调用执行的那一刻处于停用/删除态，一律拒绝——即使审批卡是在停用前生成的。
- **移动端诚实降级**。stdio server 与本地脚本需要桌面环境；Android/iOS 上直接明说无法执行，不假装、不静默失败。
- **信任边界的每一次放宽与收缩必须留痕**。trust/untrust 等生命周期动作写本机审计日志（JSONL），审计失败不得阻断主流程。

## 3. 非目标

- 不做 MCP resources / prompts / sampling 支持。v1 只接 tools。
- 不做 per-server 工具子集筛选（该 server 的全部工具常驻注入）。
- 不做连接空闲回收、后台健康巡检、自动重连策略调优。
- **不做细粒度「总是允许此工具」**。信任粒度是 server/技能整体，不细化到单个工具、单个参数模式。
- 不做跨设备同步 trusted 状态（见 §2）。也不做逐平台布尔组合（标签单值：all/linux/macos/windows，跨平台需求用同名变体表达）。
- 不在 v1 做「移动端把执行委托给桌面节点」（云端/本地执行选择），该方向已成文为独立提案（docs/notes/proposed/architecture/2026-10-18-mobile-execution-delegation.md），且以平台标签为前置。
- 不做审批卡的多 delegated 审阅（会话内 pending 卡只有一份，不接受多人审批）。
- 不承诺 MCP server 的行为安全。trusted 只表示用户对它的声明，不构成系统层面的任何安全背书。

## 4. 功能需求

### FR-PES-006-01 MCP 服务器管理

用户可在设置中增删改 MCP server：命名、选择传输（stdio 命令行 / streamable-http URL）、配置命令参数、环境变量、自定义 HTTP 头。提供「测试连接」入口：真实发起握手并拉取工具清单，把配置错误在保存前暴露给用户。server 可启停，停用的 server 不注入工具、不接受调用。

### FR-PES-006-02 工具发现与注入

启用 server 的工具以 `mcp__<server>__<tool>` 命名注入对话工具列表（含 server 描述），模型可直接调用。工具清单失败（server 起不来、网络不通）以工具结果文本形式诚实返回，不静默吞掉。

### FR-PES-006-03 工具调用审批（默认路径）

未信任 server 的工具调用：dispatch 阶段即暂存为待确认动作（pending-action），审批卡展示工具名与完整参数；用户点「接受」后按封存参数原样执行。「拒绝」则终止。模型侧收到的中间结果必须如实说明「已暂存待确认」，不得让模型误以为已执行。

### FR-PES-006-04 MCP 免审批信任开关

逐 server 的 trusted 开关（默认关）。开启后该 server 的工具调用直接执行，不再弹审批卡；UI 必须在开启入口处明示风险（第三方代码、模型可能被诱导发起破坏性调用）。撤销立即生效——下一次调用回到逐次审批。

### FR-PES-006-05 技能脚本执行

已安装技能的脚本经 `run_skill_script` 通道执行：脚本必须是技能 `SKILL.md` 声明的文件（防目录穿越）、按 shebang 解析解释器、传参经 shell-words 解析、环境变量白名单透传、输出限时收集。执行前审批卡展示完整命令与脚本开头摘录。每技能可独立加载其方法论正文而不安装执行通道（移动端降级）。

### FR-PES-006-06 技能免审批信任开关

逐技能的 trusted 开关（与 §FR-PES-006-04 同一模型）。trusted 技能的脚本直接执行，执行路径与手动确认后完全一致（同一函数重做全部校验）。

### FR-PES-006-07 生命周期审计

MCP server 的增删改启停、trusted 开关，技能的安装启停信任操作，全部追加写本机 JSONL 审计日志（时间、动作、对象）。审计失败静默降级不阻断主流程，但成功时每条动作必须留痕。

## 5. 约束

- `skills_state.json` 不进同步域；`mcp_servers` 定义随快照分发但 `headers_json`（凭据）与 `trusted`（信任）不入快照（迁移 48）。
- MCP 工具参数含动态 JSON，跨 FFI 边界一律字符串化（`args_json` / `headers_json` 等），不直接传 `serde_json::Value`（frb 界面限制）。
- streamable-http 采用逐消息 POST 拉模式，不开常驻 SSE 流；HTTP 头承载鉴权。
- trust 的粒度是 server/技能整体；不许出现「某工具免审批、其余审批」的混合态。
