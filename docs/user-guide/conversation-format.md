# 对话与记录格式

Elsewhen 接受自然语言，不要求固定命令。以下标注用于减少人物、项目和意图识别歧义。

## 人物与事情

- `@人名`：明确标注人物，例如 `@张伟 今天确认了方案`。
- `#事情`：明确标注项目、事项或主题，例如 `#付款流程 进入测试阶段`。
- 人物和事情可以组合：`@张伟 正在负责 #付款流程`。
- 同名人物需要在名称中写清区别：`@张伟（市场部）`、`@张伟（设计）`。

`@` 和 `#` 是用户给出的权威标注。系统可以据此草拟人物、关系和事实，但长期知识仍需用户确认后保存。

## 常用意图

- 明确记录：`记一下：今天完成了付款流程联调`。
- 保存知识：`把这个结论保存到知识库`。
- 创建待办：`帮我建一个待办：周五前确认合同`。
- 继续讨论：直接说 `继续聊付款流程`，不需要进入专门的“议题”页面。

## 确认与拒绝

- AI 草拟人物关系、知识页、待办等内容后，回复 `好`、`确认` 或等价肯定表达才会保存。
- 回复 `不要`、`取消` 或等价拒绝表达，不会写入长期数据。
- 普通客观记录会直接进入事件记录；人物、项目关系和知识沉淀仍走确认流程。

## 完整示例

```text
用户：@张伟 正在负责 #付款流程
AI：已草拟人物与关系……回复“好”即保存。
用户：好
```

确认后，知识库会创建或复用对应页面，并保存能够回到这条原始记录的结构化事实。
