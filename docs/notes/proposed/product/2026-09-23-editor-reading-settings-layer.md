# 知识页阅读参数分层：编辑器（内容区）覆盖层 + 全局界面设置

Status: proposed（2026-09-23 与用户讨论收敛，未实现）

## 背景

知识页是高频阅读面。用户提出「在看知识页内容的时候能够修改字体、字号、行间距」——阅读舒适度参数应能**就地调整**，而非只藏在系统设置里。

讨论中收敛出的关键区分（用户明确）：

- **全局设置（设置页外观 tab）** 作用域是**整个界面**：侧边栏、Tab、对话框、正文都受它影响。
- **编辑器/内容区阅读参数** 作用域是**知识页正文这一个 editor 区域**。

这两层是**不同的参数**，不能做成"同一套值的两处入口"。正确形态是**覆盖/继承两层模型**：编辑器维护一组可空参数（字体/字号/行距），显式设置即覆盖全局，未设置则继承全局。

当前已落地的「正文字号」（仅知识库正文、默认 16、滑块 12–24）只是这条链路的第一段，语义上位于"内容区覆盖层"附近，且尚未与全局层区分（见[与现状的关系](#与现状的关系实现时需理顺)）。

## 目标

1. 阅读时可就地调整正文的字体、字号、行距，立即生效。
2. 三个参数各自独立可"未设置"（跟随全局），不做整体开关。
3. 全局设置保持"管整个界面"的语义，不被内容区覆盖污染。
4. 存储分两层、互不覆盖：改全局不冲掉编辑器覆盖，改覆盖不影响其它界面。

## 模型

求值链（渲染时在 `fontAwareTextStyleConfiguration` 一处求值）：

```
实际字体 = 编辑器字体(可空) ?? 全局字体
实际字号 = 编辑器字号(可空) ?? 全局字号
实际行距 = 编辑器行距(可空) ?? 全局行距
```

- 每个编辑器参数可空；`null` = 跟随全局。
- `fontAware` 即唯一求值点：读到编辑器值优先、空则回落全局——改动天然收敛一处，不含布局层。
- UI 上每个覆盖项必须有「跟随全局」的重置出口；重置后该项回到 `null`，立即回落全局取值。

## 存储设计（拟）

- 全局层（**已有**）：`theme_font`、`theme_font_size`（默认 16），未来加 `theme_line_height`。
- 内容区覆盖层（**新增，三项均可空**）：`theme_editor_font`、`theme_editor_font_size`、`theme_editor_line_height`（app_meta 键）。

两层键独立，读取时按上述求值链合并。

## 与现状的关系（实现时需理顺）

- 现在「正文字号」放在全局外观页，但语义是"仅知识库正文"。按本模型，它更接近**内容区覆盖层**的作用，只是入口在全局页。
- 实现时需拍板全局字号是否要影响界面其它文字（主要受布局约束，实测影响有限）：若全局只管正文基准，则现滑块语义不变、只加分内容和存储层；若全局要缩放整个 textTheme，界面 chrome 多为显式固定字号，实际影响很小——两条路都收敛在"全局层 + 覆盖层"框架内，只是入口分布不同。

## UI（拟）

- 编辑器内：区块栏「AA」按钮 → 浮层，内含字体（沿用现有 FontPicker 机制）、字号、行距三个控件，每项带「跟随全局」重置。
- 设置页外观 tab：继续管全局层。是否镜像一份"正文区覆盖"入口留作开放问题。

## 约束 / 协作

- 区块栏与 `wiki_page_detail_view.dart` 属并行会话重构区；「AA」入口落点需等并行收尾后叠加，或明确交接该文件。
- 行距：vendor `TextStyleConfiguration` 自带 `lineHeight`（默认 1.5）及行盒控制字段，`fontAware` 增加参数即通，渲染层零改动。建议档位化（紧凑/标准/宽松，或 1.3–2.0 滑块）。

## 测试思路

沿用 RenderParagraph 实测：已知字号/行距配置下断言渲染正文的 `fontSize` / `lineHeight`；覆盖层为空时回落全局值同断言（两层求值链各测一正一反）。

## Open questions（实现前需拍板）

1. 全局层字号/行距作用域：只管正文基准，还是缩放整个 textTheme？（后者实测影响有限，倾向前者）
2. 设置页是否镜像"内容区覆盖"入口（与编辑器 AA 浮层同值），还是保持纯全局？
3. 覆盖层粒度：一个全局"编辑器覆盖层"即可，还是按知识页/按区块？（推荐前者——单层覆盖，避免状态爆炸）
4. 行距档位阈值。
