# Agent Note: 单流对话与显式主题入口实现

Status: proposed

## Problem

当前 Flutter 对话入口仍把 conversations 展示为可新建、改名、归档和切换的列表。这个模型把聊天过程当成长期对象管理，不符合 Elsewhen 以事件、实体、待办和知识页承载记忆的设计。

## Proposal

对话入口改为唯一主对话流。底层 conversations 保留，但 UI 不再提供列表管理。topic 讨论通过显式标记进入知识页聊天；AI 自动识别只提供辅助建议，不作为唯一入口。

当前实现以数据库中持久化的保留标题 `主对话流` 与 `diary` 标签作为主对话身份；旧数据首次加载时收敛到该身份，知识页聊天通过 `wiki_page_slug` 保持隔离。

## Alternatives considered

- 保留最近对话列表作为过渡：不采用。项目仍在开发阶段，没有既有用户习惯需要兼容，且会继续强化错误的信息架构。
- 完全依赖 AI 自动判断 topic：不采用。边界错误时用户无法预期内容归属，因此必须提供显式语法或标记。
- 删除底层 conversations 数据模型：不采用。旧消息和知识页聊天仍需可读，存储模型与 UI 信息架构分离。

## Acceptance criteria

- 主对话启动后无需用户选择会话。
- 主路径不出现新建、改名、归档和会话列表。
- topic 入口语法明确、可见、可纠正。
- 普通对话和 topic 聊天的事件写入边界保持可验证。

## Risks

- 无限主流需要分页和日期边界。
- 同名 topic 需要候选确认。
- topic 讨论中的结论必须通过确认门沉淀，避免信息丢失或越权写入。
