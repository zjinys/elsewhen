# Agent Note: Agent 记忆增强——来源有效性、纠错与任务相关召回

Status: proposed

- 首次提出：2026-11-21；2026-11-23 已接通记忆生命周期、受控跨会话、自审、可选索引、M5 保守策略及专用管理页工程，整体提案及 M0–M5 质量出口仍未完成。
- 输入：[Anthropic — The components of agent memory](https://www.anthropic.com/research/components-of-agent-memory)（2026-11-06）。研究中的实验用于提出待验证假设，不代表 Elsewhen 已获得相同效果。

## Problem

希望 AI 在同一主对话的早期消息已不在当前上下文时，仍能找回相关经历和明确偏好；需要引用其他会话时遵守范围限制，说明依据，并在用户纠正后停止引用旧结论。提出时原始事件、Wiki 与对话工具已有部分能力，独立 semantic/procedural 层仍是规格；2026-11-23 工程进展见下文，质量出口未签收。需要先量出缺口，避免把另一套摘要、状态和审阅工作交给用户。

初稿先建设“认知仪表盘”，并把两条不同批次的事件视为独立验证。这会产生三个问题：重复转述被升级为事实、失效内容通过长期注入继续传播、用户持续审阅自动生成的个人画像。仅检查引用 ID、事务与版本不能证明模型结论正确。

### 已核对的代码事实

| 能力 | 当前事实 | 对设计的约束 |
|---|---|---|
| 个人背景注入 | `src/ai/memory/system_context.rs::user_cognition_profile_background` 当前工作区已按最近用户输入调用知识选择，最多取 3 个 `insight/habit/recurring_cost` 并复用证据包；知识/目标专属会话跳过 | 此处已有改动与本次历史召回分别验证；不能沿用旧 top-5 假设，也不将派生背景等同于人工确认 |
| 自动知识发布 | `src/storage/digest.rs::apply_digest_batch_with_reading` 在保护人工正文的前提下自动保存；`src/knowledge_background/sources.rs` 可自动发布未受保护的参考知识 | “所有 AI 错误都会被人审挡住”不符合现状；参考知识、个人偏好与执行规则必须区分 |
| 引用与使用记账 | `src/knowledge/bind.rs::record_usage` 和 `knowledge_usage` 已记录候选与最终引用；`src/knowledge/health.rs` 使用现有台账 | 补齐缺少的访问类型与实际注入回执，不重复建立一套来源/引用台账 |
| 依赖与纠错 | `src/knowledge/dependencies.rs` 记录版本基础、epoch 和传递失效；源刷新、人工维护、跨源整合已存在；`integration.rs` 会按 30 天重新访问未变来源 | 不是“所有纠错仅由来源变化触发”。缺的是面向已保存结论、按风险调度的自审覆盖与注入前检查 |
| 校验与并发 | 来源 ID/引文、版本基础、事务、租约围栏可限制非法引用与迟到覆盖 | 不可变记录只证明“当时记了什么”；这些机制不能保证原话为真或推断受证据支持 |
| 模型预算 | `src/ai/budget.rs` 有 tokenizer/估算分族和序列化请求预算 | 分词器分类不是记忆能力分类，不能据模型家族决定可信度或放宽校验 |
| 长期记忆 | FR-PES-002 尚无独立 `memory_*` 模型实现 | 先复用现有知识与检索边界；只有出现无法表达的事实生命周期需求才增加记忆索引结构 |

### 研究证据及适用范围

Anthropic 研究支持“小型注入层、原文可回查、后台整理与纠错”这些方向，但没有验证 Elsewhen 的产品效果或人审制度。

- CL-Bench 的部分模型能形成“规则、支持依据、反例”的学习闭环；对强模型限定“只记失败”降低收益，对另一模型增加读记忆与检验假设的引导有效。不能从这些任务推导所有供应商的通用能力档位。
- 宝可梦实验中 Sonnet 3.7 写 413 个文件、获得 1 枚徽章；Fable 5 写 9 个文件加 `global.md`、获得 4 枚徽章。原文随后提到 Opus 5.5 通关，不能把前一组成绩记到 Opus 5 名下。
- 该例中可从每轮画面直接读取的位置/余额不值得另存；这不意味着凡是能从历史重新推导出的偏好、规律与经验都不保存。
- 企业 Wiki 实验使用约 35 万文件、4.2 亿 token、25 个评测问题。128 轮整理后 Wiki 单独使用达到 48%，Wiki 加搜索达到 61%，仅搜索为 53%。这是特定语料与任务的结果，不是普遍保证。
- Borges 失败指 Wiki 集合膨胀超过原材料，不能由此直接导出“任一页/来源字符比超过 0.5 就有问题”的阈值。

初稿中没有可定位一手出处的模型智力分数、供应商口碑及其他记忆基准数字不再作为设计依据；后续若使用，必须附原论文/实验、版本与评测口径。

## Proposal

按“评测 → 来源与纠正 → 任务召回 → 小型索引 → 可选后台策略”推进。先冻结不变量与用户收益，不先增加画像页面或完整记忆表。

### 对话边界与主对话召回（2026-11-22 补充）

产品分为主对话、知识页讨论、目标讨论三类；主对话持续复用，不同知识页/目标可分别关联会话，目标工作室归目标讨论。`conversation_id` 不同才是跨会话；同一主对话跨天、翻篇、裁剪、换模型属于同会话历史召回。事件/知识检索可能来自同会话，也可能没有会话归属，不能一概称为“跨对话”。三类间不默认共享完整聊天历史，知识页正文可检索也不表示该页全部讨论可供引用。

M2 的核心先覆盖单一主对话：结合当前输入与最近几轮理解实体、时间和指代，在允许范围检索历史讨论片段、事件及知识，按预算补读必要上下文和后续纠正，最终请求前复核资格。原始消息不必先成为长期记忆才能检索；区分用户决定、助手建议与工具结果。同源片段不增加独立支持，未命中允许不注入或澄清，近期上下文足够时允许跳过检索，不要求每条输入增加模型调用。跨会话引用另测任务相关性、来源回链和范围隔离。具体要求与场景以 FR-PES-002 2.1–2.2、FR-PES-002-03 及第 6 节为准。

### 1. 来源、确认和使用许可分开

记忆条目是带适用范围、时间和来源的主张。以下维度不能用一个 `verified` 布尔值替代：

| 维度 | 表达内容 | 不能推导出的结论 |
|---|---|---|
| 生命周期 | `pending/active/superseded/conflicted/dismissed/deleted` | active 不等于事实已被证明 |
| 用户确认 | 针对确切条目版本的确认/纠正记录、范围与时间 | 确认个人偏好不等于验证外部事实；看过/收藏/采纳提示不算确认规则 |
| 证据支持 | `unassessed/supported/contradicted/insufficient`，含评估版本及依据 | supported 也可能出错，必须保留回查与纠正能力 |
| 来源独立性 | 来源谱系/独立组、未知或已知关联 | 不同事件 ID、批次、会话或重复摘要不自动构成独立来源 |
| 来源有效性 | `current/stale/unavailable`，针对当前引用基础推导 | 曾经有效不能使已撤回的来源继续供当前决策使用 |
| 使用许可 | 可作检索材料、可作个人背景、是否已有规则域的明确授权 | 参考知识不能因热度、重复出现或模型 confidence 自动变成个人事实/执行指令 |

复用 `knowledge` 现有强度/确认/依赖语义，具体存储映射在工程阶段冻结。用户明确表达的偏好可以由一次确认成立；来自相同事实的转述、导入副本、AI 摘要和再生成不新增独立支持。来源谱系未知时保留未知，不从“不同批次”猜独立性。

用户当次直接表述“我偏好浅色主题”即可作为明确输入记录，无需为了记忆重复弹出确认；必须区分原话、引用他人观点、假设和对模型推断的确认。界面上额外接受一次模型建议不自动扩张成长期授权。

`basis` 至少标明主张对应的来源 ID/版本、摘录或位置与适用范围。代码核对 ID、版本、引文和候选输入归属；语义是否支持结论仍可能需要模型判断和人工审阅。存在引用不等于支持成立，程序不声称能确定性证明一般自然语言推断。

人工纠正、确认、否定与删除抑制是权威记录。重建派生索引、重新分析事件或更换模型不得删除这些记录，也不得自动恢复已否定条目。

### 2. 在召回与注入之前阻断失效内容

查询与最终请求组装都核对当前条目、来源版本、来源意见、适用时间及确认版本。以下变化立即影响下一次请求，不等待后台生成新摘要或用户批准新索引：

- 用户纠正/撤回偏好，记忆被否定、删除或出现待澄清冲突；
- 来源被撤回/禁用、事件不再可记录、相关知识页被归档或依赖失效；
- 规则失效、目标完成/暂停、适用条件或时间范围改变。

保存历史正文和当时证据，供用户显式回查；默认个人背景不再使用失效结论。合法的历史检索注明当时版本，不把旧偏好说成当前偏好。

“不再注入旧结论”针对当前背景、工具回填和派生摘要的资格，不删除不可变原始事件或篡改对话历史。历史上下文必须携带可定位的替代/撤回说明，禁止把被取代的旧原话再次总结为当前偏好；预算不足时可以省略旧材料，不能只保留旧结论而裁掉其纠正。

缓存键至少包含条目版本、依赖基础、确认/撤回代次和检索策略版本。工具已返回后、最终请求组装前发生纠正，也要重新过滤并重算预算；重试不复活旧内容。已发送请求以原输入版本记录，返回后不自动升级为当前知识，后续请求使用新基础。

全局背景与索引失效时，回退仍需上述过滤；没有可靠条目时允许无背景。用户改口按事实有效时间与适用范围处理，不能仅凭数据库更新时间选择较新 object。没有明确替代关系则待澄清。

### 3. 先做好与当前问题相关的召回

复用现有 FTS5、`select_knowledge`、`synthesize_knowledge` 和逐字证据回链，不新增并行的通用检索栈。用固定问答集检查主对话能否拿到相关材料，再定位是缺数据、没召回、没读全还是理解错。

- 优先匹配当前问题中的实体、主题、时间范围及适用条件；当前目标只是任务相关信号，不能把所有材料都向一个目标改写。
- 先取有界候选，再按来源有效性、确认范围、与问题的关系和证据支持重排；活跃但低相关的近期页面不挤掉明确相关的旧经历。
- 需要综合多页时使用现有分块证据提取，披露未读范围，不把摘要当原文；不足时返回未知或澄清问题。
- 明确偏好、用户自述、外部观点、模型假设在结果中可区分；用户能通过可读标题打开原始依据。
- `knowledge_mentor`、`goal_mentor` 与页内会话沿用隔离边界；页面或目标变化是否对这些域生效，应复用它们自己的上下文路径，不用全局画像绕过。

### 4. 将“认知仪表盘”收敛为可重建的小索引

首版不增加必须持续人审的新 `cognition_dashboard` 页面，也不让每个 digest tick 重新生成个人画像。先从当前可用条目确定性构造导航索引，按问题选择短标题、适用提示与下层引用。它是派生缓存，不是另一个个人事实来源。

- 仅索引符合第 1/2 节边界的条目；每项绑定下层 ID、版本和依赖基础。目标/规则等已有专属注入时去重。
- 用户可以固定或排除某项，选择本身单独保存；底层内容失效仍须移除，固定不构成有效性豁免。
- 首版最多 8 个下层依赖，复用现有 `dependencies::capture` 的上限；更大范围由检索访问，不扩大常驻上下文。
- 渲染后以约 800 字符作为初始展示上限，并服从最终序列化 token 预算及 `OptionalBackground` 省略策略；只有在省略/重试后仍实际进入请求的内容才记为注入。
- 来源变化即过滤/重建受影响项，不用“全文差异超过 30%”决定是否撤掉旧偏好；缓存未完成、损坏或无有效条目时无注入，或从当前有效来源重新构造。
- 如以后需要人工编写的“我的画像”，它属于独立人工文档；不得把它与自动缓存混成同一个可覆盖正文。

是否启用此索引由第 8 节的等预算对照决定，不能因已有页面形态就默认它比检索更好。

### 5. 低频自审与纠正闭环

现有源刷新、跨源整合和人工维护继续工作。新增自审应覆盖“来源未变，但已保存结论可能一开始就误读”的情况，复用租约、版本围栏、失败退避与只读队列展示，不假定 `maintenance.rs` 已提供通用语义验证器。

- 输入包含条目当前断言、适用条件、引用基础和纠正记录；显式检查支持、反例与不确定性。没有当前来源就报告缺口。
- 长来源复用阅读缓存与逐字摘录核验；未覆盖的部分明确列出。未读全不能宣称“全部来源已核验”，也不能据局部缺失直接删除结论。
- 发现明确版本失效由确定性检查立即停止当前使用；模型怀疑语义不支持时生成 `pending` 复核提案，保留引文和问题。模型不自行宣告外部事实已证伪或采纳替代正文。
- 优先用户报告错误、当前冲突、即将用于回答且很久未复核的条目；常规低风险条目后置。无流量或额度时不运行，Capture 与前台对话不等待它。
- 初始每次知识 tick 至多 1 个有界自审步骤，同页/版本/策略 7 天内不重复普通周期自审。用户纠正或基础变化形成新代次；失败沿用退避，不每 tick 重新付费。
- 增加独立每日请求/token 配额、前台忙碌让路、积压老化和失败熔断；实际值在工程开始时结合现有预算冻结。仅有“每 tick 两页”不能证明不挤占其他任务。

### 6. 访问记账与显著性只辅助调度

复用 `knowledge_usage` 的候选/引用记录，并区分 `user_open`、`retrieved`、`cited`、`injected`。按设备本地的逻辑运行/请求 ID、条目版本、使用类型去重；重绘、预算重算、模型重试不重复累加。每次重试保留独立 attempt 回执，聚合使用次数按逻辑请求计算。注入回执以最终实际发送的内容为准，失败请求单独标注，不算成功使用。

- 自动注入次数不参与自身注入排序、证据强度或确认状态，防止“常注入→常使用→更常注入”。
- 用户主动查看和实际引用可以提高纠错优先级；错误被频繁引用意味着风险大，不意味着更可信。访问少也不能使已确认的长期偏好自动失效。
- 访问台账默认设备本地、可清理、不进入知识正文或同步业务变更；个人人审与确认记录仍按业务数据保留。
- `salience` 是可选排序提示。人工显式标记优先，模型打标不得跳过 settle、recordability、版本校验和失败退避；配老化/普通任务保留额度，避免普通事件永久饥饿。
- 模型全部标 high 时回退时间顺序；显著性不自动创建规则、不自动提升个人记忆使用许可。

### 7. 后置策略：防膨胀、断链与目标关联

防膨胀先记录集合级统计：固定范围内派生正文总量/去重原材料量、同源重复覆盖、近似重复页、新增页是否带来可验证信息。短原始记录支持较长解释并不必然错误；引用相同长文也不能给无限新页面提供“压缩比额度”。

阈值由评测样本校准，首版不使用单页 0.5 比例作质量判定或人审开关。统计可生成维护线索，不能自动删除、拆页或阻断用户笔记。断链检查复用依赖与关系记录；断链是结构问题，不能顺带推断语义等价并自动合并。

有目标时，可以给检索与整理提供任务范围；目标完成/暂停后相关缓存即时更新。保留与当前目标无关但有用的记忆，用户自述优先于模型推断，不据目标相关性改写原始事件。

## 同会话历史召回首批实现（2026-11-22）

`src/ai/memory/history.rs` 复用会话冻结快照和既有关键词/摘录能力，主对话在每轮 provider 请求前自动检索；指代线索可引入近期三条聊天关键词。既有 `search_knowledge_base` 工具也返回本会话历史，不新增工具或跨会话聊天权限。原始角色、时间、内容版本、片段位置和未读范围进入来源包，中英文指令明确讨论不等于采纳、旧记录不等于当前事实。

采用冻结快照是为了沿用既有因果顺序，避免把排队中后续输入带入当前回答；装入前再查实时消息及事件资格，避免快照复活已撤回或修改来源。最多选择三个关键词命中讨论及各自相邻后续轮次，每轮最多六条、每条最多 480 字符，历史包约束为 12,000 字符并继续经过请求总预算。整个包按可选背景一起裁剪，避免预算裁剪独留旧说法、丢掉同包纠正。每轮重新验证缓存工具历史和其中事件片段，保留工具配对及其他结果字段。

选择本地词法召回，而非新增向量服务、表或一次额外模型判定，是为了先验证可测的历史遗漏问题并保持现有存储/同步边界。代价是线性扫描和词面依赖：不能保证远距离、无共同关键词的纠正，也未解决跨语言语义或大量历史性能；独立主张生命周期、人工否定重建、受控跨会话聊天引用仍待实施。失败或旧冻结提示目录缺少新指令时跳过自动历史注入，保留原回答链路。

[验证记录](../../../testing/2026-11-22-memory-history-recall.md)：24 个固定合成场景中，21 个正例的相关证据召回通过，3 个撤回场景均排除；该数字只衡量证据可达性，不是模型回答正确率。记忆相关 46 项和串行 HTTP/取消回归 4 项通过。全量测试仍有既有工作区失败，真实模型与 GUI 未验收。本次不把 M0/M1/M2 出口标为完成。

## 实施顺序与进度

### 生命周期与受控跨会话工程（2026-11-23）

迁移 92 与 `src/storage/personal_memory/` 实现本地主张元数据、短引文/版本、人工决定与抑制、快照授权和访问回执；正文仍保存在 Wiki。`search_memories/propose_memory/review_memory` 复用工具与精确版本审阅卡；确认、来源可用、模型 support 和执行许可分别处理。相同主张合并来源，不按重复次数升级证据；明确替代保留旧版本，未明确的不同值确认形成冲突。删除/否定跨原页面、同正文及主体关系抑制重提，语义改写等价性不由程序担保。

主对话每轮刷新画像、事件、历史和记忆包，Provider 预算回调再次检查版本/许可；撤回内容从缓存工具结果和旧背景移除。查询采用冻结输入，排队消息的事件派生不成为当前请求依据。跨会话需在目标会话审阅源快照，授权只到当时消息上界；不含未来消息、个人主张元数据、修改或执行权。源归档后仍可撤回授权。本地表明确不参与同步，重建保留人工决定；未实现跨设备记忆协议。

后台知识 tick 复用 `knowledge_background_runs` 自审一项：单并发、每天 4 次上限，前台优先/可暂停、版本围栏、7 天重访、失败 6 小时起指数退避。只读 2400 字符正文与有界真实依据，未读全降级 support；结构化支持/反例/未知生成待审阅卡，采纳只更新 support，不变成人工确认。小索引默认关闭，开启后从当前有效条目重建，最多 8 项且渲染至多 800 字符；注入台账依据最终预算与请求结果，裁掉不计、失败/前次重试保留 unknown，不用于自我强化排序。打开/检索/引用沿用知识访问链路并补充记忆回执。

直接偏好输入不强制重复点击：`explicit_preference` 首版只接受与用户原话/正文完整匹配、最多 160 字符的保守直接自述格式；不覆盖任意自然语言的语义分类。其余表达保持候选审阅。尚缺真实等预算回答、跨模型与 7 天观察及真人 GUI 验收；M5 首版见下节，不把默认关闭索引或排序策略的存在称为质量收益。[验证与剩余范围](../../../testing/2026-11-23-personal-memory-controls.md)。

### M5 用户控制与保守调度（2026-11-23）

迁移 93 增加本地固定、排除、人工显著性及目标关联。所有修改复用 `review_memory` 版本绑定审阅卡，只允许条目所属会话修改；重建保留决定，新替代条目不继承控制。默认查询排除停用条目，只有明确查看才 `include_excluded=true`，返回绑定当前会话/冻结输入且仅供本轮审阅的标记。实际返回的查看轮次另存条目/输入标识，下一轮抑制该轮历史、关联事件及缓存，清理访问回执也不解除限制。停用也抑制旧来源历史、事件、知识包与摘要；不改写原始内容。固定和 high 不能复活失效来源、冲突、未确认或未授权的条目。

检索在既有有界候选中按词法相关度、固定、活跃目标关联、人工显著性排序；明确关联当前活跃目标也可在没有共同关键词时进入候选。目标讨论采用自身目标，其他会话可显式传 `focus_goal_id`，不扩大可读范围；暂停/完成停止关联召回和加分，目标及关联版本进入缓存围栏，通用记忆仍保留，显式清空目标只级联清除关联。自审通常优先冲突/候选、显著性、活跃目标和近 30 天去重且封顶的工具打开/实际引用风险；每天第 4 个名额回到最早到期顺序，排除项不自审。自动注入和检索次数不反哺排序、支持或确认。

`search_memories(view=maintenance)` 提供至多 200 条可见未删除条目的相同正文、同源覆盖、词面近似重复和来源失效线索；派生正文与短依据统计明确不等同全量压缩比，不触发自动删除、合并或重写。`clear_usage` 经审阅只清本机记忆回执，保留人工决定。聊天和通用审阅卡继续保留；专用管理体验由下述增量补齐。自动遗忘、模型显著性、语义合并和真实质量收益未交付。

### 专用管理体验的取舍（2026-11-23）

新增「设置 → 知识 → 记忆管理」列表/详情页，不新增独立后台。选择单独的本机人工分页查询而非复用自动召回，是因为管理者需要找到超过 200 条窗口、非 active、已排除甚至已删除的元数据；这种浏览不是授权给任意聊天读取所有内容，也不产生模型输入或聊天查看轮次。正文仍复用 Wiki，详情最多 6000 字符，已删除/否定和版本不匹配内容不展示，保留明确截断标记。

写入继续走已有 `review_memory` 执行器：详情指纹与条目版本先绑定待改对象，准备阶段在事务中生成所属会话的提议；新 UI 展示实际提议的操作/来源/范围/替代项后，批准原 token，失败只允许刷新重审。放弃“直接 SQL 改标志”和“点批准时重新获取卡片 token”方案，避免绕过人工决定、覆盖变化或批准未展示的内容。取消拒绝原提议；管理操作不发送聊天续跑，避免设置操作意外触发模型。不可用所属会话维持原修改限制，未用人工管理入口扩大运行时授权。

首版只提供单项控制和有界维护线索，不另做正文编辑、批量事实改写或自动去重。恢复候选后仍须重新确认，目标关联仍需说明；管理页和跨设备记忆协议分开处理。验证继续使用隔离数据库及合成 UI，真实多日收益和完整设备体验验收保持待办，记录见[本轮验证](../../../testing/2026-11-23-personal-memory-controls.md)。

首次打开的空列表暴露了数据入口说明缺口：管理页只列已有主张，聊天工具 `propose_memory` 才会创建候选，自审不会从旧聊天或 Wiki 回填条目。采用明确区分未创建、筛选无结果与请求失败的空状态；不为填满界面而伪造条目，也不把旧 Wiki 批量升级为已确认记忆。历史候选发现/回填仍是独立待办，不把管理 UI 完成表述为这一链路已经闭环。

### 统一范围与使用可见性需求（2026-11-23）

[FR-PES-007](../../../requirements/product/FR-PES-007-统一记忆与使用可见性.md)补充来源对话与适用范围分离：个人通用记忆在三类对话中按统一资格使用，目标/主题/仅本对话范围显式声明；不能用创建对话充当所有适用场景，也不能由共享记忆推导出完整聊天读取许可。原 personal 范围扩展到更多对话涉及权限变化，迁移必须展示并取得用户范围决定，未决定前保留旧边界。

本次进一步核对了管理与请求链路：管理列表只读结构化主张，Wiki 认知背景、个人画像、历史/摘要、事件和任务背景还有独立入口。因此采用长期记忆管理与本轮全通道使用记录分层解释的方案，不把原始历史、参考知识、瞬时目标状态全部强转为长期个人事实；也不通过界面展示全部候选就声称最终预算后已经发送。使用记录需区分选中、裁掉、发送尝试与传输结果。

新增 2 项临时库测试并复跑既有回执测试，合计 3 passed：空主张列表与事件背景并存可复现；已有主张的管理、搜索、自动背景身份/版本一致，排除操作改变自动使用资格而不移出管理列表；预算/重试/失败的回执区分保持。没有读取个人数据库或使用真实模型。本次交付为 FR 与核验，统一范围、历史回填和全通道使用界面仍未实施；入口沿用用户调整后的「设置 → 记忆」。

### 剩余工程的存储与权限约定（2026-11-22）

继续实施时，Wiki 正文仍为记忆文本的唯一权威；本地 `personal_memory_*` 表只存条目元数据、精确版本的依据、人工决定、范围授权与请求回执。人工否定和删除保留稳定键，不随重建清空；原始事件和对话不改写。新增表明确排除业务同步，跨设备记忆协议未设计前不传播本地许可或决定，另一设备不自动获得权限。

跨会话聊天采用有向、需审阅的快照许可：目标会话只能读取用户批准时的源消息上界，后续消息不自动共享；源内容修改、归档、关联知识页失效或目标结束均重新检查。许可通过既有版本绑定审阅卡授予/撤回，模型不能直接扩大范围。记忆确认、纠正和删除同样复用审阅卡，避免另起一套公开桥接 API。

## 模型适配与信任边界

所有模型都接受同一来源、版本、引用、人工覆盖保护和使用许可约束。研究中的特定模型结果仅用于提出提示词实验，不使用 tokenizer、供应商名称或未经验证的通用智力分数分“可信/不可信”档。

默认使用短任务、显式 schema、来源白名单和有界输入。若评测表明另一套引导有效，按确切模型/版本和任务类型记录 profile，可由用户覆盖；模型别名或版本改变后重新验证，未知配置用保守模板。profile 只调整生成提示和任务拆分，不降低任何模型的校验要求，不把所有调用描述成已证明的简单任务。

确定性保障覆盖结构与生命周期，不能消除误读、遗漏及错误推断。自动发布参考知识仍存在语义污染风险；个人背景使用、用户确认和规则执行另有更严格边界。自审与人审降低风险，不承诺零错误。

## Alternatives considered

- 将所有请求上下文直接转换成长期记忆：会把历史原话、参考观点与瞬时业务状态混成个人事实。保留各类来源通道，统一记忆身份与资格，并新增本轮使用可见性；对比的是同一条目的身份、版本和供给状态，不要求管理列表与请求载荷条数相等。
- 只用聊天工具管理或让页面直接修改记忆表：前者难以浏览多个会话，后者绕过既有版本审批。采用独立人工读取接口与原审批执行器；批准使用原预览 token，失败后需重新查看，不自动换 token 重试。
- 先新增常驻画像页、每 tick 生成并人审：重复已有目标/习惯信息，失效期间继续注入且增加维护负担；先修召回与来源检查，索引后置并可重建。
- 两个事件/不同批次就升级 verified：重复转述与 AI 派生可能同源；分别表达用户确认、证据支持、谱系与当前有效性。
- 模型自由写文件夹：文件/数据库本身不决定信任强度，但无版本/来源/授权契约的自由写入不符合现有边界；沿用 Core 受控写入。
- 所有知识都加一次人审：会改变现有自动参考发布产品行为，且人审也不能保证真实；明确不同发布/使用通道，重点保护个人偏好与执行授权。
- 只搜索原始 transcript：可作基线和回退，跨事件归纳成本较高；保留有依据的派生知识，再用等预算评测确认何时有收益。
- 仅以“换一个主对话”验收记忆：当前产品持续复用单一主对话，无法覆盖翻篇后遗忘；以历史讨论片段召回为核心，跨会话引用和跨来源检索分别定义，不默认共享三类完整历史。
- 任何可重新推导的信息都不保存：会丢失跨记录形成的经验、稳定偏好和反例；仅避免重复持久化可直接读取的瞬时业务状态。
- 单页压缩比、全文 30% 差异、模型家族和访问热度作硬质量门槛：这些信号不等价于正确性；版本/撤回即时生效，其余阈值需要数据。

## Acceptance criteria

### 8.1 M0 固定基线

先准备至少 24 个经过人工标注的脱敏/合成场景，每类至少 3 个：历史偏好召回、相关旧经历、时间变化、明确纠正/否定、冲突澄清、同源重复、来源失效、跨多来源归纳。分别标记同会话历史召回与跨会话引用；至少覆盖主对话翻篇后召回、近期指代、后续纠正、讨论未采纳、跨范围隔离及无命中/歧义。每题冻结问题、输入版本、预期可用/禁用证据、允许结论与应答未知。合成工程集与后续真实材料集分别记录。

对照至少包括“现有链路”“来源过滤+任务检索”“再加注入索引”，使用相同模型版本、问题、原始材料和总 token/请求预算；维护调用计入成本。先记录基线再设召回/质量改善目标，不能挑成功问法替换原失败题。

### 8.2 不允许退化的场景

| 场景 | 必须观察到的行为 |
|---|---|
| 明确偏好 | 一次用户明确确认可以成立，同一主对话翻篇后仍可按需召回；跨会话引用另核对使用范围，不要求用户重复说两次 |
| 同源重复 | 同一错误的两次记录/两份摘要不增加独立支持，不自动升级使用许可 |
| 来源不支持 | ID/引文真实但不支持结论时，不能标为已证明；保留待评估/不足与人工反馈 |
| 偏好纠正 | 下一次最终模型请求不含被替代的当前偏好，即使旧索引存在、新摘要未生成 |
| 历史与纠正同在 | 原话仍可回查，但当前背景不含旧结论；历史被装入时保留纠正关系，预算裁剪不留下无纠正的旧定论 |
| 人工否定/删除 | 重新分析、重新索引、换模型或重建后不自动恢复；显式重新认可另记决定 |
| 失效与历史 | 撤回来源、归档、规则到期、目标结束后不作当前背景；显式历史查询可说明旧版本 |
| 请求竞态 | 检索后发生纠正，组装请求时过滤；已发送请求保留当时版本，返回不能直接发布新事实 |
| 矛盾与未知 | 双方来源均可回查；不按 confidence、事件条数或较新更新时间静默裁决 |
| 长材料自审 | 披露未覆盖范围；未读全不声称所有断言/来源都通过 |
| 注入与访问 | 最终预算外条目不记注入，重试幂等；自动注入计数不能让自身排名上升 |
| 前台与失败 | Provider 失败、无预算、租约过期不阻塞录入/对话，不提交半成品或覆盖人工结论 |
| 索引降级 | 缺失/损坏/过期缓存不恢复失效 top-5；可以不注入背景 |

来源/生命周期/授权和上述竞态规则在工程固定集中要求全部通过。自然语言支持判断另报告人工评分与失败案例，不把程序断言通过写成事实正确率 100%。

### 8.3 质量与运行验收

逐题记录相关证据召回率、回答支持度、失效事实误用数、正确澄清/拒答、纠正后仍复用旧结论数；同时记录用户每周新增审阅量、误报、端到端耗时、token、维护请求和费用。命中材料但答错与没拿到材料分开归因。

实际使用验收沿用[真实材料测试口径](../../../testing/llm-wiki-real-world-testing.md)：连续至少 7 天观察，主用模型及其他至少 2 个模型配置分别记录确切版本、供应商与运行结果。尚未执行不填写成绩；不足 3 个配置只能声明已测范围，不能外推跨模型。个人数据库不用于自动化测试；真实材料只在用户授权范围内另行验证。

## Risks

- 自审与人审都会误判；保留原文、有效时间、版本与可撤回决定，避免“通过审阅=外部真相”。
- 来源独立性在个人记录中通常未知；首版承认未知，不靠 SQL 计数制造确定性。
- 全局注入可能带来无关偏见和跨域泄漏；最小索引、会话隔离、来源过滤、等预算对照和可关闭入口共同约束。
- 自审、常驻索引与活跃目标偏置可能消耗模型预算或挤压普通材料；显式配额、老化、前台让路与完整成本记账必须先于放量。
- 人工决定与派生缓存生命周期不同；重建只重建派生物，不能清掉纠正、否定和使用许可记录。
