# Agent Note: Wiki 采用流程与数据规模

Status: proposed

## Problem

主题整理不能整批撤销；阅读、产物采用和建议反馈缺少持久状态。队列分页在 Rust 内进行，列表加载全量正文，知识依赖反复计算全文指纹，数据增长后延迟与内存开销增加。

## Proposal

补齐整理历史和带并发保护的撤销、自动准备下游复核及批量人工确认、阅读状态、产物版本与采用、建议反馈。SQLite 继续承担事务与查询，依赖变化用单调版本号快速筛查，最终确认保留完整依据指纹。队列与浏览查询在数据库筛选和分页。

## Alternatives considered

- 改成服务端数据库或分布式队列：当前本地单用户场景不需要，增加部署与一致性成本。
- 自动采纳所有下游修改：会抹去人工判断，采用后台准备、人工批量审阅。
- 撤销时直接覆盖现状：会丢失后续编辑，改为校验整理后的完整状态并事务撤销。

## Acceptance criteria

功能可在 Flutter 使用；旧库升级保留原始内容；拒绝过期确认与不安全撤销；隔离 Rust/Bridge/UI 测试通过。用合成大库测量分页和队列路径，说明实测规模及剩余瓶颈，不把模型效果当作性能证明。

## Risks

历史产物缺少生成指令和模型只能显示未知。大规模全文词法查询仍需要索引方案；不宣称支持无上限数据量。
