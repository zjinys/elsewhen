# 拟议需求：对话里的"查看今日记忆"（真检索，非推断）

**状态**：proposed（待实现）
**提出日期**：2026-09-15

## 背景 / 触发

用户在对话中问"给我看看我今天的记忆？"，AI 回复"今天的唯一记忆是你用 opencode2 讨论了一下项目的一些需求……"。

经排查，该回复**不是检索结果，而是 LLM 的推断**——`src/ai/memory.rs` 的 `prepare_context` 只加载**当前会话**的消息（`store.list_messages(conversation_id)`），没有任何 events 表 / 今日事件聚合 / 知识库内容进入上下文。模型只是把对话历史里唯一一条用户消息转述了一遍。

## 目标

让"看今天的记忆"变成真功能：AI 能基于**真实事件记录**回答，而不是从对话历史猜。

## 设计要点（初稿）

1. **数据来源**：`events` 表（`src/storage.rs`，有 `occurred_at` / `recorded_at` 时间戳），是个人事件唯一真源。
2. **注入方式**：`prepare_context`（`src/ai/memory.rs`）在 system 帧之后注入一段聚合的"今日事件"上下文（如 `date('now')` 的 events 摘要：时间 + raw_text），按需可含昨日/某时间窗。
3. **遵循既有三权分立与 prompt 铁律**：
   - AI 只做呈现/串联，不评价事件本身。
   - 不把事件聚合等同于"事实总结"；提示词里需说明这是原始记录快照。
4. **边界**：
   - 单日事件过多时需截断（token 预算，复用 `estimate_tokens`）。
   - 事件为空时如实说"今天还没有记录"，不编造。
5. **后续可扩展**：`applicable_when` + `strength`（知识库条目）按时间窗加权注入；日期/时间窗参数化（"上周"）。

## 验收标准（建议）

- 当天有事件时，问"我今天记了什么"能列出真实事件条目（来自 events 表）。
- 当天无事件时，明确回答"今天还没有记录"，不编造、不评价。
- 回答仍遵守 1-2 句风格与"零评价工具"铁律。
