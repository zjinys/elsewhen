# Agent Note: 在实际叶原文中定位模型逐字引文

Status: implemented

## Problem

真实 `gpt-4o` 合成长事件验收中，模型正确复制了事件事实引文，却把原文字符坐标算错。原实现按模型坐标截取再比较，因此拒绝该响应为 `event_reading_quote_forged`。拒绝保护了来源，但单靠模型数 Unicode 字符让合法阅读难以完成。

## Decision

叶阅读输出解析后，`locate_leaf_quotes` 只在该叶实际发送的 Unicode 原文范围内定位引文。若模型给出的范围与逐字文本完全匹配，则保留原范围；否则要求引文文本在该叶原文中逐字存在，由代码将本叶第一个匹配写入规范 `[start,end)` 坐标。重复文本采用可复现的首个位置，不声称该位置唯一或是模型意图中的特定出现处；不存在或跨叶范围均拒绝，不改写引文文本。

规范化后的引文仍经过存储层逐字原文验证。合并不能借该定位逻辑新增引文：它仍只能继承子节点已经确认的引文及其坐标。单条引文保留 400 字限制及节点输出／缓存上限。

双语 `reading.policy` 增加具体事实、标识、日期／数量优先的摘录指导：泛化重复背景不必摘录，没有独特事实可返回空 quotes。既有 prompt bundle 继续绑定旧 revision；新任务固定新策略及依赖指纹。

## Alternatives considered

- 放宽坐标校验或任意截取原文：无法证明模型引用的原始范围。
- 用全文查找第一个匹配：会跨越实际发送的叶范围；规范定位只能在本叶原文内。
- 拒绝所有重复引文：真实模型即使正确复制片段中的文字也会反复失败；相同文本在同一已读片段的首个逐字位置同样可核验，因此采用规范首位置，不能声称位置唯一。
- 修改固定 v1 协议或既有 bundle：会改变进行中任务策略；本次沿用协议字段，只增加本地可验证的位置确定逻辑及新任务策略指导。

## Consequences

模型无需精确心算字符数即可提交逐字可核验的真实引文，规范位置仍由不可变原文决定。不存在或越界的伪造证据继续失败退避；真实模型可能仍因重复背景、摘要丢失等原因无法验收，不能因为坐标修复而宣称质量已通过。

## Testing

`cargo test --lib event_reading -- --test-threads=4`：38 通过。新增回归覆盖合法引文的坐标规范化、范围外引文拒绝、重复匹配的规范首位置、正确坐标的重复原文保持有效，并保留已有伪造／合并继承／迟到结果回归。真实模型初次失败细节与后续验收结果见[验收记录](../../../testing/2026-11-09-long-event-real-model-acceptance.md)，真实模型质量不由脚本测试代替。
