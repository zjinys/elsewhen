# Agent Note: 洞察浮现取消每日 1 条限额，改由主题级去重控噪音

Status: implemented

## Problem

用户反馈「每天启动 AI 都会发这条消息」：认知洞察卡片每天弹一条，内容看起来总是同一主题。排查确认根因不在浮现层，而在生成侧——

1. 后台洞察每天成功跑一次，模型对同一批事件换措辞复述同一主题（实例：11-02 `insight/闲置ai算力转化为跨平台内容生成服务` 与 11-09 `insight/将闲置ai算力包装为跨平台内容生成服务提升发布收益`），标题逐字不同 → slug 不同 → 绕过「同页终身一次」的 slug 精确去重，登记为新候选；
2. 浮现层「全局每日最多 1 条」把重复主题滴灌成每日一弹，用户逐条「知道了」也断不了源头。

## Decision

两处改动（2026-11-11）：

- **生成侧主题级去重**（`knowledge_background.rs::generate`）：新洞察标题对 `list_insights()` 最近 300 条历史标题做归一化 bigram Jaccard 相似度比对，≥0.45 视为换措辞同主题，整条跳过——不建 wiki 页、不入浮现池（含同批累计去重）。提示词仍只挂最近 20 条标题（`past`），去重窗口独立放宽。
- **浮现层取消每日 1 条**（`storage/digest_insights.rs::tick_digest_insights_at`）：删除 `surfaced_date` 当日计数门槛；候选在 07:00–22:00 窗口内按最老优先全部浮现。静默窗、owner 主设备单写、72h 过期、同页终身一次均保留。

阈值 0.45 用本地全量 47 条洞察校准：唯一真重复对相似度 0.52，其余不同主题对全部 <0.2，余量充足。只比标题、不比观察正文——实测真重复对的观察相似度仅 0.04，正文每次换词复述，噪声远大于标题。

## Alternatives considered

- **浮现层对台账标题做模糊去重**：拦截点太晚——重复 wiki 页已经建出来了，且台账只登记带行动建议的洞察（历史重复多数没进台账），覆盖不全。放在生成侧一次拦截同时解决建页噪音和弹卡噪音。
- **比观察正文 / 三元组 grams**：实测真重复对观察相似度 0.04，无区分度；三元组对短中文标题过严。标题 + bigram 是这批数据里唯一干净的信号。
- **保留每日 1 条、只加去重**：去重后重复源已断，限额只剩「拖慢真新洞察抵达」的副作用，无正收益；用户明确表示没必要限制。

## Consequences

- 收益：同一主题不再换措辞反复弹卡；队列不积压，启动时一次清空（新候选每轮洞察最多 3 条，真实新洞察会立即浮现而非滴灌）。
- 代价：主题语义相近但确有新意的洞察会被静默吞掉（换措辞即同题的判定天然误伤边缘案例）；阈值偏保守（0.45），宁可漏放不可错杀。
- 风险边界：`habit`/`recurring_cost` 候选登记路径（`storage/digest.rs`）不受此去重影响——它们由页面新建驱动、天然低频，主题误杀的代价（挡掉新习惯页浮现）高于收益。
- 浮现频次上限实际由生成侧兜底：洞察成功后 24h 节流 + 每轮最多 3 条不变。
