# Agent Note: 同步快照续传、owner 转发与后台公平调度

Status: implemented

## Problem

[同步检查](../../../testing/2026-11-19-sync-audit.md)复现四个问题：大快照跨轮次时源数据变化会永久拒绝旧请求；AI 队列排空与异常传播阻断同步；第三个成员没有直接配对密钥却被当作可直连 peer；积压查询的迟到响应覆盖已完成的锁定状态。

## Decision

### 同一快照始终上传同一份加密内容

迁移 v90 增加 `sync_snapshot_export_chunks` 与导出的 `cached_manifest`。导出器从一次 WAL 读视图生成全部加密分片和 manifest，在同一个本地事务中提交完成标志，提交前不向 relay 宣布快照。上传按已有 32 片窗口推进；下一轮或进程重启按 durable blob 游标读取原密文，不再重扫当前领域表拼接前缀。构建期的 frontier、logical clock 和名册修订一起固定。

源端继续录入、分析或编辑不改变在途快照，新增操作通过后续增量收敛。网络中断的缓存导出保持原请求 ID；relay 过期重建时，接收方累计重申已持久分片的 ack，避免从零重传窗口与接收方旧断点互等。重快照调度器每轮继续推进，不再等待导出卡死阈值。最终应用回执后删除本地分片缓存；撤销成员同样释放给该成员的缓存。缓存只保存加密分片，不新增 provider 明文落盘。

旧版本已经上传的部分快照没有稳定缓存，迁移将其置为 `aborted`；交接与重快照改用新请求 ID。无缓存且发生时钟漂移时仍拒绝续传，同时进入可重建的中止状态，一致性检查继续生效。新导出缓存完成后才允许跨逻辑时钟变化续传。

### owner 是加入设备之间的持久转发节点

采用现有配对流程实际建立的星形通道。加入设备只向签名名册中的 owner 发送本地操作，owner 应用后，在同一事务内把原操作放入其他活跃成员的发件队列。原作者、stream、sequence、payload hash 保持不变；每一跳用直接配对密钥加密，由本跳发送者签名。接收方仅允许受信 owner 转发其他活跃成员的操作，普通成员不能冒充其他来源，已撤销来源仍被拒绝。大操作分片使用本跳发送者作为信封身份。

`received_from_device_id` 记录回执应返回的上一跳。owner 对手机的应用回执只代表 owner 已持久应用并承担后续转发，平板自己的应用回执单独退休 owner → 平板的队列。转发操作的 sequence 不推进 owner 本地流的 GC 水印。加入设备的本地历史只由上游 owner 的确认约束，owner 保留收到的远端历史并负责分发。升级时补齐 owner 已收到但旧版本未转发的操作；加入设备把历史错误的成员间发送意图迁到 owner 通道，清掉无直连通道的待发送业务封包。

provider 配置保留原有版本冲突规则，先为所有已建立通道的接收方准备持久封包再冻结 revision；加入设备只要求其 owner 通道准备完成。当前状态在每轮向各有效 peer 传播。

发送队列优先投递成员名册，避免转发内容早于来源的授权名册到达后被拒收。后台按 relay / mailbox 一次扫描全部已配对发送者，避免有效邮件因为扫描时只配置一个 peer 而被误计为未知来源；每轮最多发送 8 个 peer 的游标持久轮转，超过预算的成员仍能获得后续轮次。

### AI 工作与同步交替执行，各自保留错误边界

保留 Rust 工作区租约串行保护，避免并发调用绕过配对、锁定或切换数据库边界。Flutter 在 AI 之前、有限分析批次和消化之间、以及 finally 都给网络同步一个轮次。AI 自己的退避不跳过网络同步；单次异常不再吞掉这一轮同步。原生后台分析每次最多一个分析任务或一个影子判定，Flutter 消化每次最多一个 native tick；有进展则排下一轮，避免队列持续增长导致网络永远排不上。单个在途模型请求仍受 provider 自身超时限制，同步不取消该请求。

### 异步查询绑定 UI 状态代次

同步设置与交接元数据读取记住发起时的 `_stateGeneration`。await 后重新检查代次、busy、关闭和加入状态；锁定、解锁或其他已发布状态更新发生后，旧响应失效。正常积压变化仍触发刷新，重复读数不触发无意义通知。

## Alternatives considered

- 只把快照时钟错误改为 abort：会在持续写入时反复重建大快照，重快照旧 ID 也仍会被拒绝；因此保存稳定密文内容。
- 去掉快照时钟校验、从最新数据跳过已传分片：可能混合两个版本；因此只有完整缓存才允许跨时钟继续。
- 给 Dart 再加一个独立 timer：Rust 仍串行持有租约，长 AI 批次期间它只能跳过；因此同时缩小 native 批次、在租约释放后执行同步。
- 只过滤未配对成员：第三台设备不再导致报错，但成员之间的数据和回执仍不会收敛；因此补齐 owner 转发链路。
- 自动建立所有成员之间的完整互联：需要新增密钥交换、relay 授权及撤销协议，本次使用已存在的 owner 配对信任边界。

## Consequences

四个阻塞/状态问题具备定向回归。代价是上传前增加一次完整的本地加密构建事务，以及导出确认前额外的密文磁盘空间（原文快照上限仍为 256 MiB，密文和 base64 会更大）。构建事务可能短暂等待或占用本地写锁，传输阶段不持有该写事务。owner 不在线时加入设备之间暂缓转发，原始输入仍本地保存；多设备部署应一并升级各端，旧客户端尚不支持 owner 转发的来源语义。

仍保留真人多端验收、应用后台/杀进程、低存储空间和大数据量设备观察。HTTP 跨轮次连接池复用、整轮墙钟预算属于后续优化，本次没有把它们标成完成。

## Validation
