# Agent Note: MCP 环境变量保持本机私有

Status: implemented

## Problem

待办复核确认命名密钥提案指出的缺陷仍存在：MCP 请求头不随快照导出，但 stdio 环境变量 env_json 被完整导出。环境变量可能含 API token，凭据因此随初始配对快照进入另一设备。已有测试只用空环境变量，没有覆盖这个出口。

## Decision

先交付该提案的 P0 凭据边界修复，后续 P1–P3 继续实现命名密钥、运行时引用与设置界面。导出仍保留兼容字段 env_json，但内容固定为 {}；接收旧版快照时，也不把其中的环境变量落到本机配置。现有本机行继续获胜，本机环境变量和请求头均不被覆盖。字段集合与快照版本不变。

整个环境变量对象视为本机配置，不根据 TOKEN/KEY 等名称猜测哪些值敏感。其他设备收到服务器定义后需在本机补环境配置；后续命名引用方案单独设计哪些模板允许跨设备携带。

## Alternatives considered

- 等整套命名密钥 UI 做完再修：现有导出路径仍会携带明文，优先收紧边界。
- 只过滤命名像 TOKEN/KEY 的环境变量：不能识别任意名称中的凭据，容易产生保护已完整的假象。
- 删除 wire 字段或升级快照版本：会引入无必要的配对兼容成本；空兼容字段足以停止导出，接收侧也可忽略旧值。

## Verification

- `cargo test --lib storage::sync::snapshot`：21 passed。测试检查加密前实际导出记录无环境变量/鉴权头凭据，完整快照导入得到空 env 与不信任状态，发送端与接收端自建配置保持不变；另构造旧格式记录确认接收侧忽略旧环境值。
- 变异验证：导出 SQL 恢复 env_json 原值后，`mcp_snapshot_source_records_never_include_environment_secrets` 在凭据泄露断言处失败；接收 SQL 恢复远端 env_json 后，`legacy_mcp_snapshot_environment_is_not_installed_on_a_new_device` 在空环境断言处失败。两次均还原修复后复跑快照集。
- 没有迁移、密钥读写、真实服务调用或个人数据变更；内部改动不增加 FRB API。
- 还原变异后 `cargo test --all-targets`：库测试 1,040 passed / 20 ignored，集成测试 2 passed，0 failed；同时覆盖前两项上下文预算与页内全文总结改动。变更 Rust 文件的 rustfmt、`git diff --check`、新增 note 格式/目录及本轮索引链接与数量检查通过。全库旧 note 格式问题不在本次改动范围。

## Consequences

新生成的快照不再带 env_json 的值；发送端与接收端本机已有配置不变。代价是非敏感环境变量也不跨设备携带，用户需要按设备配置。既有设备已收到的值、历史加密快照以及 command/args/url 中手工嵌入的凭据不由这次变更清理或迁移；不把本次 P0 宣称为完整命名密钥库。
