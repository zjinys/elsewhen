# Agent Note: 知识目录回灌导致上下文预算失败

Status: implemented

## Problem

2026-11-05 13:01 与 13:03 的两次失败均在首轮模型请求成功后发生。运行预算记录显示输入预算为 58,164 token，工具返回后分别为 68,225 与 72,296 token；第二次的 tool_result 段合计 53,727 token。历史摘要已存在，本轮没有 summary_unavailable 事件。list_wiki_pages 无分页地返回 204 页及其摘要，最近三个工具结果又被预算层完整保留，所以压缩旧历史不能解决这次失败。

错误提示仅凭会话消息数量超过 40 条就断言摘要尚未收敛，导致用户重复提交相同失败任务。原路线图 R2.5 所称的恢复实际上没有处理当前轮大型工具结果。

## Decision

知识目录采用 SQL 分页读取元数据，默认 10 条、最多 20 条，支持 kind 与 offset。标题限 100 字、摘要限 80 字，返回匹配总数、下一页参数及按主题检索/按 slug 阅读的指引。保留完整 slug、页面状态与证据限制，摘要截选明确标记。按最近更新顺序返回，以 slug 打破相同时间的排序并列，方便查看新导入资料。派生产物继续排除，正文不参与查询。

预算保护继续保留当前输入、最近完整交换、证据与工具协议配对；不通过扩大默认模型窗口或删除最近交换绕过检查。失败提示取消按历史条数猜测摘要状态。

## Alternatives considered

- 扩大 DeepSeek 默认窗口或降低 token 估算：不能约束目录随数据增长的体积，也不能保证任意代理真实窗口。
- 截断所有最新工具结果：可能破坏结构化证据与写操作回执；目录在生产端分页更能保持语义与续读能力。
- 再摘要旧对话并要求用户重试：已存在摘要，失败增量来自当前轮工具，不能修复根因。

## Verification

- `wiki_directory_bounds_output_and_supports_filtered_continuation`：长中文标题与摘要的目录默认返回 10 条、估算低于 6K token；kind 分页无重复地覆盖全部匹配页面；同时间排序、参数封顶、空尾页、派生产物排除与原文保留均有断言。
- `large_wiki_directory_allows_second_model_request_near_context_limit`：204 页、64K 窗口、初始请求超过 45K token，经真实 provider 装配与回环 HTTP 服务完成两轮请求，保留上一轮约束；将第二次请求替换成旧式全量目录后，原预算检查确定拒绝。
- `cargo test --lib wiki_directory -- --nocapture`：2 passed。回环服务需要沙箱外端口绑定权限；测试使用临时库，不以个人库作为自动测试夹具。
- `cargo test --all-targets`：库测试 1,032 passed、20 ignored；集成测试 2 passed；0 failed。忽略项沿用既有测试标注，未调用真实模型。变更文件的 rustfmt 检查与 `git diff --check` 通过。
- 个人库只用于人工只读取证；未重放用户任务、调用真实付费模型或修改历史消息。
- 新 note 通过技能提供的目录与格式校验脚本（Node 原生 TypeScript，临时目录单篇验证）；全库校验仍报告既有的 product/chore 分类及旧 note 格式问题，本次不修改这些无关文档。

## Consequences

目录输出体积不再随总页数增长，普通浏览无需现场生成额外摘要；代价是模型需要分页或改用主题检索，目录摘要不能替代原文。offset 分页在页面更新并发发生时可能有重复或跳项；它适用于模型临时浏览目录，不提供快照遍历契约。任意模型极小窗口、超长用户输入或其他超大工具结果仍可能触发最终保护，本次不宣称消除全部预算拒绝。
