# Agent Note: 知识消化的相关索引与中文正文预算

Status: implemented

## Problem

2026-11-08 用户报告知识消化所有 Provider 均失败：首选请求约54,527 token，超过54,068输入预算（窗口65,536，输出预留8,192）；备用渠道返回503。消化事件批次虽有限制，构造请求仍附带全库索引；相关正文用UTF-8字节计费，却用字符数截取，中文实际体积超过选材预算。通用请求边界正确拒绝了超限输入，聊天历史压缩无法修复单次后台任务的膨胀。

## Decision

Provider提供纯本地的完整请求预检，复用真实OpenAI/Ollama序列化、时间包装、模型token计数、窗口和输出预留，另留512 token缓冲。知识消化先装入完整事件和固定指令；放不下时缩小事件批次，随后按预检结果搜索可容纳的相关索引/正文。备用Provider重新构造自己的请求，不沿用上一渠道的材料量。全库索引/正文仍有24页与字节上限，作为调度成本上限，不能代替token预检。

事件不再静默截取前4000字后标记消化成功。成功渠道未提交的批次后缀退回pending，扣回本次未执行尝试，保持原Prompt bundle/语言策略；已提交前缀依旧整批校验、原子提交。单条完整事件与固定指令放不下时，后续[持久分块消化](../architecture/2026-11-08-long-event-chunked-digestion.md)自动建立阅读任务；固定指令自身超窗仍明确失败。原文不截断，只有全文覆盖及最终提议校验通过后原子确认；该增量不改变本修复的普通批次与完整预算保护。

每tick只读取一次页面快照；预算试算复用当前所选事件数的相关性排序，避免每次probe重复整库查询或缓存20份全文。正文按UTF-8边界截取，标题/slug包装也计入材料预算。中英文包装明确长页只提供节选，不推断未展示正文；legacy/bundle仍固定原版本。最终发送端预算检查保留，不增大窗口或降低估算。准备阶段预算错误不将健康渠道记为网络故障冷却；503仍属于远端可用性故障。

## Alternatives considered

- 增大默认窗口或缩减输出预留：无法保证代理实际容量，也不约束索引随库增长。
- 继续压缩聊天历史：后台调用没有可以移除的旧对话，根因在本次附带材料。
- 截断整个用户提示词：会截掉事件、编号或输出契约，可能造成来源遗漏；分别限制辅助索引和正文更可控。

## Consequences

消化附带材料不再随全库目录无界增长，中文正文计费与截取单位一致。代价是模型只看到相关页面的有限索引与正文节选；该索引不能替代全库检索。超长自定义固定指令、单条事件独自超窗、极小窗口及远端503仍可能失败，继续依原机制退避，不对个人失败任务进行手动重放或更改历史记录。
