# Agent Note: 知识页草稿创建幂等保护

Status: implemented

## Problem

`save_knowledge_draft` 只检查知识库中是否已有同名页面，不检查当前会话是否已有同标题待确认草稿。模型重复调用工具后，确认门会逐个执行这些草稿；执行时使用随机 slug，导致同一主题被保存成多张重复页面。

## Decision

知识页草拟阶段按「会话 + 动作 + 标题（忽略首尾空白与大小写）」去重，已有草稿时复用原草稿并提示用户确认。真正执行待确认动作时再次按标题查询知识库；若页面已存在，则报告已存在并跳过写入。双层检查同时覆盖模型重复调用、历史重复待确认动作和重复执行。

## Alternatives considered

- 仅把 slug 改为标题派生的固定值：只能依赖数据库唯一约束处理冲突，无法给用户清晰的幂等结果，也可能把不同类型页面耦合到同一 slug。
- 只在确认执行时去重：重复草稿仍会堆积，确认前状态不清晰，且重复动作会继续消耗处理机会。
- 只按完整 JSON 参数去重：正文或标签稍有变化就失效；标题才是创建知识页的业务身份。

## Consequences

同一会话重复请求创建同标题主题时只保留一份待确认草稿，确认或重试都不会产生重复页面。代价是同标题但确实想创建不同页面的场景必须先改标题，符合知识库标题唯一性的既有约定。新增 Rust 单测覆盖重复草拟和重复执行。
