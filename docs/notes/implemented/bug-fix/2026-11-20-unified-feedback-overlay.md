# Agent Note: 统一右上角操作提示

Status: implemented

## Problem

全局 `SnackBarTheme` 曾用左侧 120px 边距模拟右上角，但 Scaffold 始终把 SnackBar 布局在底部，也没有最大宽度。因此“已记录，并生成一条事件”等旧调用仍呈现底部横贯窗口的胶囊；只改少数成功提示入口无法消除其他页面的同类问题。

## Decision

`FeedbackToast` 在根 Navigator 的 Overlay 中显示操作提示，捕获调用方主题；全应用原 ScaffoldMessenger 操作反馈入口迁移到同一呈现器。保留 SnackBar 仅作兼容消息载体，读取 content、action、duration、persist 和 onVisible，不使用其布局或形状。桌面右上对齐，最大宽 400px；窄屏留安全边距，长内容最高 240px 内可滚动，颜色跟随主题，关闭目标 44px。

同一窗口只保留最新提示，自动过期或手动关闭后释放浮层和计时器；带 action 或屏幕阅读器开启时等待明确关闭，指针停留/按下时暂停计时。根浮层位于当前对话框之上，其余区域可继续操作。错误详情与撤销 action 保留回调。习惯记录成功使用 success 语义；错误入口用 error 语义。移除旧主题中误导定位的大边距，避免回退组件继续横向拉长。

## Validation

相关回归 46 项通过，包括桌面/360px 深浅主题定位、SafeArea、单实例替换/过期、弹窗上层、action 回调、长文本/大字号、习惯记录、消息输入与复制、创建主题、Scout、配对与设置。创建主题候选点击的关联修复见[规范化标签](../architecture/2026-11-19-normalized-wiki-tags.md)。消息测试的清理逻辑改为等待实际提示浮层退出。

使用本地中文字体与 Material 图标生成并检查 1200px/360px 深浅主题预览，确认中文、图标、圆角与真实阴影正常。提示文本继承应用 `bodyMedium` 字体及回退链，避免自建默认 TextStyle 丢失中文字体。提示与标签相关 9 个静态检查目标无问题。

额外运行目标页测试时，两项现有断言因“当前行动”在两个位置同时显示而失败（`goal_view_test.dart:408`、`:434`），与提示布局无关；本次不修改目标呈现或这些断言。全量 lib 分析仅余生成本地化文件的两个弃用提示；提示/标签相关静态检查无错误。

## Alternatives considered

- 继续调 SnackBar 边距或宽度：Scaffold 仍按底部布局；宽度还只能居中，不能保证右上角。
- 只替换截图中的习惯成功提示：其他几十个操作入口仍会使用旧位置；统一入口并迁移所有现有调用。
- 全屏遮罩或独立通知路由：会挡住底层操作或参与返回栈；使用只拦截提示卡片区域的根 Overlay。
- 自动移除带撤销/详情按钮的提示：用户可能来不及操作；带 action 或辅助阅读时保留到明确关闭。

## Consequences

操作反馈在主区、设置和弹窗中使用相同尺寸与位置，不再覆盖底部输入框。呈现器负责浮层与计时器生命周期；业务文案和保存结果仍由原调用方决定。兼容消息载体中的旧背景/边距/形状不再控制视觉。此修改属于 Flutter 客户端，需要重载或重新构建客户端生效，Scout 服务端部署不影响提示样式。
