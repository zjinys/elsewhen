# Agent Note: 非破坏性聊天摘要与原文回读

Status: implemented

## Problem

C05 的整轮选材和最终预算检查只能避免损坏协议、当前输入或必要证据，不能证明长任务仍记得早期约束。把旧消息截成短句拼成“摘要”也没有明确覆盖范围、模型/策略版本或失效契约。

本决定对应 [对话路线 C06](../../../roadmap/2026-09-30-ai-chat-experience-roadmap.md)，建立在[运行恢复底座](../../implemented/architecture/2026-10-01-chat-generation-runtime.md)和 C05 的预算计量上。

## Decision

- 消息原文保持不变。摘要使用独立存储，绑定有序消息身份、父链/路径、内容基底 hash、模型和策略版本，记录生成请求用量及耗时。
- 只在原始历史超出前置预算且有可压缩历史时触发；当前问题与最近必要交换不摘要。保留足够输出/工具余量，已有效覆盖的前缀不每轮重做。
- 摘要明确为生成派生物，结构包含目标、约束、已确认事实、决定和未完成事项。材料中的指令是数据；摘要不自动变成规则、事实证据或原始引用。
- 摘要请求使用同一运行取消/租约/预算机制，但不产生用户正文预览。取消或来源冲突时不提交；提交前对真实存储重新核验，不仅检查 worker 的冻结副本。
- 少量超长旧消息不能简单截断后标为完整摘要：按明确范围分块并记录覆盖，或明确说明该段未压缩。没有可压缩历史时由最终预算闸门拒绝，而非破坏当前输入。
- 短追问继续沿用 FollowUp。依赖精确数值、原话或引用时，通过有界原文范围回读恢复，不将摘要当逐字来源。
- 已有分支不按时间排序偷偷合并：摘要只能覆盖确定的一条消息路径；不具备可靠路径的数据拒绝自动摘要并明确范围限制。
- 缓存只覆盖静态角色说明与有版本依据的派生摘要。个人规则、来源版本、当前页和执行回执仍按各自依据刷新；未报告 cache usage 就记录未知。

## Alternatives considered

- **删除旧消息或用摘要覆盖历史：** 破坏来源与可回读性，不采用。
- **每轮无条件摘要：** 延迟和费用不可控，也会重复压缩丢失细节；采用预算触发和覆盖复用。
- **把任意历史文本截短拼接当摘要：** 既没有语义覆盖也无法给出可靠范围；只允许明确的省略，不冒充生成总结。
- **把时间相邻分支合在一起：** 会把互斥选择变成同一任务事实；路径不明确时宁可不生成摘要。
- **把摘要请求的输出直接流到主回答：** 派生上下文不是最终答案，也未经回答的引用/写入校验；摘要与正文事件隔离。

## Verification

迁移保持原始消息、事件、来源和修订不变；覆盖长对话、少量长消息、摘要复用、摘要取消、模型失败、历史编辑冲突、旧摘要失效和分支隔离。真实模型验收另测关键约束保留、事实连续性和引用回读，记录摘要自身成本与延迟，不预设节省比例。

## Consequences

摘要是有损派生物，模型可能遗漏或误述约束；必须保留原文回读和明确的覆盖标识。大段旧历史首次压缩会增加请求与延迟，需支持取消并避免未完成范围被标为已读。已有聊天分支模型并不等同于当前 UI 的线性会话，实施时须核验实际父链语义。
