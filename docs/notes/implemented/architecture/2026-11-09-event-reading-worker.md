# Agent Note: 超长事件的自动调度与只读阅读进度

Status: implemented

## Problem

[持久阅读与最终原子消化](2026-11-09-event-reading-finalization.md)尚需接入实际后台队列。长事件若重复占据最早批次，会堵住短事件；若每段都借用整事件失败次数，正常进度会进入失败冷却。界面也必须区分分段完成与原事件消化完成。

## Decision

追加迁移 `79-event-reading-scheduling`，阅读任务增加可调度时间、错误原因和轮转序号，单例 schedule 保存普通／阅读优先级及单调轮转计数。迁移只增加本地派生状态，不修改原事件、旧 bundle 或已完成节点。

### 自动转入与公平性

`process_digest_queue` 保留普通事件的完整请求预检、相关资料选择和有限 Provider failover。只有所有候选均未选中可发送输入，且至少一个候选能容纳空材料的固定消化请求时，才判定完整单事件需要持久阅读；网络失败后不能误判为需要分块。固定指令本身不容纳时继续返回配置预算原因，不无限切空节点。

首次转入只固定首事件阅读任务，将未发送批次归回 pending、扣回领取时的 attempts，并删除没有执行模型调用的临时 run，不伪造成功／失败运行记录。失败或非法提议的普通批次也按实际选中的前缀缩回，未选中的尾部恢复 attempts。

普通领取排除同 bundle 的 active／ready 阅读任务。普通和阅读队列轮换优先；没有该类可用工作时处理另一类。阅读任务按独立 last_tick 轮转，多条长事件互不长期占据队头。中间节点调用不领取整事件 job，不增加其 attempts。失败节点按节点退避，规划／配置失败保留原因并至少等待 120 秒；等待租约的任务延后 5 秒。

每次阅读 tick 只推进一个叶或合并节点。根 ready 后在下一次阅读机会领取单事件最终消化批次，复用完整根并使用原 job 的失败退避／冷却语义。最终成功清除旧错误。分类撤销取消阅读；再次明确可记录后恢复原缓存、撤销旧调用代数并清除旧调度等待。

API 在恢复中断 digest jobs 时保护具有有效当前权限租约的最终请求；过期／权限失效的最终批次回队，根缓存保留。节点恢复和最终恢复均拒绝旧代数回执，不因普通 API 打开连接而重放已完成节点。

### Bridge 与界面

FRB 增加 `KnowledgeDigestTickResult::Reading` 和队列行可选 `KnowledgeDigestReadingDto`，包括阶段、已读／总字符、完成叶／合并数、失败详情和重试时间。应用 worker 收到 Reading 就结束当前排空循环，交给后续定时 tick，不在一次循环读完整事件。

现有知识消化队列每 5 秒只读刷新，防止重复并发加载，关闭后取消 timer。显示原始事件摘录、分段／合并计数和等待原因；ready 显示“全文已读完 · 等待最终整理”，不能冒充事件成功。预算／限额／其他失败分别给出中英文解释；不新增后台触发或手动重试按钮。显示语言热切换只重新渲染文案，不修改任务 bundle。

## Alternatives considered

- 将每段推进计为普通 batch 失败：正常长事件会用尽 attempts，使用独立节点语义。
- 始终优先最早事件：长事件会长期堵塞后面的短事件；采用普通／阅读轮换和阅读任务间轮转。
- 将首次转入标成运行成功：事件尚未完成；未调用模型的临时 run 删除，真实进度保存在任务与节点。
- 每次 API tick 无条件恢复 running：会撤销有效最终网络请求；保留当前权限下的有效租约，只恢复过期／失效批次。
- 在测试中让 FRB 全局入口初始化两次：同一 Dart isolate 不支持；隔离 helper 重新初始化同一临时库，真实进程重启保留在 E6。

## Consequences

应用可自动发现超窗事件并跨后台 tick 完成阅读、合并与最终消化，短事件与其他长事件持续获得处理机会。代价是新增调度元数据和进度 DTO；细分阶段依赖现有 5 秒 worker，应用必须运行。极小窗口、超大自定义指令及缓存限额仍可明确等待，不能通过删除尾部材料解决。

真实模型语义质量、实际进程重启／设备验收仍属于 E6，不将合成 HTTP 通过称作模型验收。
