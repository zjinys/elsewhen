# Agent Note: 上下文选材与最终预算边界

Status: implemented

## Problem

仅按正文字符裁剪无法计入工具 schema、原生调用与输出预留；提前删除旧轮还可能隐藏损坏的 call/result 交换。必须区分可选背景、原始历史和必要证据，且不能将预算省略称为语义摘要。

## Decision

对应[对话路线 C05](../../../roadmap/2026-09-30-ai-chat-experience-roadmap.md)。`ai/memory/segments.rs` 为上下文记录用途、来源、内容版本、身份 hash 和省略策略。前置选材采用 provider-aware 计量并预留工具 schema，先移除可选跨会话背景，再按完整用户交换保留历史；当前问题、规则、页面与验证所需证据不截断。无法容纳时由最终完整请求边界拒绝，要求缩小任务范围。

`ai/budget.rs` 始终计量最终序列化消息、工具定义、安全余量和输出预留。原生工具身份在裁剪前后验证；前置选材发现损坏交换时保留原上下文，由最终边界明确报错，不允许靠删除旧轮隐藏错误。SimpleMemory 的消息数量是软上限，边界向前扩至用户轮开头。

分段预算、省略计数和原因通过运行请求事件记录；只保留身份 hash、类别和数值，不记录正文、参数或密钥。显式上游超窗口拒绝仍仅允许一次缩窗重试；本地必要上下文超限与上游拒绝保持不同原因。

## Alternatives considered

- 仅保留最后 N 条消息：可能截断工具交换，因此数量只能作软限制。
- 前置选材替代最终预算检查：无法覆盖动态上下文、序列化及 provider 差异，不采用。
- 自动截断长问题/页面以通过预算：损坏任务和证据，宁可明确拒绝并要求缩小范围。
- 把被截取的旧消息叫摘要：缺少语义覆盖与基底，真实摘要由 C06 独立实现。

## Consequences

已知 tokenizer 使用本地 BPE，未知模型使用保守 bytes，安全性可能以可用上下文长度为代价。必要证据较大时请求可能拒绝，而不是制造表面成功。分段计数属于本地估算，不冒充服务商计费。

验证包含 `budget/exchange_tests.rs` 的完整请求、配对与必要证据场景，以及 memory 的可选背景优先、未知模型、整轮保留和早期损坏交换回归。最新执行结果记录在路线图；真实模型质量不由这些工程测试证明。
