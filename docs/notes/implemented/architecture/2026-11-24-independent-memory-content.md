# Agent Note: 对话记忆正文独立于知识页

Status: implemented

## Problem

旧 claim 通过 page_slug 指向知识页正文，导致设置页修改、后台自审、召回各自依赖整页 hash。新增 content 后，单纯改 UI 并不能让模型使用新正文。

## Decision

personal_memory_claims.content 是独立正文。搜索、详情、有效性、自审和替代审阅优先读取它；没有正文的旧记录继续回退。94 增列，95 回填但不覆盖已有正文，96 保存增量提取游标。profile/me 保持个人档案知识页。

后台保守提取只接受用户消息，候选写入、成功账本与游标同事务提交。候选默认 pending；明确反向偏好标为 conflicted，保留已确认记忆。编辑使用版本校验并同事务记录前后正文，删除/否定/替代状态不能由编辑恢复。

## Alternatives considered

拒绝把全部记忆追加到 profile/me：独立编辑会影响整页关联 claim。拒绝仅修改展示摘要：展示和召回会分叉。拒绝按相似度直接覆盖确认内容：相似表达可能携带否定或不同范围。

## Validation

Rust personal_memory 定向测试覆盖无知识页编辑召回、版本冲突、删除保护、增量幂等、写入失败回滚、禁用类型与明确反向偏好。迁移专项验证旧正文回填、已有正文保留、缺页保持 NULL 和重复初始化。Flutter 页面回归 12 项通过，定向 analyze 无问题。

语义关系分析在写事务之外执行，每次最多读取本会话 40 条、每条不超过 600 字的已有记忆。关系限定同类型、主题和谓词；事务内重新校验完整 claim 快照。等价候选复用旧记录，补充只替代仍有效的未确认候选并合并消息依据，冲突标记新候选，不覆盖人工正文。无效模型输出保留为独立 pending 候选。新增测试覆盖双来源合并、人工修改保护、删除抑制、冲突及分析期间的并发修改。

## Consequences

设置管理列表覆盖普通、目标与知识页会话；来源分类只用于显式筛选，不隐式隐藏非普通会话候选。管理可见不等于跨会话召回授权。全局去重命中外部会话时，对话工具不返回其标识或状态，语义整合不更新外部记录。

自动补充合并保留全部依据，并遵守已有 8 条依据上限；达到上限时保留独立候选，不截断证据来换取合并。词法补充也要求旧候选来源仍有效，避免把失效来源传播到新版本。

设置页、召回及维护统计共享独立正文。删除/否定后的列表、详情及编辑历史响应隐藏正文，数据库保留内部抑制记录和审计信息。语义关系分析增加一次有界模型请求；模型分类仍可能有误，因此自动合并只影响未确认候选，用户确认内容保持不变。路线图逐项验收及全量回归结果见 [验收报告](../../../testing/2026-11-24-conversation-memory-acceptance.md)，专项通过，仓库全量仍存在已记录的基线失败。
