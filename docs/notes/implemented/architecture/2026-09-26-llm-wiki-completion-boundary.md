# Agent Note: LLM Wiki 完整闭环的实施边界

Status: implemented

## Problem

最初的 LLM Wiki v1 能维护知识页、生成洞察和在对话中按需搜索，但可靠触发、统一来源和知识使用的可解释性没有闭合。自动事件消化随后落地，剩余断点是导入材料缺少独立版本、知识缺少出处、人工修订与来源更新没有统一审阅流程。直接照旧来源层路线图实施，会重复现有导入并忽略有界项目盘点。

## Decision

SQLite 保持唯一真源。`04-knowledge` 增加来源身份、不可变快照、页面来源关系、知识适用条件、待审建议、引用审计和自动洞察账本。`Store::open` 在迁移后单独事务回填存量来源；不修改冻结基线和迁移发现器。URL 规范化后去重，推文按推文 ID 统一身份，无 URL 的粘贴文本按 SHA-256 去重。显式文件使用 file URL；旧文件页从已有固定路径字段恢复出处，不读取用户目录。

方法、案例、规律和页面修订先保存建议，用户确认才写页。建议保留来源版本、事件 ID、目标正文 hash 和拒绝记录；确认时在事务内复查来源及目标版本。相同来源版本与目标正文的拒绝决定不会因模型改写措辞反复出现。人工持有页的 digest 只积累证据并留下建议，标题、摘要、标签与正文都受保护。修订后的方法降回 reference，规则需要重新确认。

`src/knowledge.rs` 供主/页内对话、搜索工具、事件分析、话题方案、每日回顾和自动洞察共用。检索最多读取 80 个候选、选 6 页，结果按调用方预算且不超过 12,000 字；适用条件参与检索，拒绝或来源过期的页面排除。每轮对话含工具参数和结果限制为 24,000 字。`[[kb:slug]]` 只在系统实际提供且仍有效的候选中解析，未知标记移除；审计分别保存选材和实际引用，并保留当时的片段与来源版本。

自动洞察在原 worker 排空分析和消化后执行，固定四透镜仍兜底；14 天内最多 60 个事件、原文最多 6,000 字，最多 3 条洞察，允许空结果。成功每天最多一次，相同输入不重复生成；失败退避、连续失败冷却，进程中断由十分钟租约恢复。洞察页面、出处、审计和成功账本同事务提交，旧的独立洞察生成写入路径移除。

GUI 增加“来源与修订”“提炼知识”“审阅本页”“知识审阅”和回答“引用依据”。重复 URL/推文导入对照旧原文后确认；推文整理稿单独保存为产物。显式文件模式先读取预览，确认只写当时读取的版本，每批最多 100 文件、240,000 字，每文件最多 12,000 字，超限跳过并报告；项目模式原有扫描边界不变。

FRB 自动生成文件只由生成器维护；Dart 手写代码统一引用 `bridge/api.dart`，避免每次生成抹掉手补的 export。

## Alternatives considered

- 继续靠用户手动执行 `wiki digest`：不需改队列，但知识积累取决于用户记得运行命令，无法成为日常闭环。
- 在每次事件记录时同步调用模型：看似即时，却使原始事件保存依赖网络和 Provider，不符合当前异步分析边界。
- 直接执行旧 `sources` 文档的全套新表和 CLI：会与已落地的 `source` 页和导入流程形成双份来源，也没有解决先前事件遗漏问题。
- 让模型自行挑选所有材料或先引入向量数据库：缺少可解释的适用性与预算边界；现阶段可先利用已有搜索和结构化条件验证质量。

## Validation

- Rust 临时库覆盖 v3 升级、旧来源/派生关系、重启幂等、URL/推文去重、快照不可改、文件预览、过期确认、持久拒绝、人工编辑、规则确认、引用白名单与工具上下文预算。
- 消费通路覆盖真实 agent 工具轮次、每日回顾实际引用、话题出处、自动洞察空结果/非法来源/成功提交/退避/租约恢复。
- Flutter mock widget 覆盖查看原料、接受/拒绝、来源冲突、窄屏和取消导入；真实 Bridge 使用 `isolated_bridge.dart`，测试来源历史及本机 HTTP Provider → 建议 → 确认 → 规则强度。测试不使用个人数据库或外部账号。
- `new_migrations.rs` 的目录清单与最新版本断言已对齐 `04-knowledge` 和版本 4，迁移发现逻辑及冻结基线保持原样；显式断言继续校验预期的完整迁移集合。Rust 全量 246 项通过，包含迁移 SQL 自检与 v3→v4 数据测试；Flutter 此前全量 199 项通过，主分支本次定向复验 12 项通过。具体运行结果记录在 FR-PES-004 的实施记录中。
- [实际效果测试指南](../../../testing/llm-wiki-real-world-testing.md) 按用户要求使用当前数据库的一致性备份，以现有原料、外部文章和旧方法页为样本，在新对话中对照提炼前后回答，分别记录准确度、实际引用与版本纠错。已检查副本结构和来源缺口；真实模型和 7 天使用评估尚未执行。

## Consequences

旧页面和历史原文可追溯，人工定稿不会被后台更新吞掉；代价是追加式快照和审计占用更多本地空间。来源过期会减少可引用材料，直到用户审阅确认。

当前检索是有界关键词与适用条件匹配，不承诺语义召回完整；引用核验证明材料确实提供给模型且出处有效，不证明模型论断必然正确。长日结输入超过预算时明确失败，不静默截取成“完整回顾”。目录文件预览只展示前 6 个文件的限长内容/差异，超限文件可分目录再次导入。长期使用中的质量与空间增长仍需独立观察，不能由离线测试代替。
