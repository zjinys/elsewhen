# Agent Note: 对话 AI 角色分层

Status: implemented

## Problem

主对话需要像熟悉用户情况的个人秘书一样提供记录、回顾和陪伴；知识页对话则需要像专业导师一样围绕页面内容进行质疑、校验和修订。此前两者共享同一个基础 system prompt，知识页仅追加页面内容，导致角色边界不清。

## Decision

会话在存储层增加 `assistant_mode` 字段，主对话使用 `personal_secretary`，知识页会话使用 `knowledge_mentor`。导入内容的临时对话不落库，但使用同一套专业导师提示词定位。Flutter bridge 暂不暴露该字段，因为角色由会话创建路径决定，不需要用户手工选择。

`knowledge_mentor` 使用额外的严谨审稿指令，并停止注入跨会话近期用户消息；页面内容和页面修订能力仍保留。旧数据库中的知识页会话即使字段默认值为秘书，也会通过 `wiki_page_slug` 兼容识别为导师，避免依赖迁移执行顺序。

数据库迁移使用版本 30，普通新会话默认写入秘书模式，知识页新会话显式写入导师模式。

## Alternatives considered

- 仅依赖 `tag=idea`：语义不稳定，且 tag 是用户可见分类，不适合作为 AI 行为契约。
- 仅在 prompt 末尾追加几句“你是导师”：无法控制跨会话记忆注入和旧会话兼容，角色边界仍然脆弱。
- 把角色模式暴露给 Flutter 让用户选择：当前场景的角色由会话类型天然决定，开放选择会增加错误配置面。

## Consequences

主对话继续保留原有陪伴、跨会话回忆和主流程工具；知识页对话拥有更明确的专业导师行为，并避免无关的跨会话回忆。当前工具注册表仍是共享的，导师角色的工具限制主要通过 prompt 和上下文边界实现；若后续需要更强隔离，应继续按 `assistant_mode` 过滤工具注册表。

验证：`cargo check` 通过；`cargo test --lib` 通过，138 个测试全部成功。
