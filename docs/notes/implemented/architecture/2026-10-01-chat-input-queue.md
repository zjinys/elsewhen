# Agent Note: 已保存输入的持久生成资格

Status: implemented

## Problem

当前 run 只允许同会话一个活动生成，但用户在等待期间仍需保存输入。UI 内存中的排队无法解释重启、撤回、停止与重复请求，也不能让旧 run 读取后来提交的消息。

## Decision

对应[对话路线 C08–C09](../../../roadmap/2026-09-30-ai-chat-experience-roadmap.md)。队列只存已提交消息的身份和资格，不复制正文。保存继续走已有输入幂等事务；队列与 run 领取在 SQLite 写事务内裁决，同会话 FIFO，唯一消息资格和稳定 run key 防止重复派发。

停止同时冻结会话派发；继续必须显式操作。撤回仅取消未消费的生成资格，不删除事件或消息。重启不自动恢复派发，显示待处理项供继续；不确定业务动作沿用已有回执规则，绝不自动重放。

steering 采用单独明确的模式，仅在工具轮完成之后、下一次请求前注入。注入记录与消费资格同事务，预算或材料不兼容时保留普通排队资格。

## Alternatives considered

- UI 数组保存消息正文：无法恢复且复制身份，不采用。
- 停止后立即启动下一项：违背停止语义，必须冻结派发。
- 撤回时删除原消息或事件：违背原始记录不可变，撤回只影响生成资格。
- 自动把所有输入并入当前 run：改变已冻结的上下文截止点，必须显式选择补充任务。

## Verification

覆盖 FIFO、重复投递、并发领取、撤回、停止竞争、重开、会话删除和稳定 run 身份；两个入口生成时均可保存且不等待模型。steering 另覆盖预算不足、附件、取消和崩溃，不能双重消费。

## Consequences

持久领取与线程启动之间可能崩溃，必须保留 interrupted 身份而不是自动重做。消息保存成功但队列登记失败时 UI 必须告知已保存但未排队；重试复用同一消息，不重新创建事件。
