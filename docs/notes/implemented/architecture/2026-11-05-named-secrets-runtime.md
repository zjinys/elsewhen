# Agent Note: 命名密钥本机存储与运行时引用

Status: implemented

## Problem

多个 MCP 共用凭据时需要逐个修改，配置没有独立的凭据生命周期。P0 已阻止环境变量随快照传输。

## Decision

复用迁移 70 与 provider master/CHACHA20-POLY1305。密封安装写入密文、plaintext 置空；未启用密封的安装沿用现有 provider 策略保存明文，启用密封时事务内补封。AAD 绑定数据集、installation、id 和不可编辑代号。列表只返回名称、备注和引用位置，不返回值。

MCP 环境变量在启动前解析，HTTP 会话保存引用模板、每个请求构造时解析。搜索工具在构造引擎前解析 API Key。缺失、锁定、无效引用均阻断。管理 API 保存/删除后作废 MCP 会话，轮换后重连。named_secrets 继续排除同步；P0 的 env/headers 全量本机边界保留，新设备需要本机配置。

设置 → 安全提供密钥管理、轮换、引用列表与删除确认；MCP JSON 编辑器按光标插入引用。新增密钥时可勾选精确匹配提取：在同一事务中替换 MCP env/header 值及搜索 Key。只匹配完整值，不猜测敏感字段，不扫描或回显现有明文；已有代号拒绝提取覆盖。带 Bearer 前缀的旧 Header 需要手动改为 Bearer {{secret:name}}。

## Alternatives considered

批量替换明文无法建立共享引用，舍弃。HTTP 会话缓存解密 Header 会延长明文生命周期，改为每次构造请求解析。自动按字段名称提取有误识别风险，改为用户提供精确值并显式勾选。

## Consequences

共享凭据可集中轮换，列表与引用审计无需解密。未配置密封的安装仍使用明文列；身份清除沿用既有边界，清除旧身份绑定的密文，需重新填写。界面不提供读取/复制旧明文，轮换需要填写新值。未来插件可调用同一个解析器，目前接入 MCP 与搜索。

## Provider 表单联动（2026-11-06）

Provider 编辑器支持直接输入 API Key 或选择现有命名密钥。选择时保存引用模板，编辑时通过 api_key_source 元数据回填所选名称，不读取真实值。手动输入会清除选择状态；留空仍保留已有凭据。列表加载中或旧引用缺失时保留名称占位，密钥列表失败不阻止直接输入。

Provider 凭据写路径按实际保存的模板维护 named_secret:name 来源元数据；切回直接值恢复 database，编辑保留已有值时同样维护来源。运行解析、轮换与删除保护沿用既有实现。

## 密钥输入交互与名称编辑修正（2026-11-06）

Provider凭据改为“直接输入/使用密钥库”互斥选项。直接模式只显示密码框；密钥库模式只显示带钥匙图标的选择框，打开与MCP同样的选择弹窗，展示名称和代号，已有引用默认进入密钥库模式。移除同时展示密码点与下拉框的歧义。

密钥编辑改为“编辑密钥”：名称必填（最多128字），代号为唯一稳定引用且创建后固定；名称允许重复，代号才是唯一标识。新建重复代号在事务内拒绝，不用upsert意外覆盖已有值。metadata-only edit不解密或替换原值，新密钥值留空保留；需要轮换时才填写新值。弹窗内校验和显示错误，提交期间禁重复点击。DialogRoute退出动画结束后才释放控制器。
