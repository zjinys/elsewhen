# Agent Note: 语义航向评估的持久边界

Status: implemented

## Problem

目标航向提醒目前从关键词和停滞天数推断偏离。这个判断既漏掉同义的真实进展，也无法解释休息、突发任务和明确改计划；分钟级后台 tick 还可能在同一输入上重复产生模型调用。

## Decision

把一次判断拆成不可变的输入快照、结构化评估和追加反馈。快照保存目标／计划上下文、证据的真实来源 ID、时间和逐字节选，并带有输入指纹、提示 bundle 和后台 authority 代数。只有模型返回通过严格引用校验的 `aligned`、`drifting`、`changed` 或 `insufficient` 结果才能进入本地提醒；偏离必须有至少两个不同日期的独立用户证据。结果提交时重新检查租约、目标快照和 authority，迟到结果直接丢弃。

评估器复用已有 provider 预算、故障隔离、每目标／计划频控和后台处理权限。反馈追加保存并参与下一次指纹，用户打开讨论只生成预填草稿，不代表目标已校准；任何目标或计划修改仍使用现有显式审批工具。

## Alternatives considered

- 继续扩展关键词表：无法覆盖语义表达，也会把同词记录误当进展，不能提供可审计证据。
- 每次 tick 直接请求模型：无法在重启、重复 tick 或目标变更后识别同一输入，成本与迟到写入风险不可控。
- 让模型直接修改目标或计划：越过现有审批边界，且无法把提醒和用户确认分开。

## Verification

迁移80从79升级保留旧提醒的七天频控历史，停用未经语义证实的旧pending卡。存储专项验证重启去重、六小时新输入限制、失败退避、两日期／真实引用、截断保守降级、事件消息双写、分类撤销、目标与owner ABA、租约回收、提交回滚、用户纠正、讨论不校准及目标数据清理。回环HTTP验证有限failover保持同一完整快照及每渠道输出预留；第二连接在模型调用中录入成功，证明不持有数据库写锁，新增反证使旧响应失效。

Flutter具备中英文窄屏证据／反馈卡、运行时语言切换和临时库真实Bridge测试；模型输出与原文不随UI语言改写。真实模型9场景最终通过，首轮语气问题和全部17次调用成本见[验收记录](../../../testing/2026-11-09-semantic-compass-real-model-acceptance.md)。工程全量结果在[路线图](../../../roadmap/2026-11-09-semantic-compass-phase4-roadmap.md)维护。

## Consequences

收益是提醒可追溯、用户可纠正，重启、迟到响应或owner变更不会重新付费或提交过时结果；业务修改仍走原有显式审批。评估、反馈和authority是本机派生表，不进入同步快照；清空目标工作区会在同一事务删除它们，原始事件保留。

代价是每个目标至少三天后才开始判断，六小时／七天降频及不完整证据降级会漏掉一些真实偏离；日常新增用户事实会撤下已显示的旧证据卡，以免继续呈现过时判断。用户纠正按完整目标／计划依据保存，未确认更新依据前不再产生同类偏离结论。公开合成评测不替代真人GUI、真机多设备或长期使用验收。
