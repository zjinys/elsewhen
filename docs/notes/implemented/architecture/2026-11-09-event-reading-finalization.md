# Agent Note: 连续阅读树的有界合并与最终原子消化

Status: implemented

## Problem

[预算内叶节点阅读](2026-11-09-event-reading-budget.md)证明每段原文已处理，但摘要长度或最后一段完成不能证明整个事件可确认。合并依赖缺口、旧处理者响应、最终提议错误或半途写入都会产生错误的完整消化声明。

## Decision

E3 使用 `src/storage/event_readings/tree.rs` 验证阅读树，`finalization.rs` 提供独立最终租约；`src/knowledge/event_reading.rs` 选择并执行单个叶或合并节点，`src/wiki/digest/finalization.rs` 调用既有提议与页面事务。模型合并、最终提议是不同 tick 的调用阶段，不在同一 tick 串行完成全文和最终写入。

### 连续树与合并

全体叶必须有序无缺口地覆盖原事件 `[0,total_chars)`，原文内容指纹和每叶内容指纹必须一致。所有节点输出必须完成、在缓存限额内且引文逐字可校验。每个合并节点要求 2–8 个连续子节点，绑定确切输出 hash、有序 position，层级为子节点最高层加一，最多 16 层；子节点只归属一个父节点。只有一个完整 frontier 根时才可标为 `ready`。

执行器选择最高层级最低的相邻节点组，避免逐段串接形成过深树。按当前有限候选 Provider 的完整请求预算试探 2–8 个子节点，固定可容纳的组后，再在每次具体渠道发送前完整重检。预算不足以合并最小二元组时返回 `event_reading_merge_input_exceeds_budget`，保留所有已读缓存，不缩减输入冒充完整合并。

合并输入明确区分生成摘要和校验引文。输出仍使用固定阅读协议；合并不得新增子节点未提供的引文，即使这段话确实存在于原事件中也不能冒充已读取证据。范围、依赖、层级、输出与引文在提交及最终根验证时再次检查。

### 最终请求与事务

最终 `claim_event_reading_final` 绑定原消化批次、任务固定 bundle、根 ID／输出 hash、任务代数、处理权限代数和 600 秒租约。领取与提交之间不持数据库写锁，每个候选发送前验证并续期；过期恢复保留根，旧代数或权限先失效后恢复的旧结果均拒绝。

最终材料包含原事件 ID、完整覆盖范围、叶计数、根 ID、`generated_summary`、`verified_original_quotes` 的绝对位置。它使用冻结的 `event_reading_context` 模板，明确标注生成摘要不是逐字原文。来源编号继续映射原批次唯一事件；真实模型若返回本批原事件的确切 UUID，也作为编号别名严格映射，任意其他来源仍拒绝，不创建中间事件。最终请求复用普通消化的相关资料动态选材和每渠道完整序列化预算，但使用严格预算入口，未知预算不能发送。

最终输出必须是完整正常结束的严格 JSON 数组，最多 32 项、总文本最多 128 KiB。拒绝尾随杂质、未知字段／额外来源、非法来源编号、输出截断及非法提议。合法提议沿用 slug／kind 校验、同义页面重定向、事件证据并集去重与人工正文保护。最终提议失败释放有效最终租约，保留 `ready` 根；调度层可按原 job 重试，不重新消费阅读节点。

`apply_digest_batch_with_reading` 在一次 `IMMEDIATE` 事务中重新校验最终租约和整棵树，然后写页面、证据、语言元数据、wiki log、原 digest job／run 成功状态和 reading task 成功状态。任一步失败全部回滚。普通 `apply_digest_batch` 拒绝存在未完成阅读任务的同 bundle 事件，防止绕过完整根检查；短事件仍沿用原路径。

## Alternatives considered

- 以根摘要短或最后一段完成作为覆盖证明：无法排除缺口、重复片段和缺失子依赖，使用完整叶覆盖与依赖 hash 验证。
- 先确认阅读任务再写页面：最终失败时会假报成功，改为共用既有页面事务。
- 合并时从全原文补取引文：模型没有看到这些范围对应的原文输入，要求只继承子节点引文并保留定位。
- 最终失败清空阅读缓存：重复消耗全部叶和合并调用；保留完整根，只重试最终提议。
- 只在最终调用前检查权限：请求期间可能发生重新分类或移交，提交再次检查当前权限及代数。

## Consequences

最终失败不会写入半成品页面，也不会丢失有效阅读结果；原始事件内容和身份始终保留，人工编辑正文不会被摘要覆盖。每次调用受完整预算及节点限额约束，摘要树的语义质量仍需 E6 真实模型验证。树验证读取本任务有界节点和依赖；未实现跨任务全局缓存清理。

E3 提供执行和原子提交能力，[E4 自动调度与进度](2026-11-09-event-reading-worker.md)已接线；本记录只描述 E3 的原子提交能力，完整产品验收以路线图 E5/E6 为准。

- 预算边界覆盖最小合并组无法容纳时零网络调用；最终 failover 的窗口不足渠道零发送、网络失败和截断后切换，每个实际渠道只调用一次。

- 响应为合成脚本；实际 Provider 序列化估算器执行预算，非真实模型质量验收。HTTP 与完整应用验收仍属 E5/E6。
