# Agent Note: 对话伴随面板的宿主与状态边界

Status: implemented

## Problem

当前待办、目标速览和审阅均通过模态底部面板打开，桌面用户无法边看边聊。审阅内容已有内嵌主从窗格，但其返回逻辑默认拥有独立路由，直接嵌入主对话会误关闭聊天页面。窗口宽窄切换也不能销毁正在填写的草稿。

## Decision

消息区挂载本地宿主，通过容器内的稳定注册对象处理三个现有入口。宽度依据消息区实际可用空间，至少840px时在右侧留至多420px，聊天和输入继续可用；更窄的桌面窗口使用底部遮罩与面板，移动设备沿用既有底部路由。没有消息区宿主的独立入口仍按原有sheet呈现。

聊天子树始终保持Row首个子项，同一GlobalKey的面板在右侧与底部之间迁移，保留编辑状态。只在面板打开时构建内容；重复入口关闭，其他入口替换，会话切换或卸载清理宿主及等待回调。Escape／返回／关闭只结束面板。审阅明确区分嵌入态，禁止它pop主聊天路由；接受／拒绝继续走现有确认和审批契约。

## Alternatives considered

- Scaffold.endDrawer：默认模态且与窄屏导航抽屉重叠，仍无法边聊边看。
- 全平台使用并排布局：手机聊天空间不足，保留底部交互更符合现有操作。
- 两套独立面板实例切换：缩放时丢失审阅批注或待办草稿。
- 切换窗口后自动关闭：实现简单，但会丢失用户正在进行的工作。

## Verification

Flutter全量610项通过，最终焦点调整后20项工作区／审阅专项复跑通过；新增5项覆盖中英文面板草稿／聊天草稿跨宽窄变化保留、重复入口关闭、切会话清理、Escape关闭、消息区实际发送、审阅嵌入与主路由保留，以及聊天宿主在后台时其他路由独立显示sheet。35项入口专项通过，原有单条／批量审阅、处理回执和移动返回语义保持。静态分析、格式、本地化与最终回归结果统一在[路线](../../../roadmap/2026-11-09-chat-companion-workspace-roadmap.md)维护。

## Consequences

桌面可边看待办／目标／审阅边继续聊天，消息列表与输入保持同一子树，面板只在打开时构建。路由是否当前激活参与宿主选择，避免在设置等页面把内容打开到后台聊天。嵌入式审阅不pop主路由，接受／拒绝、编辑与确认沿用原有契约；本批没有Rust、数据库或同步协议变更，也不需要重新生成FRB。

代价是面板占用聊天宽度，消息区可用宽度不足840px时恢复底部遮罩并排除背景输入焦点；移动设备沿用原有sheet路由。宽窄切换保留状态，但主动关闭、替换入口或切换会话会结束面板，未保存的临时编辑不做持久化恢复。自动化widget证据不能替代真人桌面／手机触摸体验，仍需验收。
