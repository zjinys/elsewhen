# Agent Note: 有界项目盘点与 AI 综合评估

Status: implemented

## Problem

本地目录的项目导入不能把完整文件地图写入知识库：大型目录会生成巨大页面，影响阅读性能；但仅保存目录统计又无法回答主要功能、完成度和商业价值等语义问题。

## Decision

项目模式采用“只读盘点 → 预览 → 用户确认 → 保存报告”的流程：

1. `src/local_sources.rs` 先做确定性只读扫描，收集项目名、候选文件统计、元文档、技术栈、测试与未完成线索、Git 摘要和顶层结构。项目模式最多遍历 100,000 个目录项并收集 20,000 个符合文本扩展名且未被内置/根目录字面目录规则排除的候选文件；只读取其中有限样本，这不是完整文件内容镜像。
2. 确定性报告阶段最多读取 `MAX_EVIDENCE_FILES = 96` 个高优先级样本文件；每个样本实际读取最多 12,000 字符，摘要正文最多 `MAX_SUMMARY_CHARS = 18,000` 字符。根 README 最多读取 5,000 字符，每个 CLAUDE.md/AGENTS.md 最多读取 3,000 字符；manifest 实际读取最多 64,000 字符。技术栈 manifest 只提取有限依赖（每个 manifest 最多 6 个，最终展示最多 12 个）。
3. 有活动 AI Provider 时，在同一份最多 20,000 个候选文件的项目清单中按优先级选取最多 24 个文件作为模型证据，总计最多 30,000 字符、单文件最多 4,000 字符。敏感文件按文件名/扩展名启发式跳过，疑似凭证赋值行替换为占位符；这不是完整的秘密检测或隐私保证。
4. 模型只接收确定性摘要和上述脱敏后的有限证据，并被要求输出主要功能、特点、完成度、未完成线索、商业价值、证据/不确定性和下一步。商业价值只能作为证据和假设基础上的判断，不生成无依据的市场、收入或客观评分结论。
5. 没有 Provider、证据读取失败、Provider 初始化失败、空响应或模型调用失败时，保留确定性摘要，并在报告中标注 AI 未执行或失败原因；不因 AI 不可用阻塞导入。
6. `import_directory_as_project` 只有在用户明确要求导入项目时才调用。工具先验证目录并完成盘点，在知识库写入前创建待确认动作；动作参数保存 `ProjectSummary`（项目名、有界候选文件数、跳过数、是否达到扫描上限和完整预览正文）。确认时直接调用 `ingest_project_summary`，保存预览中的同一份报告，不重新扫描、不重复调用 AI，因此即使原目录随后消失也能完成确认保存。
7. `import_directory_files` 是不同的显式模式：确认后才重新扫描目录，为每个可读文本文件创建 source 页；它不使用项目 AI 综合报告。命令行的 `sources project <目录>` 是用户显式执行的直接导入，不经过聊天确认，但使用同一套 AI/确定性评估流程；聊天工具仍先预览再确认。项目模式不保存完整或截断文件地图。

这里的“有界候选文件数”是项目模式清单中符合文本扩展名且未被排除规则过滤的文件数；项目模式最多遍历 100,000 个目录项、收集 20,000 个候选文件，并在报告中标注是否达到任一上限。`MAX_EVIDENCE_FILES = 96` 只限制确定性阶段实际读取内容的样本数；“证据样本可读”与候选文件数不是同一个统计口径。显式逐文件导入仍使用自己的完整候选清单。

## Alternatives considered

- **保存完整文件地图**：在大型项目上造成数 MB 页面和界面卡顿，拒绝。
- **只截断文件地图**：降低性能风险但仍然保存错误的信息模型，拒绝作为项目模式默认结果。
- **只做确定性统计**：安全、可复现，但不能回答功能和完成度等语义问题，作为 AI 不可用时的降级路径保留。
- **确认后重新扫描和调用 AI**：会造成预览与最终保存不一致并重复消耗 token，拒绝。
- **项目模式逐文件建 source 页**：保留为显式的 `import_directory_files` 行为，不作为项目盘点默认行为。

## Consequences

项目摘要正文有明确上限，原始目录仍是事实来源；AI provider 不可用不会阻塞导入。用户在确认前能看到实际将保存的报告，确认后保存内容稳定一致。有限证据和敏感信息过滤降低隐私与 token 风险，但凭证过滤是启发式的，不能替代用户对 Provider 隐私策略的判断。
