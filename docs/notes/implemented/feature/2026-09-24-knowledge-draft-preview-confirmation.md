# Agent Note: 今天栏预览并单独处理知识草稿

Status: implemented

## Problem

`save_knowledge_draft` 写入待确认动作而非知识页。用户在知识库列表找不到草稿时，AI 容易将「草稿存在」误说成「页面已入库」；仅靠回复「好」也无法预览完整正文，且会确认同一会话的其他待处理动作。

## Decision

「今天」栏显示当前对话待入库知识草稿的数量，点开可查看列表，并逐篇预览完整 Markdown 正文、标题和类型。保存按钮通过动作 ID 和会话 ID 单独确认这一篇；写入成功后才移除待确认动作并刷新知识库及草稿列表，界面直接显示后端的真实结果。删除草稿须二次确认，后端只将指定待确认知识动作标为 declined，不动已有知识页和其他待确认动作。AI 提示和纠错文案区分草稿、已保存及已有页面三种状态。

## Alternatives considered

- 让预览按钮发送「好」作为聊天消息：既依赖模型正确理解，也可能执行会话中的其他待确认动作。
- 将待确认草稿伪装成知识库页面：会把尚未写入的内容呈现为已保存，重现本次误解。
- 只调整 AI 文案：不能让用户独立核实完整正文与执行保存。
- 在每条消息旁显示草稿：多篇草稿会占据对话空间，入口和数量也不够集中。

## Consequences

用户可从「今天」栏查看、核实、删除或定向保存当前对话的草稿，不必依赖 AI 口头报告。保存失败时预览保留并可重试；删除后不会被对话确认操作保存。代价是草稿入口只汇总当前对话，其他类型的待确认动作仍沿用原有确认流程。
