# Agent Note: 产品线索与个人研究工作区

Status: implemented

## Problem

同一产品的多次 finding 重复占据主区，动态数量和平台热度不足以支撑用户取舍；只存变化记录也无法证明趋势采样完整。旧拉取以客户端时间推进、单批 1000 上限及非原子快照会让后续研究建立在不完整基线上。个人研究与外部镜像必须有不同的保留和同步边界。

## Decision

主工作区分发现线索、跟进研究与原始动态。发现使用产品身份归并后的卡片网格，来源用本地图标识别，点击按需打开 side sheet。卡片依次展示用途、关注理由/实际时间窗口、报价事实和关键未知；缺少可靠信号时允许为空，全部产品与搜索仍可访问。研究编辑以理由、买方、报价假设和关键问题为主，实验/反馈与个人适配按需展开。

Scout 成功采集以 lease 栅栏与 D1 原子批次发布；所有成功轮次记录观察，失败和部分结果不能成为新基线。新增稳定实例身份、固定上界增量分页，客户端每页持久提交后推进游标。新增产品、来源成员关系、观察与可重建线索索引；GitHub 数字 ID 与旧名称 alias 保留研究连续性，跨平台不按同名合并。详情、产品查询、回填与后台索引均有界。

7/30 天趋势由相同来源与口径的成功观察计算，保留起止时间、样本数、前一窗口和 snapshot 引用。历史缺口、未知币种、零基数与口径重置各自处理；首次监控基线不能冒充新品，评价数不能推算销量。持续增长、榜位改善、价格变化和新进入监控范围有各自规则/版本，不生成混合商机分数。

个人研究复用 human-held memo、wiki 修订与既有同步/导出；内容 token 防止过期编辑覆盖。研究固定加入时的产品证据，用户记录假设、反证、实验、反馈和阶段。清空镜像、换连接或离线不删除研究。偏好是单独的用户明确填写文档，可撤回；研究可以固定当时偏好依据并保留适配/不适配理由。多主题归属由用户逐项确认，同主题可对比最多 5 产品，原产品身份不变。

原文证据由用户确认 URL/摘录，保存哈希、时间与可选出处信息。每项研究可单独启用有界 AI：只使用给定材料，无工具，逐字引文校验、证据 ID 校验与未知约束。任务绑定材料、问题、提示和 provider 配置；过期结果不允许采纳。接受候选时固定候选与有界证据，后台分析永不替换人工结论。

落点：`scout-cf/src/{store,feed,products,trends,insights}.ts`、D1 迁移 0004/0005；`src/scout/{research,analysis}.rs`、`src/api/scout.rs`、本地迁移 87/88/89；Flutter Scout provider 与 `scout_view_parts`。此前[阅读工作区](2026-11-17-scout-reading-workspace.md)继续承担原始动态阅读，本决定接管默认产品发现与研究路径。

## Validation

2026-11-20 来源去预设修正：GitHub 使用 `github-newcomers`，合并 Dart/Rust 为全语言近 90 天创建、stars >50 的前 30 项；查询在每次采集时解析日期，specHash 只包含稳定规则，跨日不重建基线。CWS 使用 `cws-discover` 从公开扩展发现页的 `data-item-id` 与可访问性引用提取名称、简介、评分、链接；3 MiB 页面界限、100 项上限，空页/卡片字段缺失失败封闭。无内置扩展 ID，额外跟踪支持链接、去重、最多 20 项，默认留空。D1 0007 停用旧源但保留观察/产品/研究证据；当前来源 API 和后台隐藏已退休源，客户端正常来源列表不因历史镜像恢复旧项。

CWS 本地与 Workers 出口真实页面均解析出 30 项，Workers 返回 200、约 1 MiB。发现页为商店推荐样本，顺序不写 rank，首次进入不冒充新发布；来源依据见 [Chrome 商店发现说明](https://developer.chrome.com/docs/webstore/discovery/)。GitHub 查询使用[官方搜索 API](https://docs.github.com/en/rest/search/search#search-repositories)。新源首次成功只建基线。

来源专项与回归：Workers 77 项通过、4 项 opt-in 跳过；Flutter 原 18 项通过，新增退休源导航回归后来源专项 6 项通过；TypeScript、Flutter 相关静态检查、Wrangler dry-run 通过。线上迁移 0007 已应用，旧三源退出当前源 API；新两源首轮成功均为 0 findings，后续采集 GitHub 30 项、CWS 30 项加 1 个既有额外跟踪。CWS 首次遇到 302 后补同范围单次跳转，跨域、登录/unsupported、主题分类跳转均失败封闭；采集形状升 v2 重新建基线。

最终 Scout 部署版本 `9fe34bfc-2efe-4476-a6d5-656b78b9a71b`，经 `elsewhen.cc.cd` 认证接口触发核验：GitHub 快照 118 共 30 项；CWS 快照 119 共 31 项、`baseline_reset=true`、0 findings；当前来源列表为 6 个且无旧三源。客户端中文来源标签/导航变更在代码中，需客户端后续构建生效。

2026-11-20 产品信息补齐：卡片顺序为名称/分类与开发者、来源用途简介、可核实的榜位/评分或 stars/下载标价、关注理由和研究操作；普通首次监控改为中性信息条，完整证据缺口留在详情。缺简介显示明确缺失与原始介绍入口，不从名称推断产品用途，也不自动翻译或生成商业结论。来源筛选入口保留当前的按钮与弹出多选面板。

App Store 采集在 top-25 榜单后增加一次 Apple 官方 lookup，按 trackId 回填说明与商店事实；2 MiB 响应界限、16000 字符简介上限，缺项或失败拒绝本轮，避免旧字段被清空和错误 diff。字段/解析版本进入 specHash，升级首轮只重建基线。Gumroad 保留返回的 description/summary。采集新字段需要部署 Scout 并成功重新采集后才出现在旧产品资料中。

Atom/RSS 从测试/运行时两套简易解析改为相同 htmlparser2 XML 解析，兼容 CDATA 与 XHTML。服务端纯文本与客户端 `html` 展示归一化最多解开四层 HTML 转义，去标签、隐藏块和订阅源导航，数值/命名实体正常显示；客户端两类 Scout 模型共用清洗，旧镜像立即可读，证据 payload 不改写。Apple ID lookup 的接口依据见 [Apple lookup 文档](https://developer.apple.com/library/archive/documentation/AudioVideo/Conceptual/iTuneSearchAPI/LookupExamples.html)。

公开源验证 App Store 全部 25 条取得简介和商店事实；用 983156458/284882215 的公开 lookup 验证批量 ID 关联。Flutter 专项 48 项与 Workers 64 项通过（另 4 项 opt-in 跳过），TypeScript/Flutter 静态检查与 Wrangler dry-run 通过。使用合成卡片验证桌面/360 信息顺序和完整详情，未读取个人数据库；这些检查不代表线上部署或 AI 质量验收。

2026-11-20 发现页细节：上次拉取复用本地化 `prettyTimestamp`，每分钟更新，悬停显示准确时间；桌面同步操作靠右并用留白和细竖线分组。卡片改成有界懒加载的自适应行布局，移除 360 固定高度和正文后的 Spacer；窄屏筛选横向滚动保留阅读空间。

来源多选以监控集合 ID 为粒度，空选择表示全部，多个选择取并集，与文本搜索和线索类型组合。客户端复用已部署的单来源查询：首源固定 as-of，其他所选源沿用同一 as-of，各取最多 40 条，按 `(observed_at, product_id)` 全局倒序去重后输出最多 40 条；下一页从最后实际输出的键继续查，不能直接推进各源未消费的游标。实例或 as-of 不一致时拒绝合并，任一页离线则整体标 stale；原始动态保持原单来源行为。源数增加会增加请求量和最多 `40 × 源数` 的临时合并成本；未扫描全库，也不需要服务端升级。

专项验证包含 90 个混合来源产品、重叠产品去重、三页排序/边界、来源清空/单选、多实例拒绝合并、stale 传递，以及桌面/360 浅色多选交互与卡片高度。来源专项 5 项与 Scout 回归 38 项通过；相关静态检查无问题。界面预览使用合成数据，未读取个人数据库。

## Alternatives considered

来源修正否决仅改前端名称或把硬编码 ID 搬入设置：这两种做法仍要求用户先确定语言/扩展，无法发现未知对象。使用公开 CWS 推荐卡片而非逐条请求详情，让未配置用户也有可读内容，并把常规请求限制为一次；代价是推荐样本覆盖有限、默认无安装量/评价数。GitHub 使用有时间范围的 stars 排序，不能称为真实增长速度榜。

- 只把卡片名字放大：App Store 榜单没有用途说明的问题仍在；补来源简介并展示已有事实。
- 用 LLM 凭名称生成用途/收入或把免费榜当作收费证据：不可核实且有额外调用成本；商店事实与未知分开，免费只表示下载标价。
- 只修采集端：旧镜像和研究保留的原文仍会乱码；客户端加展示归一化并保留证据原值。
- HTML 正则剥标签后再解实体：无法处理多层转义与 CDATA，且易残留 href 等杂文；采用语法解析器和有界迭代。
- Apple lookup 部分成功也覆盖产品：可能移除既有简介并制造差异；本轮失败保留最后成功快照，代价是补充接口不可用时该源暂不更新。

- 当前页本地筛来源：后续页符合条件的产品可能被漏掉，且分页会受未选来源干扰；使用服务器端逐源过滤和共享 keyset 合并。
- 立即新增服务端多来源协议：单次请求更省成本，但本轮交互修改要连带服务部署；复用现有接口可立即使用，来源规模增大时可保持客户端语义并迁移到单查询接口。
- 仅降低卡片固定高度：仍会留下空白或在较长描述/字号下溢出；改成内容高度和按行懒加载。

- 继续把 finding 作为机会卡：无法消除产品重复，也不能通过只记录变化证明采样连续。
- 在前端加载全部源快照后分组/筛选：让大数据量占用与查询不稳定落到用户端；采用产品索引、有界窗口与固定 as-of keyset。
- 把研究状态写进可清空镜像：连接变更和缓存维护会删除个人劳动；复用已同步的人工知识文档。
- 用热度计算统一商机成功分数：stars、榜位、报价不是同一商业指标；提供可解释信号和未知。
- 自动归并同名产品、自动确定用户适配或采纳 AI：这些判断需要用户任务、能力和真实证据；保留人工确认与可撤回依据。
- 等评价采集和模型质量完全成熟才提供研究：已有原文手工确认与实验记录可以先支持决策，不以生成文字填补证据缺失。

## Consequences

用户可从产品线索进入可追溯、可同步的研究与实验记录，采集失败或镜像重建不再破坏个人判断。服务端增加观察、历史线索索引与回填成本；现有 800 观察/产品计算界限、32 查询缓存及 1000 研究读取限制是明确范围，不能外推到无限规模。

这是工作区工程交付，未发布。可配置阈值、自动评价采集/去重、完整机器主题建议、跨平台审阅关系、部分素材/事件研究回链仍未实现。7/30 天连续观察、20 份真实模型审阅、真人界面与真实商业实验仍待验收；[原提案](../../proposed/feature/2026-11-17-scout-opportunity-research.md)保留未交付范围，任务状态以 [roadmap](../../../roadmap/2026-11-17-scout-opportunity-research-roadmap.md)为准。

2026-11-19 后续：主对话情报速览改为精选信号卡。客户端只从服务端新鲜、完整的产品信号页选择最多三个价格变化、持续增长或榜位提升；原始未读数量、首次进入监控和消失事件不会生成提示。同一实例/产品/信号/指标端点证据跨日去重，旧数量卡在 UI 中隐藏，点击精选卡进入发现线索视图。
