# Agent Note: 待办升级为可讨论工作项

Status: implemented

## Problem

待办当前通过模态弹窗编辑，标题、说明、状态与讨论过程彼此割裂。复杂待办无法保留思考、决策和上下文，完成后也只剩一条扁平记录。

## Decision

待办保留状态化数据模型，并按需关联知识页。用户打开待办时创建或进入关联页，在页内聊天、记录决策和沉淀背景；简单待办不打开就不生成页面。页面头部编辑状态、优先级和截止日期，页面聊天继续使用现有会话；“沉淀讨论”通过现有 `save_wiki_revision` 确认门写回。

## Alternatives considered

- 每条待办创建时自动生成知识页：会为大量一次性事项制造空页面。
- 完全把待办改成知识页字段：会削弱快速勾选、截止排序和结构化查询。
- 继续使用编辑弹窗并附加聊天：弹窗不适合持续工作和长期回看。

## Verification

- `cargo test --lib`：130 项通过。
- `flutter analyze --no-fatal-infos --no-fatal-warnings`：无 error；仓库保留既有 warning/info。
- 存储测试覆盖按需关联幂等、完成后历史保留和字段编辑。

## Consequences

实现保留轻量待办的低成本创建路径，同时为需要讨论的事项提供持久页面和聊天历史。页面创建与关联是两个持久化动作；若关联写回失败，用户可再次打开待办重试，不会改变原始待办内容。
