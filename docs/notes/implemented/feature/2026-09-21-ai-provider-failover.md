# Agent Note: AI Provider 自动故障切换

Status: implemented

## Problem

应用支持保存多个 AI provider，但对话只调用当前激活项。激活项网络不可达、鉴权失败或服务异常时，对话直接失败，其余可用配置无法接管。

## Decision

对话生成按“当前激活项优先，其余配置按创建顺序”构造 provider 链。一次请求在当前 provider 的原生工具协议和文本协议均失败后，继续尝试下一项；首个成功项被持久化为新的 active，后续请求直接从它开始。所有配置失败时返回聚合错误。

运行时一次性读取包含密钥的完整配置列表，不通过临时修改 active 获取备用配置，因此失败尝试不会改变全局选择。工具协议兼容回退仍发生在同一 provider 内，只有实际请求失败才跨 provider。

## Alternatives considered

- 每次失败只提示用户手动切换：恢复慢，且已有多个配置却没有形成容错能力。
- 每次请求轮询所有配置：会改变用户明确选择的优先级，也无法稳定使用已经验证可用的节点。
- 请求前临时修改 active：会暴露瞬时全局状态，并可能影响并发请求，因此不采用。

## Consequences

单个 provider 故障不再直接中断对话；成功备用项会自动接管。一次故障请求的延迟可能按失败节点数量累加，所有节点不可用时错误信息会包含各节点失败原因。当前切换作用于持久化对话生成路径，其他后台分析任务仍沿用其各自的 provider 调用策略。
