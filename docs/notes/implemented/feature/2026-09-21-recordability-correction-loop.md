# Agent Note: 事件可记录性纠正闭环

Status: implemented

## Problem

AI 分析完成前无法可靠判断一句对话是否属于事件；分析后若把“评价助手”“闲聊”标成非事件，用户仍需要能纠正误判、保留原始对话，并让日流和长期事实立即一致。

## Decision

新增追加式 `event_recordability_decisions`。有效分类优先级为人工决策、最新分析、默认事件。消息时间线上显示“记录 / 讨论 / 分析中”状态菜单，用户可以纳入记录、作为讨论或重新分析。作为讨论不会删除不可变事件或消息，但会从日流和每日回顾中隐藏，清除该事件产生的实体事实、关系和待确认动作，并把关联普通会话标记为 discussion。重新分析只把非运行中的分析任务重新排队，历史 `event_analyses` 保留。

写入路径继续先保存原始事件，再异步分析；这样 Capture 不等待网络，也不因 AI 故障丢失用户原话。写入前的严格 AI 门禁不作为默认行为，避免破坏随手记录体验；如未来增加严格模式，必须是显式用户选择。

## Alternatives considered

- 在事件保存前同步调用 AI：会让 Capture 依赖网络和 Provider，违背本地优先和不阻塞保存约束。
- 删除被判为讨论的事件：会破坏可追溯性，因此只追加分类决策并在读模型过滤。
- 覆盖原始分析 JSON：会丢失模型判断历史，因此保留分析版本，人工决策单独记录。

## Consequences

用户可以从当前对话消息完成分类纠正和存量重新分析，操作结果立即影响日流、事实和待确认动作；原始事件与消息始终可回看。代价是新输入在异步分析完成前仍会暂时存在于事件账本，UI 以“分析中”明确显示这一短暂状态。

验证覆盖隔离 Rust 数据库、Bridge 分类/重分析往返、原始事件和消息保留、实体派生数据撤出及旧分析保留。
