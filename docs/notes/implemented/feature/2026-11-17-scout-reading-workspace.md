# Agent Note: 情报阅读工作区

Status: implemented

## Problem

情报页先展示采集源计数和运行状态，总览与发现重复按源组织。点击动态直接跳外链，没有站内理解变化、研究历史和保存判断的路径。未读与变化类型互斥，筛选后“全部已读”仍影响全库。

## Decision

情报直接进入跨源动态流，来源与未读入口放在既有左栏。来源菜单为窄窗和移动端提供相同筛选。阅读状态和变化类型独立组合；全部动态、未读这两个导航入口重置类型，选择单源保留类型与阅读条件。

动态按检测时间倒序、ID 倒序作为稳定次序，统一每页 40 条。主区按日期展示自适应 1–4 列卡片网格，SliverGrid 按需构建可见条目。点击卡片打开右侧模态 side sheet（最多 620 逻辑像素，窄屏铺满）；关闭按钮、遮罩、Esc 均能关闭，保留底层浏览位置。抽屉以 220ms 从右侧进入，系统减少动画时关闭位移动效。详情绑定选择时的本地记录，后台更新和标已读不能换掉正在阅读的内容。

卡片突出前后变化，详情展示字段对比、指标、完整采集数据与服务端历史快照。历史加载失败不阻断本地数据阅读。`new/gone` 改为“首次发现/未再出现”，说明它们只描述监控集合。

来源通过平台 SVG 图标、固定色彩、平台名和监控主题共同标识；GitHub/Rust、GitHub/Dart 共享平台图标但主题不同。图标来自 Simple Icons，CC0，随应用离线打包；未知来源使用通用图标与服务端名称。

批量已读只提交当前加载条目的明确非空 ID 列表，按钮为“本页标为已读”，确认后按捕获的 ID 执行。空列表不能传给代表全库的既有 API。

“存为素材”复用来源预览与确认流程，保存采集记录、原链接和检测时间；身份使用服务地址加 finding ID，避免用情报摘录覆盖原网页素材。“记为事件”先展示可编辑文本，再经既有 repository 写入事件并唤醒分析。转知识草稿暂未接入。

## Alternatives considered

- 常驻右侧详情与单列长列表：数据多时压缩浏览宽度，改为按需打开侧滑详情，主区完整用于卡片扫描。
- 仅靠源文字或远程 favicon：前者难以快速辨认，后者离线失效，采用本地平台标志并保留文字。
- 保留总览并美化卡片：仍迫使用户在采集状态与实际内容之间跳转。
- 每源独立分组分页：后面来源的新消息被前面长分组压住，增加查询和计数逻辑。
- 根据当前筛选循环拉全量再标已读：操作范围会随着数据加载变化，且为批量动作引入额外全量读取。
- 自动判断重要性或用 AI 生成变化结论：本次只呈现确定性的已有差量，不新增未经验证的优先级模型。

## Validation

- 情报模型与 UI 测试共 25 项通过，包含站内选择、360 像素窄屏、组合筛选、按源批量已读，以及 40 条多列卡片、遮罩/Esc 关闭和滚动位置保持。
- Rust Scout 存储测试 8 项通过，包含检测时间排序与分页稳定次序。
- 修改范围 Flutter analyze 无问题；测试数据边界替换，不访问个人数据库。
- 桌面预览由真实 widget 使用固定样例数据渲染；生产服务联网与个人素材落库未作为自动化验收。

## Consequences

用户能直接阅读变化并进入研究与记录动作。连接与源运行信息降为次要信息。历史仍依赖服务可达，完整数据保留折叠入口；服务端目前返回完整历史，尚未增加历史分页。已读刷新会重新获取当前第一页，统一分页的游标优化后续再做。
